# 简体中文玩家术语表

状态：首发文案基线  
更新日期：2026-09-17

本文件规定首发界面、教程、提示、复盘、统计、Premium、广告奖励、错误提示和无障碍朗读中面向玩家的简体中文术语。内部领域模型、数据库字段、事件代码和测试数据可以保留既有英文标识，不应把内部名称直接展示给玩家。

## 核心术语

| 概念 | 玩家用语 | 首次说明与使用规则 | 避免使用 |
| --- | --- | --- | --- |
| 玩家手动记录候选数字 | `笔记` / `候选笔记` | 按钮和模式名称使用“笔记”；教程首次出现时写“候选笔记”，之后可简称“笔记” | 铅笔、备注、手动候选 |
| 系统生成当前合法候选 | `快速候选` | 工具栏、重新生成弹窗、统计、奖励、错误提示和复盘统一使用 | 快速铅笔、快速笔记、自动候选、快速草稿 |
| 辅助功能剩余使用量 | `可用次数` | 状态写“可用 3 次”；变化写“增加 1 次”或“使用 1 次”；达到上限写“可用次数已达上限” | 额度、库存、余额、点、credit |
| 棋盘位置 | `格` | 明确为空时可写“空格”；无障碍朗读使用“第 2 行，第 3 列” | 格子、单元格 |
| 当前一次游玩 | `游戏` / `本局` / `局` | 常规操作使用“新游戏、继续游戏、游戏已暂停”；当前结果或后果使用“本局”；数量使用“局” | 不强制把所有“游戏”替换为“对局” |
| 具体数独内容 | `题目` / `新题` | 指谜题本身或更换内容时使用，例如“开始新题” | 与“本局”混用造成统计口径不清 |
| 3×3 区域 | `3×3 宫` / `宫` | 教程首次说明使用“3×3 宫”，之后简称“宫” | 九宫、方块、区块 |

## 单局相关表达

“游戏”是中文游戏界面的常用词，不因为它也能指整个产品就需要回避。以下表达保持不变：

- `新游戏`
- `继续游戏`
- `游戏已暂停`
- `新游戏规则`

需要强调当前这一局时使用：

- `放弃本局`
- `本局已结束`
- `本局补给`
- `本局复盘`

统计指标必须直接说明口径：

- `开局次数`
- `完成题数`
- `总游戏时长`
- `放弃次数`

“对局”可以用于历史记录和复盘等偏记录管理的语境，但不是全局强制词。

## 候选相关边界

- `候选数`：按数独规则仍可能填入某格的数字，是逻辑概念。
- `候选笔记`：玩家在格中记录的候选数，是玩家可编辑的数据。
- `快速候选`：系统根据当前盘面生成候选笔记的辅助功能。
- `笔记模式`：玩家输入或删除候选笔记的输入模式。

不要因为统一术语而把所有“候选数”替换成“候选笔记”。提示中的逻辑推理通常讨论候选数；教程、设置和错误提示在描述玩家记录时才使用候选笔记。

## 内部名称映射

以下内部名称属于实现和持久化协议，可以保留：

| 内部名称 | 玩家用语 |
| --- | --- |
| `quick_pencil`、`quickPencil`、`quickCandidates`、`quickDraft` | 快速候选 |
| `pencilMode`、`manualCandidates` | 笔记 / 候选笔记 |
| `credit`、`balance`、`inventory`、`wallet` | 可用次数 |
| `cell` | 格；无障碍中使用完整行列位置 |
| `box` | 宫 |

内部标识变更涉及数据库、事件或序列化兼容时，不应仅为文案一致性而重命名。

## 维护要求

1. 新增或修改玩家文案时，先按本表选择概念，不从内部字段名直译。
2. 英语源文案、日语、德语和简体中文应表达同一个产品概念；各语言可以采用本地最自然的写法。
3. 教程、工具栏、设置、广告奖励、Premium、完成奖励、统计、复盘、错误提示和无障碍标签必须同步更新。
4. 涉及变量插值的文案必须检查插值后的完整句。
5. 术语测试只检查首发玩家可见资源；开发诊断、数据库字段和历史技术说明不作为禁用词扫描范围。
