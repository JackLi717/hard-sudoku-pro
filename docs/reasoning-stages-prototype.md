# 排除与填数分步识别原型

语义只引用[唯一权威归因协议](player-technique-attribution-policy.md)。本轮实现算法和离线评价，不改写旧局、不建设成长计分，也没有修改 C++ 技巧检测器。

## 结构

`verifyReasoningStages()` 接受已经过整段 native 验证的完整机会图，输出：

- 来源步骤：实际效果类型、完整直接结果、已观察/未观察部分、原起点及结果推理快照、来源技巧候选与默认解释。
- 填数步骤：在具体前置效果之后重新验证的直接基础技巧，与来源步骤分开定名。
- 依赖：`observed` 为已记录的前置效果足以推出收尾，`possible` 为仍需省略步骤的备选解释。

实现位于 `src/application/technique-recognition/reasoning-stages.ts`，接入回顾复验服务 `verifyReviewProcesses()` 的返回值。现有页面布局没有修改；新分步结果可通过服务输出和回归 JSON 检查。来源阶段的完整结果与收尾的必要前置子集分别保存，不把之后才发生的操作倒灌到收尾的前提中。

## 回归方法

使用[跨平台回归机](played-game-regression.md)，读取此前冻结的全部 25 局（iOS 9、Android 16），1,848 条操作。保留旧算法结果作为基线，分别检查：

1. 原有候选、默认解释、提示隔离和完整过程是否倒退。
2. 新来源是否由 native 在原起点证明，收尾是否由 native 在化简后证明。
3. 独立行列宫扫描器验证前后状态、首次形成的单数、实际/未观察效果分区和依赖标签；不调用生产单数实现。
4. 故障注入检查：虚构已观察排除、错误后置状态、来源丢失和依赖降级均会被发现。

39 种技巧均有分步测试，并在工程验收的 native 阶段强制运行；无收尾的夹具检查来源独立完成，不强造一个单数。另覆盖省略排除、提示污染、图不完整、身份不符、枚举失败和错误来源/收尾。

## 首轮结果

- 25 局回归失败 0，原有候选和默认解释变化 0。
- 可发布的分步来源 599 个：357 个排除型、242 个填数型。
- 收尾路径 172 条：98 条观察到前置依赖，74 条仅为可能路径。
- 其中真正“实际排除 → 填数”的路径 14 条，涉及 7 次不同落数；其余观察到的路径包括直接落数来源带来的后续单数。路径可重叠，不能当作独立技巧次数。
- 旧 iOS 数据缺少提示曝光等证据，继续受准入限制；包含在全库回放中不等于允许追认独立技巧。
- 原来的 4 个最终未匹配动作保持待分析，没有为让指标通过而补上技巧名称。

实际例子：会话 `session-1788427345446-09ifcnhz` 中，R5C5 明确删除 3、8，来源默认“隐性对子”、备选“裸三数组”；随后 R6C6=3 被单独验证为“隐性单数”，且保留来自前置删除的已观察依赖。不是只留下最后的单数，也不是把两层当作两次独立发现。

结论：分步命名、前置来源保留和不重复归因的预期得到支持；本轮没有证明真人技巧意图准确率提升，也没有提高四个遗留未匹配动作的召回率。首次报告为 `.local/behavior-regression/run-4EinFr/report.json`，新报告可作为下一轮显式 `--baseline`，其中分步来源和依赖也参与防退化检查。
