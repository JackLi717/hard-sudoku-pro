## 2. 已确认的交互范围

### 2.1 真实操作重放

- 完成页提供本局复盘入口；提供简洁的已完成对局入口，能够查看有足够记录的历史游戏。不只停留在 `__DEV__` 内部诊断页。
- 展示棋盘、可恢复的当时候选状态、本步动作与进度；提供上一步、下一步、回到开局、跳到结束、播放和暂停。
- 播放过程中可暂停并选择一个动作查看解释。离开页面、切换会话或进入演练时停止播放，避免后台推进。
- 按真实记录恢复填数、明确候选编辑、提示及有可靠依据的撤销/错误事件；自动候选清理不能伪装成玩家删除。
- 先审计存储是否包含完整事件顺序、撤销和候选来源。若只能恢复有效解题历史或部分快照，必须明确标示；不能把它称为全部点击的原样重播。必要的未来记录补足可在本范围实现，历史缺口不可补造。
- 不写回原对局，不改变完成结果、统计、当前游戏、提示库存或成长数据。

### 2.2 调试体验阶段展示全部已找到的合理解释

- 用户主动选择“解释这一步”，先提供已有的直接解释，必要时按需进行多阶段分析。
- 本轮不设“前三条”的界面截断：展示本次受限搜索实际找到并验证的全部非重复代表性解释。长列表可滚动、分页或虚拟化，但不能静默只留前三条。
- “全部已找到”不等于穷尽数学上的所有解释。显示正在分析、完成、取消、失败、搜索受限和无解释状态，明确限制原因。
- 现有离线默认 `maxPaths=3` 会提前结束搜索，不能只去掉 UI 的前三条截断就声称完成。应将搜索预算、结果保留与显示数量解耦；在有限时间/状态/内存预算下保留全部已发现且验证的代表性结果。安全容量达到上限时必须标注截断，不能无限计算或无限保存。
- 去除纯重复和仅由独立步骤换序形成的重复解释，保留有实质不同的推理。候选排序遵循权威协议，不声称全局最优或玩家一定采用。
- 正式产品是否限制三条、如何最终排序与呈现，留待体验后决定；不要增加未经批准的付费限制或数量选择设置。
- **不实现基础解释折叠**：不按题目 Level 或推定玩家水平隐藏基础解释。本轮也不提供该开关。

### 2.3 点击任一解释，复用提示方式逐步演练

- 复用观察、推理、结论的分页文案、棋盘候选高亮、行列宫标记及无障碍说明，支持上一页、下一页、查看结果和退出。
- 多阶段路径明确显示阶段顺序及每一阶段的起始推理盘面，每阶段使用现有 `HintStep` 证明。
- 将现有游戏提示呈现提取成共享组件/展示层，而非复制一套独立提示文案和图形规则；确保正常游戏提示体验不退化。
- 真实历史与推理演练使用隔离的状态。明确标记“可能解释”和省略的中间步骤；演练中的应用只推进演示副本，不调用游戏的 `apply_hint` 或玩家输入命令。
- 退出或切换解释时恢复原真实复盘位置，不留下上条解释的理论排除，不改变原始历史。
- 保留提示辅助/未知状态，不把解释或演练计为玩家独立使用或技巧掌握。

## 3. 明确不做

- 成长档案、评分、成就动画、玩家技能评级和失误分数。
- 基础技巧隐藏、折叠或按等级自动过滤。
- “看看其他技巧”的独立学习入口、搜索与目标动作无关的高级机会。
- 替代路线继续下棋、分支树、全局最优着法或完整求解教学。
- 增加 39 种之外的技巧或为四个历史样本写坐标特例。
- 无限搜索、在正常游戏过程中主动运行重分析、因复盘而扣除提示次数。

## 6. 验收要求

- 有效记录可逐步前后重放，起点/终点与保存快照一致；往返不丢失候选。播放、暂停、切换会话及后台行为可测试。
- 不可恢复的记录明确降级；不显示假造的撤销顺序或错误输入历史。
- 正常提示共享组件改造前后行为一致；演练绝不触发游戏写入、扣费或提示曝光污染原局。
- 解释数量大于 3 的测试能看到第 4 条及之后结果；少于 3 不凑数。搜索/容量截断状态明确，重复路径不膨胀列表。
