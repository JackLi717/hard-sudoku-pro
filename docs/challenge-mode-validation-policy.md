# 技巧挑战模式选题与判题机制

记录日期：2026-10-02。状态：待评审机制设计，尚无挑战编译器或专用判题器。

本文件是未来挑战的盘面准入、证据、步骤和通关语义来源。它不修改普通游戏的提示选择或 [玩家技巧归因协议](player-technique-attribution-policy.md)，也不把可解释动作升级为玩家掌握结论。

讲解和练习复用原题合法性、回放、结构证据及原子结果校验；练习的帮助和完成规则按 [讲解与练习设计](technique-learning-practice-design.md) 执行，不继承综合关进阶门槛。编译检查增加每技巧三至五道免费题、每扩展包五道不同且未与免费及其他包重叠的题，以及跨讲解、练习和挑战的等价局面去重。

## 首期机制范围

建议首期采用真实回放起点、完整原子提交、结构证据校验和受控的有限状态图。状态图列出考核范围内允许的全部步骤和替代路径，移动端在当前状态验证并应用提交；它不是一条只能照抄的标准解答。

首期证据适配器覆盖产品批准的六种技巧。Full House、Naked Single 等基础收尾需独立接入并声明其角色，不能暗中开放整个 40 项目录或让普通提示策略决定考核范围。

所有完整性声明都相对于发布任务允许的技巧、证据规则和原子操作集合。不得声称穷举所有数学解法、任意深度的链或玩家真实心理路径。引擎中未适配的新技巧不是设计人员可以自行启用的配置。

## 起点准入

每个正式起点必须满足：

1. 原题是有效且唯一解的经典 9×9 数独，保留原题给定身份。
2. 当前 values 和候选由共享引擎逐步合法回放产生，每个回放步骤在其操作前状态重新检测并验证。
3. candidate_masks 精确等于回放结果，不能仅检查没有删除最终答案。
4. 考察技巧存在真实的填数或排除结果，关键结构可在当前快照证明。
5. 提交规则、目标、允许技巧和证据类型可由编译器表达。
6. 允许路径中的状态与证明检查完成，没有取消、超时或枚举截断。

人工候选结构只用于隔离的算法反例和回归测试，不进入正式关卡。设计人员不手改题面或候选来制造目标图形；通过生成、搜索和合法回放获得所需状态。

专项关先按现有 Hint Lab 的低级规则偏序推进到固定点，重新确认目标仍存在；否则淘汰。综合关不要求每个状态都没有低级步骤，因为基础收尾和依赖正是考核的一部分，但必须验证低级路径不能绕过核心目标直接通关。

## 结构证据

玩家提交结构依据，校验器在当前完整快照验证约束；系统不要求书写推理全文，也不要求先选择名称。界面可以采用统一的候选、格子和区域选择，证据适配器负责解释这些选择。

| 技巧 | 首期必须能够校验的关键依据 |
| --- | --- |
| Hidden Single | 所选区域、数字与其唯一候选位置；当前区域其他落点全部排除 |
| Pointing | 某宫中一个数字的全部候选落点，且它们集中在同一行或列 |
| Claiming | 某行或列中一个数字的全部候选落点，且它们集中在同一宫 |
| Naked Pair | 两格属于同一区域，候选并集恰为两个数字，结果位于该区域其他格 |
| Hidden Pair | 同一区域中两个数字的全部落点只占两格，排除这两格中的其他数字 |
| X-Wing | 同一数字、两条基础线和两条覆盖线，基础线各恰有两个对齐落点 |

这些是适配器的校验需求，不是所有未来技巧都可以套用的通用证明格式。Naked Pair 的结构同时可能符合 Locked Pair 分类，必须按现有检测器语义核对效果；不通过界面选择强行重新命名。

证据归一化要容忍候选排列顺序和等价区域表达，但不得放过遗漏必要落点、虚构强连接或额外无关结构。每种适配器必须有“结论正确但依据不成立”的反例。

HintStep.premiseCandidates 和 proofSteps 可提供参考，但关键依据不能简单等于固定列表。缺少充分结构数据时补充检测器的可序列化证明或适配器，不凭字符串解释内容推断关系。

## 单次提交

首期建议每次提交只表达一次原子技巧应用：

- placement：一个被直接证明的填数。
- elimination：同一个结构能够产生的完整直接排除集合。

禁止在一次提交中混合填数与排除，或把不相关的两个机会拼成一组。若同一结构有多个排除目标，顺序不影响接受；缺少目标或夹带额外排除不接受整组。

这个完整结果要求必须写在任务说明中。未来如开放“找一个有效排除”，需要单独的部分结果累积契约，不能让现有解释器的部分匹配悄悄改变首期规则。

“排除后形成单数”是新状态下的另一次步骤。普通归因解释器的一跳 placement 匹配不能把来源排除和收尾填数合并为玩家已经提交的过程。

完整判题顺序：

1. 校验提交格式、内容身份、尝试、revision 和完整快照身份。
2. 校验依据是否对应当前状态中的有效结构。
3. 从结构证明计算完整直接结果，比较规范化提交 effects。
4. 查找状态图当前节点下全部等价有效边，保留证据成立的证明变体。
5. 原子应用 effects 与确定性同侪候选传播，产生新快照。
6. 更新该次尝试的有效机会、依赖和综合目标。
7. 返回校验证书，事务保存成功后才展示应用或通过。

最终答案只能作为离线安全检查，不能当作运行时推理证明。一次错误不能先应用正确部分，再拒绝其余部分。

## 替代解法和错误边界

同一技巧有多个有效结构时，满足任务的任何一个都应接受。不同技巧得到相同结论时，依据可验证、技巧在任务允许范围内即可接受，不强制最小 humanCost 或首个检测结果。

专项关明确要求某技巧时，其他方法的合法结论可以反馈为不符合本关任务，而不是“数独推理错误”。综合关不预告技巧顺序，按允许范围接受所有达标路径。

合法但未在允许考核范围内的技巧，不作为错误推理；反馈当前任务范围，并不改变盘面。界面应在进入前说明该集使用已接触技巧，不能让玩家事后才发现限制。

在允许范围内、证明成立却查不到图中的边，说明内容或编译契约有问题；返回 unavailable 并保留尝试，不记玩家错误。正式内容的独立检查必须阻止这种遗漏。

取消、枚举截断、超时、状态缺失和原生故障同样不能转成 rejected 或通过。完整的 no_match 才可参与否定判断；预算内没找到不等于证明不存在。

## 综合目标

GoalSpec 首期建议包含四类条件：

| 条件 | 判定依据 |
| --- | --- |
| 核心技巧覆盖 | 至少两个不同核心技巧结构，有真实接受的步骤证书 |
| 步骤下限 | 至少二至三个有新结果的原子应用，具体由内容声明 |
| 依赖要求 | 至少一个后续考核步骤在起点不能成立，且依赖此前真实效果 |
| 结果目标 | 已达到声明的填数、排除或局部推理目标 |

允许数种结果目标组成成功集合，避免把示范路径唯一终点写成暗中的唯一答案。每个终点都须满足相同核心考核条件。通过后立即结束，不继续枚举无关整盘解法。

一次步骤只贡献一个机会应用。若同一提交支持多个技巧分类，目标匹配器可在各步骤可验证的技巧集合中求一个合法分配，但不能让同一步同时满足两个技巧名额；记录可能分类，不宣称玩家真实选择了哪种方法。若这种歧义会让两技巧考核失去意义，淘汰该局面。

同一机会的重复、剩余结果和等价证明不另算发现。机会身份绑定快照、结构和规范化完整结果；撤销后重做只恢复当前有效路径，不能叠加历史次数。

初期依赖检查采取保守方案：在后续步骤前状态证明其成立，再对照起点与去掉候选来源效果的可达前置状态，确认必要条件与真实父步骤。删除来源后状态无效、反事实未完成或依赖不明时，不计依赖条件。不凭操作先后就宣称发生了技巧衔接。

## 状态图编译

编译器从合法起点进行有界探索。节点包含值、候选及目标所需的覆盖与依赖状态；不能仅按盘面合并，否则同盘面不同考核证据会丢失。边是允许技巧中的完整原子应用，保留合法证据变体。

编译器必须检查：

1. 每个允许步骤的机会枚举完整，不只取 nextStep 的第一条或最低等级前沿。
2. 从每个尚未通关的可达节点，至少存在达标路径。
3. 所有终止路径均已满足目标；不能有合法操作把玩家带进只能重开的考核死路。
4. 达标路径中含必要核心结构与真实依赖，不能只靠基础单数清空盘面而通过。
5. 正式节点及边均可在共享校验器中复现，新快照完全一致。

编译范围只包含本任务允许的操作，撤销沿接受边回退，错误草稿不进入状态图。预期答案路径仅用于讲解，不决定允许边。

最大图节点、路径深度、序列化大小和枚举预算是工程限制，原型测量后冻结。触及限制时将内容标为检查未完成，不能裁剪替代路径后仍宣称合格。若闭合状态图导致合格综合题过少，应在机制阶段重新评审方案，再制作正式内容。

## 难度与内容差异

挑战难度独立于原题整盘 HSP 分数，综合关又独立于其中最高技巧等级。记录目标技巧等级、区域跨度、结构密度、排除目标数量、干扰机会、必要依赖和路径长度；humanCost 只是参考。

首期使用标准、变化、混合三个编辑等级，由试玩校准，不新增评分算法版本或不透明的脑力分数。

生成器对原题和关键结构分别去重。数字置换、旋转、镜像等价的素材不能计作独立新增来源；模式覆盖从真实证明计算，不信任设计人员手填标签。综合题的差异还需检查依赖形态和允许路径，不能仅比较起点字符串。

## 生成与独立检查

流程为设计约束输入、来源检索、合法回放、机会及证据计算、图编译、独立重放、整集检查、体验复核、生成正式资源。

独立检查器重新数原题解、重放起点、重算每条边的证明与效果、验证快照和依赖、检查目标、重新核对图闭合、去重及技巧分布。不信任源文件自报的 unique、complete 或 passed。

共享底层证明规则保持语义一致；独立检查从原始来源重新计算，不只读取编译器缓存。精选样例和对抗反例另行人工检查，以避免共享算法缺陷被两个工具同时接受。

跨功能题目独立是硬门槛，检查完整发布目录中的讲解、练习和挑战三池，而不只检查本批新增题目：

1. 生成器标注 content_usage、source_puzzle_id 和由原题计算的来源族身份；不能信任不同 ID 就代表不同题目。
2. 同一原题来源族只能属于一个功能，数字置换、旋转和镜像等价来源仍视为同一族；另一合法回放阶段也不能跨池。
3. 校验原题及值、候选、给定身份的等价局面，防止不同来源标记掩盖同一考题。技巧名称或一般结构相同本身不是重复。
4. 冲突、来源身份缺失或等价检查未完成，均不允许生成正式发布资源；不能用一条警告代替失败。
5. 正式发行后保持来源用途归属，不通过更新将曾公开讲解或练习的来源改派为挑战。开发期仍维护当前输入和简洁报告，不增加历史数据库或实验审计归档。

运行时验证会话与内容用途绑定。模式切换不迁移已填数字、候选删除、解析曝光或完成事实；共享组件不得读取另一模式的活动状态。

集级检查要求五个不同专项技巧、一个综合关、综合核心技巧已经在本集或前集出现、进阶引用无环、标题任务解析完整。发布资源只有实际完成的整集。

开发期临时候选池和检查点可丢弃。保留当前生成输入、必要来源引用、最终资源和简洁验证报告，不建设实验历史库、审计档案或新版本序列。

## 必须覆盖的验证样例

| 样例 | 必须得到的结果 |
| --- | --- |
| 标准有效结构与完整结论 | 接受 |
| 顺序不同或另一种有效结构 | 接受 |
| 最终答案正确，依据错误 | 拒绝 |
| 只选部分排除或夹带无关排除 | 整组拒绝，盘面不变 |
| 合法技巧但不符合专项任务 | 任务范围反馈，不声称推理错误 |
| 同效果多个技巧证明 | 不重复计算技巧覆盖 |
| 同盘面但候选已改变 | 过期，不计错 |
| 枚举截断或取消 | 不可判定，不计错 |
| 有效替代路径满足综合目标 | 通关 |
| 只用基础收尾绕过核心目标 | 不通关，内容编译应提前发现 |
| 撤销、重做或重复回调 | 当前目标恢复，不重复推进 |
| 查看解析或系统恢复故障 | 保留事实，不伪造独立通关 |
| 同原题不同 ID 或不同回放阶段跨功能分配 | 内容检查失败 |
| 换数字、旋转或镜像后跨功能分配 | 内容检查失败 |
| 同技巧来自独立原题的不同局面 | 可进入各自内容池，继续正常正确性检查 |
| 切换功能携带另一题候选、解析或完成状态 | 拒绝状态串用，不推进成绩 |

通过以上机制验证之后，才能要求关卡设计人员以本规范稳定生产内容。
