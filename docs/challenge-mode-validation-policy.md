# 过关挑战验证规则

当前统一以唯一解判断结果。本规则替代旧的 Hidden Single 终点、实际排除依赖、两类技巧路径和有限状态图检查要求。

## 内容准入

1. 原题必须恰有一个解；已有原生来源 checker 与独立求解器都验证答案。
2. 回放起点中的每个已填值与唯一解一致，原题给定不变；所有空格候选合法并保留答案。
3. 第一集前五个来源分别具备 Hidden Single、Pointing、Claiming、Naked Pair、Hidden Pair 主题的真实有效结构；来源回放与该结构由既有原生 checker 复验。
4. 六关来源相互独立，并与讲解、练习来源去重。开发素材由生成器更新，不手改候选。
5. 输出一份当前 validation-report.json；不保留历史图、数据库或审计归档。

## 运行时准则

- 填数与唯一解相等即正确；删非答案候选即正确。
- 正确结果不因采用其他技巧、省略操作、无技巧声明或不是预选目标而变成错误。
- 第一关和综合关正确填数通关；排除专项正确排除或填数通关。
- 任意多项提交必须全部正确才保存；错误整批回退，保留旧接受结果。
- 无操作或非法请求不计错，保存失败不计推理错误并保留草稿。
- 不从「通过」推断玩家真实思考方式或技巧掌握，不承诺排除猜中。

## 必要回归

所有六关遍历源空格的每种数字、源候选的每种删除，确认同一判据；第九行第五列直接 7 与先删 8、9 再填 7 均通过。错误附加填数不能夹带正确部分接受。覆盖撤销整批、错误数保留、SQLite 重放、重复检查互斥、前台用时与后台暂停。

候选显示验证所有同伴与非同伴格，修改、擦除、撤销及错误回退均能还原；设置关闭自动候选删除时遵从普通游戏偏好。棋盘返回先到当前说明，继续保留操作，说明 Home 才退出。
