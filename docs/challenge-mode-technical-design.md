# 过关挑战技术设计

当前开发基线统一采用唯一解判定，覆盖所有十八关；不再使用技巧范围回查、证明路径匹配或运行时状态图。

## 数据边界

`ChallengeLevel` 含稳定 ID、episode_id、观察主题、原题、回放起点、起点候选和唯一解。构建工具从既有真实回放来源导出，原生 checker 验证唯一性与回放，独立 Python 求解器再次验证答案。共享来源分配记录不包含答案字段。

运行时目录只加载十八个来源，验证解是完整合法数独、给定值一致且候选保留真实答案，然后缓存冻结对象。没有逐节点证明重验，没有全技巧原生枚举，也没有可能把错误答案当成「未找到证明」的超时分支。

## 判定与事务

`domain/challenge/engine.ts` 的 checkChallenge 按唯一解判断每项操作。填数正确、删除非答案候选正确；一次批次任何错误则全部回退并计一次错误。空、重复、给定格或非法请求返回 enter。Hidden Single 专项和各大关综合关以正确填数通过；其余技巧专项接受一次正确排除或填数即通过。

`ChallengeAttempt` 只保存玩家实际操作、批次边界和统计，不保存算法标签、证明编号、图节点或推断的玩家心理路径。restoreChallenge 按当前唯一解重放各批次，拒绝损坏的通过状态。撤销移除最后一批，历史通过事实保持。

Controller 保存成功才发布正式结果，使用进度 revision 与数据库事务。互斥阻止重复检查和导航中的重复保存。保存失败时正式状态不变，界面保留草稿。用时先累积再落盘，失败不丢失也不重复累计。

## 共享棋盘

ChallengeScreen 继续使用 GameScreen，不另造棋盘或输入键盘。challengeState 从来源、正式操作和草稿重建 values 与候选，按普通游戏 autoRemoveCandidates 设置删除同伴候选。替换、擦除和撤销重新计算显示效果，保留独立手工排除。

数字输入不读答案，不限制任意 1～9 的草稿；唯一解仅用于主动检查。草稿错误数字也按普通棋盘规则影响候选显示，检查拒绝后整个草稿回退。

棋盘 Back 与系统返回打开当前说明，保留草稿；无棋盘信息按钮。说明页 Home 回首页。六关导航、上一关说明、固定标题及默认折叠帮助见产品设计。

## 存储和内容更新

内容随 App 发布，用户进度独立存储在 challenge_progress，不改普通题库 SQLite 或普通游戏记录。当前为预发布开发期，更新当前内容与尝试格式，不增加版本或兼容分支。内容身份变化时按当前题目重放验证；新增大关不会丢弃原题上仍然有效的尝试。损坏尝试重建，已有通过与解析事实保留。

HoDoKu 仅为离线工具，不随 App 打包。访问资格独立保存在 challenge_access，以 episode_id 和唯一广告事件记录去重；授予资格的事务验证上一大关六个历史通过事实。CommercialController 使用 challenge_episode placement，只有有效奖励才授予整大关访问资格，Premium 免广告授予。互斥防重复播放，当前会话保留未成功保存的奖励凭据供重试；不改辅助钱包。正式广告市场与同意策略保持原样，侧载 preview 包选择 Google 官方测试单元。

## 验证

覆盖所有关卡每个原空格的 1～9 填数、每个源候选的删除、混合批次、保存失败、重复检查、损坏恢复、候选清理与还原、返回和继续。内容检查验证唯一解、原生来源回放、主题覆盖、候选合法及独立分配。无需枚举玩家路线。
