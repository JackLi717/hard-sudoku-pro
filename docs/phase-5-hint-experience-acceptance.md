# 阶段 5：完整智能提示体验验收记录

日期：2026-09-01

## 交付范围

阶段 5 在既有 `HintStep v1`、C++ 引擎和事务持久化之上补齐了完整提示体验：

- 请求提示前拒绝标红错误、行列宫冲突和与唯一答案矛盾的无解输入；失败不展示提示、不扣
  额度。提示候选与 81 格确定数字指纹绑定，首次请求初始化，填数时增量清理，擦除或替换时
  重建，退出后完整恢复，应用提示后可随整步撤销。
- C++ JSON 边界使用结构化 writer，为每个步骤返回焦点格、区域、前提候选、排除、填数、
  `humanCost` 和可变长度 `proofSteps`；TypeScript 同时校验证据格与当前盘面一致、证明结论
  与原子动作一致，并继续兼容没有新字段的旧存档。
- 39 种正式技巧都有类型安全的英文源名称和观察模板，并从结构化步骤生成“观察方向 → 零到
  多个推理页 → 结论应用”的动态页面。观察页不显示答案，每页只显示自己的证据；翻译资源与
  四语术语审核属于阶段 6。
- 提示以底部抽屉展示，第一页提供关闭/下一步，中间页提供返回/下一步和直接看结果，最后一页
  提供返回/应用。讲解期间棋盘只读但计时继续；展示成功即扣一次额度，关闭不退款。
- 棋盘按当前页面展示焦点格和区域轮廓、带下划线的前提候选、带删除线与“×”的排除候选、
  带“+”的待填数字，并弱化无关格。格子无障碍标签同时读出候选、错误、前提、排除和填数
  结果，不依赖颜色传达提示结论。
- 应用前执行短促的抽屉强调动画；一次提示的所有排除或单一填数仍作为一个数据库事务和一个
  撤销动作，已消耗额度不会因撤销返还。

  SQLite 测试覆盖提示候选和完整撤销快照在进程重启后的恢复。

## 模拟器实际体验修正

- 单元格选择从数据库事务中拆出，改为不增加 revision 的同步展示状态；不会进入全局 `busy`，
  下一次数字、候选、提示、暂停或后台事务仍会保存当前选择，实际游戏操作继续保持原子持久化。
- 游戏计时器改为局部刷新，棋盘和格子使用稳定回调与 memo 化；没有候选内容的空格不再创建九个
  空白候选节点。
- 棋盘不再依靠 81 个格子的半像素边框拼接。横线、竖线、宫线和外框由独立覆盖层按设备像素
  对齐连续绘制，选中及提示边框不会改变基础网格粗细。
