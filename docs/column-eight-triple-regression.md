# 第八列三数组：真实操作漏识别回归

日期：2026-09-03。归因及分段语义只以 [玩家技巧归因协议](player-technique-attribution-policy.md) 为准；本文记录问题证据与测试，不另定义技巧选择策略。

## 真实样本

Android 会话 `session-1788427345446-09ifcnhz`，题库题目 `hsp-f872a45990345b4c276f`。从模拟器只读复制 SQLite 及其 WAL，未改写玩家历史。

操作为 R2C8、R4C8、R5C8 各删 2；R6C8 填 7；R2C8 填 5；R7C8 依次删 1、8；R9C8 依次删 1、8。玩家所述三数组为 R4C8 `{1,6,8}`、R5C8 `{6,8}`、R8C8 `{1,8}`。

## 已确认原因

1. 正确落数后适配层重新生成合法候选与提示排除，没有保留此前玩家明确删除的候选。填 7 后，R2C8、R4C8、R5C8 的 2 被加回分析网格，尽管界面草稿没有加回。原三数组因此消失。对保存的请求仅恢复这三处删除后，native 重新给出 nakedTriple 候选。
2. 两次删除 1 后分别约 1274ms、1230ms 出现删除 8。前段已过空闲截止时间，但 native 尚未完成；新请求取消了前段分析。日志中的 `analysis_cancelled` 是调度导致的漏记，不能据此否定玩家操作。

默认选更简单的解释不是上述缺陷。修复没有增加 C++ 技巧，没有改变 humanCost，也没有把玩家回忆当作确定的技巧标签。

## 修复与回放

正确落数保留其他空格的既有独立候选删除及其来源。封闭片段的分析针对冻结的结束快照完成，正常后续操作不取消它，也不能被其晚到回调覆盖。污染、恢复、超时及资源上限继续由权威协议约束。

`__tests__/behavior-segment-lifecycle.test.ts` 使用实际题目与题库解，经过游戏命令分发、适配层、异步控制器和 native 回放验证：

| 操作 | 保留的合理解释 | 默认解释 |
| --- | --- | --- |
| R6C8 填 7 | 包含 nakedTriple | hiddenSingle |
| R2C8 填 5 | 包含 nakedTriple | hiddenSingle |
| R7C8 删 1、删 8 | 每次均包含 nakedTriple | 每次为 hiddenPair |
| R9C8 删 1、删 8 | 每次均包含 nakedTriple | 每次为 hiddenPair |

回放故意延迟并打乱返回顺序，九次操作均有最终可归因结果，无取消失效。后续请求中 R7C8、R9C8 均为 `{2,9}`，并且原三数组三格保持 `{1,6,8}`、`{6,8}`、`{1,8}`。

在填 5 后的第八列，2、9 只能位于 R7C8、R9C8，所以两次删除 1 也有隐性对子解释。这证明操作可以成立，不能证明玩家脑中实际采用的是隐性对子或某个行列排除技巧。

边界回归覆盖同段请求取代、异步乱序、冻结快照指纹错误、提示、撤销、暂停、恢复、分析失败、超时与队列容量淘汰。该测试文件已在自动验收的 `segment-lifecycle` 阶段运行真实 native。

## 范围限制

修复针对当前观察运行中的连续正向操作，不新增跨恢复的玩家删除持久化。原始诊断没有追溯改写；旧日志仍如实保留当时的失败。工程回归通过不代表 humanCost 已校准，也不代表成长评分可以发布。
