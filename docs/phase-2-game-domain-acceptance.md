# 阶段 2：游戏领域核心验收记录

日期：2026-09-01

## 交付范围

阶段 2 已形成不依赖 React Native、SQLite、广告 SDK 或购买 SDK 的纯 TypeScript
游戏聚合：

- `GameState + GameMove[]` 保存当前局状态和完整命令历史；命令携带时间和操作 ID，
  相同初始状态与命令序列逐字段产生相同结果。
- 支持选格、确定数字输入/替换、候选编辑、擦除、冲突派生、错误识别、三次错误
  失败、暂停/继续、有效计时、完成、明确放弃和失败后重新挑战。
- `manualCandidates`、`quickCandidates`、瞬时 `solverCandidates` 与持久化
  `hintCandidates` 分离；玩家草稿不能反向改变提示证明状态。
- 正确填数按设置原子清理两份玩家草稿；错误填数保留并且不触发清理；普通擦除和
  替换会安全重建已启用的提示候选状态。
- 快速草稿按盘面指纹免费恢复；盘面变化后要求确认。生成采用“校验/计算、替换、
  返回扣费效果”的单次领域转换，失败不会覆盖旧草稿或产生扣费效果。
- 智能提示先准备独立候选请求；有效 `HintStep` 成功展示时记录使用并返回扣费效果，
  应用时把全部排除或唯一填数作为一次可撤销操作。关闭或撤销均不退还已经产生的
  使用次数和扣费效果。
- 撤销恢复确定数字、两份草稿、提示候选和错误统计的操作前快照，同时保留随后发生
  的非撤销模式切换、快速草稿生成以及不可退还的辅助使用记录。
- 题目分配会先从同级未首次完成且启用的题目中选择；同级全部完成后才进入重玩。
  分配使用调用方种子，测试和恢复时可稳定复现。
- 首次完成、完美完成、每连续三次首次完成奖励，以及失败/放弃中断连续完成均已作为
  纯函数实现；重玩不发奖励，也不推进或中断连续首次完成。

## 不变量

- 题目给定数字不可修改；题面必须与完整合法答案一致。
- 错误限制启用时自动强制开启自动检查。
- 暂停、失败、完成和放弃状态不接受棋盘编辑；提示讲解期间棋盘只读。
- 计时只累计 `active` 时段，系统时钟倒退不会减少或重复累计有效时间。
- 操作序号单调增加，撤销后不会复用；重复操作 ID 会被拒绝。
- 快速草稿和提示扣费由 `GameCommandResult.creditSpend` 与新状态一起返回。阶段 3
  数据层必须在同一 SQLite 事务中保存状态和额度流水，不能只提交其中一部分。

## 自动化验收

- 领域测试覆盖给定数字保护、手工/快速/提示候选隔离、候选同步、替换、擦除、
  错误与冲突、第三次错误失败、暂停计时、完成、放弃和重新挑战。
- 覆盖快速草稿首次生成、相同指纹免费恢复、过期确认、额度不足不修改状态，以及
  旧历史不能撤销后生成的快速草稿。
- 覆盖提示候选初始化、展示扣费、原子应用、两份草稿同步、整体撤销，以及使用次数
  和扣费不可退还。
- 覆盖未完成题优先、确定性分配、首次/完美/连续完成奖励和连续完成中断规则。
- `npm run check` 作为合并门槛，包含格式、Lint、类型、schema、C++ 提示核心和 Jest。

## 后续阶段边界
