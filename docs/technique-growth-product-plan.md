## 1. 产品定义

在正常离线数独游戏之外，首先提供可理解的单局复盘：解释玩家的重要填数和候选删除为什么成立、前后操作如何关联，以及还有哪些合理的推理路径。长期技巧成长建立在这些可核验的历史证据上，不再作为当前批次的首要交付。

核心表达：

> 不只完成数独，还能看懂这一局；在长期游玩中，逐渐看见自己的成长。

产品顺序是：正常游戏 → 保存实际操作事实 → 验证合理解释 → 单局复盘 → 积累长期证据 → 在满足成长门槛后提供成长反馈。

系统不是读心工具。它解释“这一步可以怎样推出来”，不宣称“玩家当时一定采用了这个技巧”。存在一个或多个合理解释，本身就有复盘价值，不必先确定玩家的心理过程。

## 2. 首要用途：单局复盘

复盘应帮助玩家回答：

- 这一步为什么能够这样填数或删除候选？
- 前面的排除如何让后面的填数成立？
- 是否有其他合理解释，或成本更低的推理方式？
- 哪些结果受到了提示帮助，哪些有独立完成的行为证据？
- 哪些步骤尚不能解释，是搜索范围限制还是记录不足？

默认提供简洁解释，允许展开前提、关键中间状态和其他解释。不是把全部诊断日志平铺给玩家，也不是把所有基础落数重复包装为技巧发现。

同一前置过程带来的多个结果应能够关联查看；来源排除与填数收尾分别表达，不因最后是单数就抹去复杂前提，也不把一条过程重复统计为多次独立发现。

### 自然玩法都应受到支持

- 完整执行排除，再填数。
- 执行部分排除，剩余步骤心算后直接填数。
- 完全心算中间过程，只操作最终填数或删除。

不要求玩家为了被识别而补做草稿、放慢操作或填写技巧名称。候选删除较少不等于能力较弱；操作详细也不等于理解更深。

### 事实与解释分开

实际游戏历史记录玩家真正执行的操作。程序补出的中间状态只是推理状态，不得伪造为玩家操作，也不能覆盖原游戏进度。

“可能解释”的含义是推理本身可验证，但无法确认玩家是否采用；不是未经证明的猜测。多解释与默认选择、未记录前提、提示隔离和搜索边界均遵循权威协议。

建议文案是“这一步可以通过……解释”“这条路径省略了以下中间步骤”。未找到解释时使用“当前搜索范围内未找到解释”或具体的数据不足原因，不把未匹配直接称为猜测、误打误撞或不会使用技巧。

## 3. 后续用途：长期技巧成长

成长回答“多局下来，处理哪些局面的表现更稳定”，不能由单次合理解释直接推出掌握程度。

应区分本局相关技巧、独立完成的行为证据与长期成长判断。程序能用高级技巧解释一次操作，不等于玩家掌握了该技巧；多条解释也不等于使用了多种技巧。长期判断还需要样本数量、不同题目、提示依赖、稳定性和证据质量。

保留以下后续方向，但不属于当前交付：

- 首页成长摘要、个人技巧档案和技巧详情。
- 待探索、正在成长、已掌握、待巩固的状态设计。
- 可信的发现时间、成长曲线和基础技巧退出重点展示的机制。
- 完成页成长总结、成就动画、可关闭的分级反馈。
- 弱项练习推荐等另行批准的扩展。

操作间隔不直接等于思考某个技巧的时间。发现时间的可测性、评分模型及阈值仍待验证，不承诺仅靠现有记录就能可靠测量。正式成长存储、评分与界面仍须通过 TG-4 及相应产品签收；复盘可用不等于成长评估已经可靠。

## 4. 当前范围与现状

当前优先目标是完善已完成对局的解释与回顾，不建设实时教练、不新增 39 项之外的技巧、不改变题目规则、提示顺序或难度评级。

已有实现是[开发模式内部回顾原型](session-technique-review-prototype.md)、[排除与填数分步原型](reasoning-stages-prototype.md)及[离线多阶段解释原型](multistage-reasoning-prototype.md)。当前入口只针对刚完成的会话，尚无历史对局浏览器；多阶段搜索尚未接入界面。本文不是正式开放入口、历史浏览或成长功能已经上线的声明。

产品定义与首轮方案沟通已完成；当前在离线工具中实现并回归算法，不修改 UI、游戏数据或成长评分。预算与解释契约统一维护在权威协议，原型参数仍需后续校准。

## 5. 复盘验收方向

- 解释必须能在对应的操作前盘面和可靠候选上下文中复现，不能从最终答案倒造技巧证明。
- 真实操作、未观察的中间步骤和提示依赖能被清楚区分；错误、撤销、恢复、过期及记录不足不能被包装成成功证据。
- 多个解释确实支持目标操作；路径长短、成本与搜索范围有可核验依据，不声称搜索之外不存在更简单路径。
- 玩家能理解关键依据及前后关系，而不仅看到技巧名称；手机、iPad mini、大字体和屏幕阅读器均需验证可读性。
- 同一机会的连续删除、填数收尾及备选路径不会造成独立发现次数膨胀。
- 分别报告解释覆盖、证明有效性、污染隔离、重复关联、未解释原因、性能与阅读体验，不用“未匹配归零”代替验收，也不把候选数量变多当作成长证明。
- 使用历史 iOS/Android 对局、39 技巧夹具及对抗反例进行自动回归；用户持续负责体验，不要求为推进工程重新完成独立盲审工作表。

## 6. 离线、隐私与打扰边界

游戏记录和复盘分析在本地处理，不要求账号、联网、云同步或上传逐步行为。新增存储的具体设计后续讨论，原始事实与可重算解释须分离，不能破坏现有进度、统计或诊断历史。

复盘以游戏完成后的主动查看为主要场景，不在游戏中即时确认删除正确性或提前暴露后续结果。不得用算法分析阻塞正常输入，亦不得通过动画制造未经证实的掌握结论。

未来的成长反馈需可关闭、不遮挡棋盘、不抢焦点、尊重减少动态效果；重置、导出和隐私边界在实现前明确。课程、考试、证书、全球比较及不透明的脑力评分不属于本方向。

## 7. 下一轮讨论议题

下一轮围绕“可验证的多阶段可能解释”讨论方案，而非立即扩充检测器：

1. 如何表达一条包含已观察与省略步骤的完整解释，并复用现有 39 项技巧？
2. 如何比较整条推理而不是仅比较最后的单数，保留有意义的备选而不淹没玩家？
3. 如何设置可控搜索范围、记录截断与未知，并遵守现有归因准入边界？
4. 如何区分能在复盘中展示的解释与能够进入长期成长统计的证据？
5. 如何用已分析的四个未匹配动作及全库回归验证收益，同时防止误归因、提示依赖丢失和性能回退？

首轮方案已获确认并记录于权威协议；以上议题继续用于审查原型及讨论后续产品接入，不以离线算法完成代替 UI 和成长验收。
