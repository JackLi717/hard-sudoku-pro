# Hard Sudoku Pro 游戏文案上线审核与改进建议

审核日期：2026-09-10  
审核对象：当前仓库中的正式游戏界面文案，以简体中文为主，并核对英语源文案、界面实际露出和现行产品决策。  
审核结论：**当前文案已有较好的完整度和教学基础，但不建议原样提交商店。完成 P0 项并统一核心术语后，才适合进入上线前真机语言验收。**

2026-09-10 发行范围更新：首个公开版本确定为有商业化版本，核心产品功能仅为游戏、单局复盘、统计和玩法说明。设置、广告兑换、Premium 购买/恢复、隐私与支持属于必要的商业化支撑。数独学堂、我的技巧、技巧成长、本局技巧足迹和成长反馈均不在首发正式文案与设备验收范围；开发版 Hint Lab 同样不在范围内。

## 1. 审核范围与方法

本次检查覆盖：

- 首页、开局与替换对局弹窗；
- 游戏页、暂停、候选数、提示和通用错误消息；
- 完成页、奖励和统计；
- 互动玩法说明；技巧目录及 39 项技巧的中文名称与教学说明仅作为后续版本输入；
- 对局复盘、历史对局、真实操作回放和分析状态；技巧足迹与成长记录只作为后续版本输入；
- 设置、语言、主题及辅助功能相关说明；
- iOS、Android 和 React Native 配置中的产品名称；
- 中英日德四种语言的结构完整性及英语源文案中的共性问题。

正式中文资源约包含 538 个界面键；技巧名称、提示演示和教学说明另有约 350 个文案字段。开发环境专用的 Hint Lab 和诊断页不作为正式用户文案评分对象，但正式界面引用开发式表达时仍计入问题。

本次为源代码层面的文案审核，没有替代以下上线环节：各目标语言母语审校、真机截屏检查、动态字体与屏幕阅读器验收，以及 App Store / Google Play 商店页、隐私政策和购买页的最终审核。

## 2. 总体评价

| 维度 | 评价 | 说明 |
| --- | --- | --- |
| 功能覆盖 | 良好 | 主要状态都有对应文案，四种语言的键结构也有自动检查。 |
| 中文自然度 | 中上 | 主流程简洁，教程语气友好；首发复盘页明显偏工程说明。 |
| 术语一致性 | 待改进 | `Level / 难度`、`快速铅笔 / 快速候选 / 自动候选`、`铅笔 / 备注 / 候选笔记`并存。 |
| 信息可信度 | P0-1 已修正 | 数据失败提示已移除无法保证的安全承诺和重装建议；商业化承诺仍需随阶段 7 实现冻结。 |
| 教学准确性 | 良好但需专家终审 | 推理文案大体严谨；部分技巧名和“看见、强链、覆盖线”等术语缺少新手解释。 |
| 上线完整性 | 未达标 | Premium 仍是不可用入口，购买、隐私、恢复购买、支持等正式信息未闭环。 |

值得保留的优点：

- 首页定位明确，“离线、专注，只用逻辑解题”与产品方向一致；
- 智能提示强调逐步推理，而不是直接泄露答案；
- 多处明确区分“可能的解释”和“玩家实际思路”，事实边界严谨；
- 教程采用动作指令，短句较多，适合移动端；
- 错误状态、加载状态和无障碍标签覆盖较完整；
- 技巧教学不只给结论，还解释候选数为什么能被排除。

## 3. P0：上线前必须解决

### P0-1 数据安全提示存在相互矛盾的承诺

实施状态（2026-09-10）：**已完成**。四语失败文案已改为“暂时无法读取”，明确进度仅保存在本机并警告不要卸载；失败页已提供可实际重新初始化的“重试”按钮。以下保留原审核发现作为变更依据。

原文案（变更前）：

> 已保存的游戏不会受影响。请关闭应用后重试；如果问题持续，请重新安装当前构建版本。

问题：产品同时说明进度只保存在设备上。卸载或重新安装通常可能清除本地应用数据，因此不能承诺“不会受影响”，也不能把重装作为没有备份提示的常规恢复步骤。“当前构建版本”还是明显的开发用语。英语、日语和德语源文案也有同类问题。

建议改为：

- 标题：`暂时无法读取游戏数据`
- 正文：`请完全退出应用后重新打开。你的进度只保存在本机，请勿卸载应用，以免数据丢失。`
- 主按钮：`重试`
- 次按钮：存在真实支持渠道后再显示 `联系支持`

如果工程上不能确认数据是否完好，应明确使用“无法读取”，不要使用“已安全保存”“不会受影响”等保证性表达。对应位置：[resources.ts](../src/localization/resources.ts#L1356-L1359)。

### P0-2 商业化状态与正式文案没有形成同一事实基线

决策状态（2026-09-10）：**发行有商业化的版本**。不再保留“先发布无商业化版本”作为当前方案。P0-2 的产品方向已确定，但实施仍未完成；必须通过阶段 7 并以实际商店与广告行为冻结文案后，才能关闭该阻断项。

当前正式首页展示一个禁用的 `PRO / Premium / 即将推出`入口；完成页仍包含“首次完成奖励”“完美奖励”“连续完成奖励”。现行产品文档则说明商业化新规则尚未实现，且首轮方案不叠加完美、连续完成的额外额度。用户能看到的承诺不能建立在待验证数值或旧逻辑上。

上线前必须在四种语言中补齐并冻结：

- 实时商店价格，以及“一次性非消耗型购买、不是订阅”的明确说明；
- Premium 实际权益：无普通插屏和激励广告、辅助仍消耗有限库存、符合条件的首次完成补给；
- 已冻结的难度补给表、购买启动库存和 `99` 点持有上限，以及 OQ-015 尚待试玩的耗尽体验；
- 免费用户的初始快速铅笔 `3` 次、智能提示 `5` 次，以及每条激励广告只为所选资源增加 `1` 次；
- 首发仅标准激励广告、无任何自动广告或其他广告格式，以及无填充、地区或隐私状态不允许时的降级；
- 购买所需网络、离线权益缓存、恢复购买、购买/恢复失败、退款与支持入口；
- 完成页只展示实际结算：免费用户不显示待领取完成奖励，Premium 用户显示本局实际补给与上限。

“即将推出”不是可发布的备用文案。Premium 入口在首发候选版中必须能打开完整购买与恢复流程；否则候选版不符合已确定的“有商业化首发”范围。对应位置：[HomeScreen.tsx](../src/ui/screens/HomeScreen.tsx#L172-L184)、[resources.ts](../src/localization/resources.ts#L1394-L1395)、[game-feature-plan.md](game-feature-plan.md)、[premium-reward-design.md](premium-reward-design.md)。

### P0-3 缺少上线所需的信任与支持信息闭环

现有设置页没有产品信息、隐私说明、支持方式、版本号；如果启用 Premium，也没有购买说明与恢复购买入口。产品计划本身已将购买、恢复购买和隐私列为首期设置页内容，但当前界面未实现。

建议至少补齐：

- `关于 Hard Sudoku Pro`：版本号、版权和第三方许可入口；
- `隐私说明`：本地保存哪些内容、是否使用广告或分析 SDK、联网发生在什么场景；
- `帮助与反馈`：真实可用的支持方式；
- 如有购买：`恢复购买`、权益说明、价格与计费性质、购买失败和恢复失败提示；
- 商店页使用的隐私政策与支持链接，并与应用内说法一致。

“无需账号”“进度仅保存在本机”“离线游戏”等陈述必须以最终集成的 SDK 和网络行为为准。不能先定营销句，再让实际行为例外。

## 4. P1：首发质量必须完成

### P1-1 统一难度命名，不要在中文界面混用 Level

中文主流程同时出现“选择难度”“五个难度等级”“Level 1–5”和全大写 `LEVEL {{level}}`。这会让产品像未完成本地化，也会使屏幕阅读器读出不自然的英文。

推荐统一为：

- 常规标签：`难度 {{level}}`
- 开局按钮：`开始难度 {{level}}`
- 游戏页眉：`难度 {{level}}`
- 下一题：`下一道难度 {{level}} 题目`
- 技巧目录：`难度 {{level}} · {{count}} 种技巧`

如果品牌决定全球统一保留 `Level`，也应在中文里统一大小写和空格，不能同时存在 `Level`、`LEVEL` 和“难度”。当前测试还把中文 `Level` 固化为预期值，修改时需同步测试：[product-experience.test.tsx](../__tests__/product-experience.test.tsx#L224-L238)。

### P1-2 建立一份面向玩家的术语表

目前同一个候选功能有多组名字：

| 概念 | 当前出现形式 | 推荐用户用语 | 说明 |
| --- | --- | --- | --- |
| 手动候选输入 | 铅笔、手动候选、备注模式、候选笔记 | `笔记` / `候选笔记` | 按钮用“笔记”，说明首次出现时写“候选笔记”。 |
| 自动生成候选 | 快速铅笔、快速候选、自动候选、快速草稿 | `快速候选` | 比“快速铅笔”更直接；如保留原品牌名，至少全局只用一个名称。 |
| 使用配额 | 额度、库存、点、次 | `可用次数` | 面向玩家优先说“剩余 3 次”，账本或内部逻辑再使用“额度”。 |
| 棋盘位置 | 格、格子、单元格 | `格` | 短且自然；无障碍完整句可用“第 2 行第 3 列”。 |
| 一盘游戏 | 游戏、对局、本局、尝试 | `对局` / `本局` | “游戏”保留给整个产品，“题目”保留给谜题。 |
| 数独区域 | 宫、九宫、3×3 宫 | `宫` | 教程首次说明“3×3 宫”，之后简称“宫”。 |

建议先用 5–8 名目标用户快速测试“快速候选”和“快速铅笔”哪个无需解释；一旦确定，代码、教程、错误提示、奖励和商店页必须全部采用同一名称。

### P1-3 把复盘页从“算法报告”改成“玩家解释”

当前复盘正式文案包含“搜索投入”“证明验证标准”“原生调用”“技巧机会枚举”“搜索容量”“验证通过”等术语。信息虽严谨，却让普通玩家承担了内部算法的认知成本。

推荐采用两层信息结构：

- 默认层只回答：系统找到了什么、为什么可能有多个解释、是否还在分析；
- “分析说明”折叠区再解释时间限制、候选数来源和不推断玩家真实思路的边界。

重点替换示例：

| 当前文案 | 建议文案 |
| --- | --- |
| 复盘分析强度 | 分析深度 |
| 档位表示搜索投入，不是玩家等级……搜索预算为 5 / 15 / 30 秒，原生调用可能延后结束…… | 分析越深入，可能找到更多解题思路，等待时间也会更长（约 5 / 15 / 30 秒）。所有档位都使用相同的正确性检查。 |
| 已找到 {{count}} 条验证通过的解释 | 找到 {{count}} 种可能的解题思路 |
| 本轮预算内未找到解释 | 暂时没有找到可展示的解题思路 |
| 技巧机会枚举不完整 | 仍有部分解题思路未检查完 |
| 候选状态更新·来源未知 | 候选数发生变化，来源未记录 |
| 推理演示·候选由程序计算 | 演示用候选数（由系统计算） |

正式文案位置：[resources.ts](../src/localization/resources.ts#L1588-L1679)。

### P1-4 成长页需要保留事实边界，但降低审计口吻

发行范围状态：**不是首发阻断项**。成长页不在首发 Release 构建暴露入口，以下建议保留为后续版本的文案输入。

“归因准入”“复验”“程序可能解释”“未补造历史”“证据覆盖”等词属于模型或数据设计语言。集中出现在玩家页时，会让本应有成就感的“我的技巧”像一份鉴定报告。

建议改写原则：先告诉用户记录了什么，再用一句话说明没有记录什么；详细数据边界放进“统计说明”。

可直接采用的基线：

- `growth.note`：`这里记录你接触和使用过的技巧，仅供回顾，不代表熟练度。`
- `growth.kind.application`：`已确认的技巧应用`
- `growth.kind.possible`：`可能的解题思路`
- `growth.reason.verified_process`：`系统根据这段完整操作确认了该技巧。这里展示的是一种合理解释，不代表你当时一定这样思考。`
- `growth.reason.missing_evidence`：`部分操作或时间没有记录，因此这条内容保持未知。`
- `growth.coverage.complete`：`整理完成 · 仅作回顾参考`
- `growth.aboutBody`：`记录仅保存在本机。查看提示、完成教学和在对局中使用技巧会分别记录；可能的解题思路不会算作实际使用。没有记录不代表你不会这项技巧。`

“完成不代表理解”出现频率也应降低。它作为统计边界说一次即可，不要在完成演练、学习反馈、记录原因等多个正反馈节点重复否定玩家。对应位置：[growth-copy.ts](../src/localization/growth-copy.ts#L115-L192)。

### P1-5 移除普通用户不需要的内部技巧代码

发行范围状态：**不是首发阻断项**。数独学堂和技巧详情不在首发 Release 构建暴露入口；以下建议用于后续恢复正式入口时的审核。

技巧目录当前在每个技巧名下直接显示 `nakedSingle`、`groupedAic` 等稳定代码。这是开发、日志和数据兼容信息，不是学习技巧所需内容；中文资源里还有“稳定技巧代码”标签。

建议：正式目录和详情不显示代码；仅在开发模式或“诊断信息”中提供复制代码的入口。对应位置：[ProductInfoScreens.tsx](../src/ui/screens/ProductInfoScreens.tsx#L290-L309)、[resources.ts](../src/localization/resources.ts#L1464-L1469)。

### P1-6 修正教程规则句的语义

当前：

> 每行、每列和每个 3×3 宫都只能出现一次 1–9。

“出现一次 1–9”不自然，也可能被理解为“整组数字只出现一次”。建议改为：

> 每行、每列和每个 3×3 宫都要填入 1–9，而且每个数字不能重复。请点击高亮的空格。

对应位置：[resources.ts](../src/localization/resources.ts#L1442-L1443)。

### P1-7 统一产品名称

应用内标题是 `Hard Sudoku`，iOS 和 Android 显示名是 `Hard Sudoku Pro`，React Native 配置又是无空格的 `HardSudokuPro`。如果 `Pro` 表示付费权益，免费用户看到它还可能误解当前版本已经包含 Premium。

上线前应确认唯一品牌规则：

- 商店名、桌面名、应用内品牌名是否都为 `Hard Sudoku Pro`；或
- 产品名使用 `Hard Sudoku`，`Premium/Pro` 只表示购买后的权益层级。

确认后同步 [resources.ts](../src/localization/resources.ts#L1369-L1371)、[app.json](../app.json#L1-L4)、[strings.xml](../android/app/src/main/res/values/strings.xml#L1-L3) 和 [Info.plist](../ios/HardSudokuPro/Info.plist#L7-L11)。

## 5. P2：建议在上线润色阶段完成

### 5.1 页面级建议改稿

以下是优先级较高、可直接进入文案表的改稿。涉及产品行为的项目仍需先由产品或工程确认事实。

| 键或场景 | 当前文案 | 建议文案 | 理由 |
| --- | --- | --- | --- |
| `modal.replace.body` | 当前游戏将被记录为放弃，并且无法撤销。 | 开始新题后，当前对局会记为“已放弃”，且无法恢复。 | 明确动作与后果。 |
| `home.subtitle` | 五个难度等级，每一步都有清晰逻辑，无需账号。 | 五个难度，只用逻辑，一步步解开。无需账号。 | 更短、更像产品主张；“每一步都有”是偏强承诺。 |
| `statistics.attempts` | 尝试 | 开局次数 | 统计口径更清晰。 |
| `statistics.completions` | 完成 | 完成题数 | 避免名词不完整。 |
| `settings.candidateNoteAssist` | 备注数字辅助 | 候选笔记辅助 | 与数独术语一致。 |
| `settings.alternatingBoxShading` | 九宫交错底色 | 宫格交错底色 | “九宫”容易被理解为整个 9 宫棋盘。 |
| `game.mistakes` | 错误 {{count}} | 失误 {{count}} | 对玩家更友好；“错误”保留给系统或冲突状态。 |
| `game.pencil` | 铅笔 | 笔记 | 更直观；是否修改取决于术语测试。 |
| `game.remaining` | 剩余 {{count}} 次 | 可用 {{count}} 次 | 在库存位置更自然。 |
| `result.complete` | 完成题目 | 题目已完成 | 更像完成状态标题。 |
| `result.perfect` | 完美完成——没有错误，也没有使用智能提示。 | 漂亮！全程无失误，也未使用智能提示。 | 减少评价感，提升庆祝感。 |
| `result.saved` | 进度和奖励已安全保存。 | 本局记录已保存到此设备。 | 不作无法验证的“安全”承诺。 |
| `replay.historyIntroCopy` | 先快速浏览摘要，需要时再进入完整回放或技巧总结。 | 先看本局摘要，也可以继续回放每一步或查看技巧总结。 | 去掉产品说明口吻。 |
| `replay.available` | 可逐步重放 | 可逐步回放 | 与“观看回放”统一。 |
| `message.insufficient_*` | ……额度已经用完。 | ……可用次数已用完。 | 面向玩家表达。 |
| `message.no_supported_hint` | 当前没有可用的受支持逻辑步骤。 | 暂时找不到适合当前盘面的提示。 | 隐藏实现细节。 |
| `message.level_replay` | 这个难度的题目已经全部完成，开始重复挑战。 | 这个难度的题目已全部完成，接下来会随机重玩一道。 | 明确系统接下来做什么。 |

### 5.2 标点、数字与模板规范

建议形成以下中文格式规范，并用脚本检查：

- 中文正文使用全角标点；范围用 `1–5`，不要混用 `1-5`；
- 数字与中文量词的空格规则需要统一：`3 次`和`3次`二选一；本产品现有主流程更常用空格，建议统一为 `3 次`以提高扫读性；
- 模板变量与名词保持统一：`{{count}} 条记录`，不要同时出现 `{{count}}条`；
- 逻辑式可以保留半角符号，但等号两侧规则统一，例如 `A = 1`；
- `第 {{current}} / {{total}} 步`改成可朗读的`第 {{current}} 步，共 {{total}} 步`；
- 中文界面不使用全大写英文状态词；品牌和技巧原名除外。

### 5.3 技巧名称与教学用语

当前 39 项技巧名称总体可识别，但上线前应由熟悉中文数独社群的编辑做一次术语终审。重点是“准确、可搜索、对新手可解释”同时成立，而不是只做直译。

建议：

- 首次出现保留中英文：`X-Wing（X 翼）`、`Two-String Kite（双线风筝）`；后文只用中文短名；
- `满宫唯一数`实际适用于行、列或宫，建议改为描述性更强的`唯一空格（Full House）`，避免“宫”限制了范围；
- 第一次使用“看见”时解释为：`两个格子能互相排除同一个数字，称为“看见”`；
- 第一次使用“强链 / 弱链”“基线 / 覆盖线”“鱼鳍”“染色分量”时给出一句术语说明；
- 技巧目录中的“目标”和“识别方法”保留，内部代码移除；
- 不要为了术语统一直接批量替换。每项技巧都应在至少一个真实盘面中检查变量插值后的整句。

## 6. 多语言与无障碍建议

项目以英语为源文案，因此中文发现的事实问题要先回写英语源文案，再同步日语和德语，避免下次迭代被旧源文案覆盖。

上线前建议完成：

1. 英语、日语、德语分别由母语编辑审校，不把“键完整”视为“翻译合格”；
2. 为每个翻译键检查占位符集合一致，例如源文案有 `{{count}}`，所有语言都必须保留；
3. 检查插值后的完整句，而不只审查模板片段；
4. 在 iPhone SE 级别小屏、常见 Android 小屏、最大系统字体和横竖屏切换下截屏；
5. 用 VoiceOver 与 TalkBack检查数字键、候选数、棋盘格、提示步骤和图形标记的朗读顺序；
6. 英语复数改用统一的复数规则处理，不长期维护 `gameCount` / `gameCountOne` 这类手工分支；
7. 给技术型长文案设置内容层级，不通过缩小字体容纳全部说明。

## 7. 建议增加的自动化检查

现有测试已经检查四种语言的键集合一致，这是很好的基础。建议再增加：

- **占位符一致性**：各语言同一键中的 `{{name}}` 集合必须与英语一致；
- **未替换占位符**：渲染后不得残留 `{{...}}` 或 `{...}`；
- **正式文案禁用词**：阻止“当前构建版本、原生调用、技巧机会枚举、稳定技巧代码”等开发术语进入非开发界面；
- **品牌一致性**：应用内名称、平台显示名和商店元数据使用同一已确认名称；
- **正式入口检查**：Release 构建不能出现没有动作的 Premium、购买或“即将推出”主入口；
- **关键承诺快照**：本地保存、联网、奖励、购买等句子必须和最终功能事实表一致；
- **无障碍文案快照**：中文步骤进度、棋盘坐标和剩余次数使用自然可朗读的句式。

## 8. 推荐执行顺序与验收门槛

### 第一轮：先冻结事实

- 按已确定的有商业化首发范围，冻结 Premium、广告与完成奖励的实际行为；
- 确认本地数据在失败、升级、卸载和重装时的真实行为；
- 确认唯一产品名；
- 确认 Level 是否作为全球品牌词保留；
- 确认“快速铅笔”的最终用户名称。

### 第二轮：重写主流程

先处理 P0，再统一首页、游戏、完成页、教程和通用错误消息。此轮目标是任何用户不读说明也能完成开局、输入、候选、提示、暂停和结束流程。

### 第三轮：降低高级页面的工程感

首发只重写单局复盘：默认层讲清结果，高级说明层保留严谨边界。不要删除必要的“不推断玩家真实思路”声明，但减少重复和内部术语。成长与技巧教学文案留到后续版本。

### 第四轮：多语言与真机验收

同步英语源文案及日德翻译，执行占位符检查、截屏检查、动态字体和屏幕阅读器测试。

满足以下条件后，文案可判定为达到首发标准：

- 不存在可能诱导用户丢失本地数据的操作建议；
- 所有购买、联网、奖励和数据保存陈述与实际行为一致；
- Release 构建没有无效入口和开发术语；
- 核心术语在全部页面一致；
- 四种语言均完成母语审校和变量插值检查；
- 关键页面在小屏、最大字体和屏幕阅读器下仍可理解；
- 隐私、支持、版本和购买恢复信息与商店材料闭环。

## 9. 本次建议的边界

本报告原始审核未直接修改游戏内字符串。2026-09-10 已由产品负责人确定有商业化首发和四项核心功能的方向；奖励数值、广告位置、SDK、实时价格、退款与支持信息仍必须以实现和商店事实为准。未冻结的数值不得提前写成用户承诺。
