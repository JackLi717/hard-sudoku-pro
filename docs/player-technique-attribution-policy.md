# 玩家技巧归因协议（唯一权威）

本文是玩家行为技巧归因的唯一权威协议。其他产品、算法、评价和界面文档只能引用本文中的字段与决策，不得重新定义“多技巧如何选择”或“什么情况下允许归因”。底层机会搜索中的 outcome/effect 歧义仍是算法诊断事实，不等同于产品层必须放弃默认解释。

## 目标

技巧归因根据玩家在盘面上留下的可观察结果，给出稳定、可解释的默认判断。它不声称能够证明玩家脑中实际采用了哪一种推理路径。

系统采用以下平衡：行为结果限定合理候选，最低人力成本提供默认技巧，未来可选的玩家确认补充系统无法观察到的真实思路。

## 结果匹配

- 玩家直接填数，可以匹配直接产生该 placement 的技巧。
- 排除若干候选数后再填数，可以将这些连续操作作为同一段推理匹配。
- 排除类技巧的全部 elimination 是该技巧可产生的结果，不是玩家必须逐项执行的操作清单。观察到其中一部分即可构成证据。
- 玩家未显式排除候选数而直接填数时，如果某个排除类技巧的结果会立即形成该 placement，该技巧仍可作为合理候选。这种推导只允许一层直接的 Naked Single 或 Hidden Single 闭包，不递归搜索后续技巧链。
- 一个候选技巧必须解释本段中所有已观察操作；只解释其中一部分的技巧不能参与最终选择。

一次操作序列在 placement、转向不相关操作、棋盘修订中断、查看或应用提示、撤销时结束。系统应先累计连续证据再选择技巧，不能在第一个 elimination 后过早定案。

## 默认选择

多个技巧都能解释同一段结果时，默认选择 `humanCost` 最低的技巧；成本相同则使用固定技巧目录顺序。选择必须确定、稳定并且可重复。

这里的“最低成本”表示最容易成立的合理解释，不代表玩家唯一使用了该技巧，也不代表它是整盘数独的全局最优解法。产品文案应使用“系统识别为”或“最简单的合理解释”，不得表述为已经证明玩家采用了该技巧。

即使产生了默认选择，也要保留本次全部合理候选，供诊断、算法评估和未来的玩家确认功能使用。提示、撤销、修订连续性和机会枚举边界的安全限制继续生效；无法完整枚举候选时应放弃归因，而不是从不完整集合中选择。

## 可选的玩家确认

未来可以增加一个默认关闭或由玩家主动开启的确认模式：仅当 placement 完成且存在多个合理技巧时，在空闲界面区域显示候选技巧。最低成本技巧预先选中，玩家不操作时仍采用默认结果，也可以选择自己实际使用的其他候选技巧。

玩家只能从本次算法认可的候选集合中选择，不能把逻辑上无法解释本段操作的技巧写入归因。确认功能不改变数独解题结果，只修正技巧成长归属。

每次行为解释必须输出以下四个概念：

- `candidateTechniques`：本段全部合理解释，按 `humanCost`、稳定技巧目录顺序排列；即使存在多个候选也不得丢弃。
- `automaticTechnique`：当且仅当允许归因且至少存在一个候选时，取 `candidateTechniques[0]`，即最低成本默认解释。成本相同使用稳定技巧目录顺序。
- `selectedTechnique`：未来确认模式中玩家从 `candidateTechniques` 主动确认的结果。原型阶段恒为 `null`；未来未操作时仍以 `automaticTechnique` 作为默认结果，玩家不得选择候选集合之外的技巧。
- `attributionEligibility`：归因准入结果。`eligible` 才允许产生默认或玩家确认归因；`ineligible` 必须带稳定原因码，且 `automaticTechnique`、`selectedTechnique` 均为 `null`。禁止原因至少覆盖 `incomplete_opportunity_set`、`hint_polluted`、`undo_polluted`、`restore_polluted`、`revision_expired`、`board_fingerprint_mismatch`、`rapid_operation_polluted`、`invalid_effect`、`analysis_cancelled` 和 `analysis_failed`。

`selectionSource` 只在未来真正生成成长事件时区分 `automatic` 与 `player_confirmed`，不是本阶段行为识别结果的第五套选择规则。

## 连续动作和污染边界

- placement、玩家明确删除的候选数分别规范化为 `placement`、`elimination` effect；落子引起的自动候选清理不是玩家 elimination。
- 手动候选与快速草稿只决定某次点击是否为玩家明确删除；识别器维护独立 `growthCandidates`，不得直接把界面候选网格当成算法真值。
- 同一观察运行中的正确落数、提示准备/展示/应用、辅助补全及暂停/继续，在盘面没有撤回或改写已填前提、且新落数不与记录中的删除冲突时，保留其他空格上已明确删除的候选：新盘面合法候选及提示排除与原独立候选取交集，同时保留删除来源片段。归因中断不等于候选事实撤回；提示及辅助补全仍污染并中断原片段，不产生独立技巧证据。自动清理不是新 evidence。撤销、擦除、候选撤回、冲突前提和观察器恢复仍执行重建规则，不把本规则扩展为跨恢复的玩家删除持久化。
- 玩家加回识别器曾记录删除的候选时，相关删除片段（包括已结束片段）及当前未结束片段标记为 `restore_polluted`，从当前盘面重建独立候选后重新分段。加回本身不是 elimination，也不产生技巧归因；普通补写草稿不视为候选恢复。原始诊断保留，不改写成成功结果。
- 玩家在同一空格直接填入自己此前删除的数字，也视为撤回该删除：只对未被游戏判错的落数进行此处理。旧删除片段失效，从落数前的盘面重建独立候选，以新片段重新分析 placement；不把相互矛盾的删除与落数强行合并，也不跳过 native 合法性及其他准入检查。
- 擦除已结束落数与撤销历史动作，必须通过具体游戏 move ID 关联其片段；擦除根据该格最后一次改变值的动作定位，撤销根据实际退出历史栈的动作定位。若目标是没有归因的错误输入、提示或草稿补写，不得退回到其他动作的“最近一次技巧”。当前开放片段仍按中断规则处理；恢复后缺少关联证据时不猜测历史片段。
- 同一不可变起始盘面上的连续 elimination，以及其后紧接的 placement，属于一个待解释片段。超时、无关落子、暂停或后台、提示、撤销、恢复、无法可靠排序的快速操作都会结束或污染片段。
- 每个异步结果必须同时匹配 `sessionId`、片段 ID、请求 ID、起始 revision 和起始盘面指纹；任一不匹配都按过期结果丢弃，不能追认到较新的盘面。
- 请求的 `issuedRevision` 保持不可变。观察器仅对连续接收到的选格、铅笔模式/候选来源切换、快速草稿生成及非撤回性的草稿补写，且盘面指纹未变化时，推进内部 `compatibleRevision`；结果必须与该已观察 revision 一致。缺失事件、提示、撤销或盘面变化不能仅凭指纹相同而放行。
- 连续删除的空闲截止时间从最后一个实际 effect 起算，当前原型为 750ms；中性的 UI 操作和慢响应不重置截止时间。截止时已有分析则结算；尚在分析则封闭证据，等待本请求完成，不能再追加稍后的操作。计时回调延迟时，处理新命令前也必须检查截止时间。
- 已封闭片段（空闲截止或 placement）若仍在分析，冻结该片段及其结束时的 session/revision/指纹，允许后续正常操作另起片段。结果只对冻结快照作严格校验并写入历史诊断，绝不覆盖当前识别状态；这不是允许过期结果作用于当前盘面。同一未封闭片段的新累积请求仍取代旧请求。
- 提示、撤销、恢复、擦除、无效操作或候选撤回等中断仍取消待处理分析并记录明确禁止原因；取消后的回调不得复活归因。最多保留 32 个待处理请求，每个请求等待上限 30 秒；超时或容量淘汰标记 `analysis_cancelled`，不把分析延迟误称为玩家快速操作。最新请求真正过期、指纹错误或失败/取消时结束对应片段，旧回调不能清除较新片段。
- 片段 ID 与请求 ID 必须包含本次观察运行的唯一标识，重新 attach、恢复同一 revision、重建控制器或重启应用不得复用。审核导出同时校验会话和片段起始状态，禁止跨会话或跨恢复运行覆盖证据。
- 默认机会搜索达到枚举边界时，适配层使用既有扩容上限复算一次；扩容后仍达到边界才标记 `incomplete_opportunity_set`，不得从不完整候选中选择默认技巧。
- `prepare_hint`、`reveal_hint`、`apply_hint` 均污染当前片段；仅关闭提示不会恢复已经失去的独立性。撤销和从持久化状态恢复同理。
- 提示对盘面的影响与玩家是否独立使用技巧是两件事。已接受的 `apply_hint` 删除必须保留在独立候选中；落数、暂停、恢复、重建观察器和草稿操作不得仅从已填数字重算而加回这些候选。候选重建依据游戏提示历史，不复制界面草稿。撤销提示则撤回其候选影响；擦除或改写提示起始盘面的已填前提后，不再沿用该提示的排除。
- 直接提示辅助的最小边界：提示明确展示的 placement/elimination，以及在提示执行前后首次形成的直接 Naked Single/Hidden Single placement。只比较一步，不递归追踪后续解题链；已存在简单解释的其他落数不会仅因本局用过提示而被禁用。命中该边界的玩家片段为 `hint_polluted`，仍保留实际提示后盘面上的候选技巧，但默认及玩家选择均为 `null`。
- 例如双线风筝提示删除 R4C6 的 3 后，R9C6=3 已成为列唯一数：诊断可以包含 `hiddenSingle`，但不得记为玩家独立完成双线风筝，也不作为独立掌握唯一数的证据。其后无直接提示依赖的操作按更新后的盘面正常评估。
- `hintAssistance` 是请求中的可回放来源诊断，记录实际应用及已知展示的提示、起始盘面、提示效果和本段受助效果，不是新的技巧选择规则。在线适配器与离线回放必须遵守相同准入限制，不能回放 native 结果后重新授予受助片段归因。
- 接受 `reveal_hint` 时，提示及其实际分析候选快照写入 `GameState.hintExposures`，与提示展示状态和扣费一起提交同一游戏事务；不依赖影子日志异步写入。曝光不属于 undo snapshot，关闭、撤销、暂停、重启均不删除。恢复只把已应用提示用于候选排除；曝光本身只用于污染边界，不能把关闭的提示当成已经执行。
- 曝光缺失与空曝光不同。保留对局有提示使用但缺少完整曝光时记录为未知，`hintAssistance.exposureComplete=false`，禁止独立归因，默认和玩家选择均为 null；不从最终答案或现存提示历史补造缺失曝光。新局从空曝光开始；不同会话互不继承。曝光格式损坏或数量不一致必须拒绝作为完整证据恢复。
- 快速操作本身不等于高超或作弊；这里的污染专指前一异步分析尚未完成时发生了无法完整重放或跨片段的状态变更。能按 revision 完整重放的连续玩家 effect 仍可作为一个片段重新分析。

技巧成长可以使用未来的最终选择；自动算法的离线评估仍应使用自动判断，避免玩家选择掩盖算法自身的低估倾向。本阶段只实现协议、实际行为识别原型和离线评价闭环，不实现成长界面、正式成长存储或用户档案写入。

## 跨片段技巧机会归并

- 原始操作片段与机会身份分开，去重不删除记录、不改写候选技巧或默认解释。共享应用层投影 `buildTechniqueOpportunityGroups` 是回顾与未来统计共同的数据来源，界面不得按技巧名或相邻时间自行合并。
- 当前采用结果等价的操作性机会身份，不声称识别玩家脑中的一次发现。C++ 桥返回已有默认候选的完整 `matchingOpportunities`（placement/elimination），不只返回数量，也不只返回本次玩家执行的局部效果；不增加 C++ 技巧或更改搜索排序。
- 在同一会话、同一题目给定格且保留锚点已填数字的后续盘面中，完整结果相同，或执行部分结果后剩余结果完全相同，关联到原机会。关联不依赖观察器运行 ID、时间间隔或技巧名称；不同结果的同名技巧不合并。结果直接形成的一步 Naked/Hidden Single 可关联到原机会，不递归追踪整条解题链。
- 按默认解释的全部匹配机会判断身份；若对应多个可能身份，则为 ambiguous，不强行任选、不做传递并集。其他候选技巧仍完整保留，归并不改变最低成本默认规则。没有完整枚举、缺少保存的机会结果、无最终分析或证据格式不可用时，不提供可计数机会。
- 一个机会最多提供一条代表记录；同一机会包含已失效或受污染片段时，当前保守策略不提供独立归因代表。歧义成员本身不计数，也不能把两个不同机会合成一个。上述只是未来统计的事实准备，不产生掌握分数。
- 历史诊断只有匹配数量而没有机会结果时显示证据不足；不后台重算并回写历史以制造成功归并。原始诊断缺失导致无法确认的情况仍不算通过。正式成长数据和评分须另行设计与验收。

## 跨操作完整机会关联（诊断原型）

- **逐步解释可以越来越简单，但完整过程的技巧归因不能随着盘面化简而被降级覆盖。** 必须区分“当前盘面为什么能填数”与“哪些前置推理使它变得可填”；前置排除不是免费前提。局部 `automaticTechnique` 只解释该局部动作，不得覆盖经验证的完整过程归因。
- 最低成本只在同一起始盘面、同一独立候选快照和同一待解释结果范围内比较。不同起点的局部最低成本不能相加、取最大技巧等级或拼成一条所谓最优路径；不同起点或不同完整机会的合理过程保留为备选，不替玩家猜测心理路径。当前原型不声称求得任意多技巧长链的全局最优解。
- 收尾单数若由已记录的前置效果在原起点的一步闭包中形成，应保留前置技巧作为整段解释，单数作为依赖性收尾，不再作为另一次独立发现。省略的心算排除可以作为合理解释，但不能伪造为实际执行证据。起点已成立的单数仅可作执行关联，不能倒推为复杂技巧的功劳。
- `buildOpportunityProcesses` 是逐步归因之上的独立只读投影，覆盖整个技巧目录，不按技巧名称分支，不替代现有回顾去重或成长统计。它从每一步的全部 `candidateTechniques.matchingOpportunities` 建立候选过程，而不是仅从 `automaticTechnique` 建立。
- 完整结果相同的技巧是同一候选机会的不同解释；执行部分结果后，严格相等的剩余结果可回接原机会。结果仅部分重叠的机会保持独立，输出 `overlaps`，禁止通过交集做传递合并或把各过程都计作独立发现。无论默认名称是否相同，都必须比较具体结果。
- 关联跨越 750ms 分析片段和中性操作间隔，但必须具备连续证据：相同观察运行、给定格与提示来源，前一步应用实际 effect 后的盘面及独立候选必须与下一步起点一致。未知观察身份按独立片段处理；恢复、候选加回、未观察的盘面变化、提示、撤销、缺失最终结果或不完整机会证据会形成边界，不能靠相同最终盘面追认连续性。
- 一个候选过程分别保留起始快照、完整结果、实际执行结果、尚未执行结果、成员动作、后续单数及中断边界。自动清理、心算省略的排除不伪造为实际执行；因此先直接落数的过程可以是部分执行，但仍保留原机会的合理解释。
- 后续单数仅比较原完整机会执行前后的单层结果，不递归搜索技巧链。排除首次形成的单数标为 `new_single`；在原盘面上已可推出、且位于该机会操作格的单数标为 `already_available_single`，只表示执行上的关联，不声称由该技巧新推出或证明玩家意图。
- 图构建阶段不授予整段默认技巧。`verifyOpportunityProcesses` 将真实累积结果送回原始起点做 native 复验，并校验完整响应身份、机会枚举完整性及完整结果。整段继续使用既有四字段协议和 native 的成本排序，不改写逐步归因、不合计局部成本、不凭共同技巧名称猜测整段结果。整段解释有效不等于机会身份唯一；重叠图不产生掌握计数。
- 复验包含已观察的前置效果与新形成的收尾落数。native 的单次请求最多包含一个末尾 placement，因此多个新收尾分别使用同一冻结起点和累计排除复验，仅保留所有检查共有的技巧、完整机会身份与一致成本，绝不在收尾后的简单盘面重新给源技巧定价。起点已有单数直接检查其起始候选成立性，不强行要求 native 把它判为源技巧新形成的单数。
- native 一步闭包接口当前只覆盖排除型结果。直接落数型源机会先在原起点通过 native 验证，再由规范盘面/候选传播检验其直接形成的单数；不要求 native 把其他格子的后续单数识别成该源机会直接 placement，也不递归延长链条。该分支依据 placement/elimination 结果形状，不依据技巧名称。
- `followUps.prerequisite` 区分 `observed_effects`（已经执行的前置效果足以形成该单数）、`unobserved_effects`（完整机会可推出，但需要未观察到的效果）和 `already_available`（起点已成立）。记录的前置效果是一组充分证据，不声称是最小证明，也不倒灌之后才发生的删除。
- 复验输出 `placementExplanations`，保留原 `localAttribution` 和各候选过程的锚点、前置证据及标准四字段归因。`dependencyStatus` 为 `observed`、`possible`、`not_established` 或 `unverified`。只有存在验证通过且有实际前置证据的路径才令 `independentUse=false`；其他情况为 `null`，不等于允许独立计数。多条路径不产生跨起点的默认赢家；图截断不输出此投影，失败或不完整的过程不能授予有效源技巧。输出用于离线诊断及开发模式回顾详情，不接入正式统计。
- 回顾页面保留本步原始解释，只在用户主动复验时读取同一记录的全部备选过程，不将局部过滤当成机会图完整。复验总等待上限 30 秒；取消、刷新、新证据、切换记录或退出页面使该次结果失效。每次运行使用独立请求命名空间，不取消另一运行或游戏分析。过程起始盘面来自冻结证据，不从最终答案反推；显示前置默认解释、备选技巧和实际效果不代表玩家心理意图，也不修改原始诊断、游戏、去重计数或成长档案。
- 当前片段完整枚举后得到 `no_match`，不等同于归因污染：若其真实操作仍属于先前已保存的完整机会，可作为该过程成员，但标记 `locallyMatched=false`，不改写原始未匹配记录；整个过程必须在原起点通过 native 复验。这个例外不适用于提示、撤销、过期、枚举不完整或缺失最终结果。
- 默认最多建立 512 个候选过程；图被截断时保留诊断，不发布截断集合上的整段默认解释。完整图按每批最多 128 个过程串行复验，批次之间让出执行权，直至全部处理，不因过程总数超过单批容量而整体拒绝。报告记录实际批次大小、尝试数及产生归因结果对象数（不是独立技巧使用数）；单次失败、过期或枚举不完整时仅该过程不发布归因，继续处理后续批次。离线命令对每次 native 调用保留 30 秒超时与 16 MiB 输出上限，不修改原始诊断、游戏进度、用户档案或评分。
