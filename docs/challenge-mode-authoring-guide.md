# 技巧挑战模式关卡设计规范

记录日期：2026-10-02。状态：未来内容生产规范草案，尚未制作正式挑战。

设计人员负责提出考察目标、筛选局面、组合体验和编写任务解析；工具负责证明、判题资源和数据生成。产品以 [产品定义](challenge-mode-product.md) 为准，正确性以 [选题与判题机制](challenge-mode-validation-policy.md) 为准。

## 讲解和练习的配套交付

学习、练习和挑战分别标明内容用途。每种发布技巧配一个免费完整讲解和三至五道独立免费练习；扩展练习以同技巧五题包交付，稳定 pack_id 显式引用五道题，不靠变换、重复题或不足五题满足广告奖励。

讲解侧重清楚的证明演示，练习侧重标准结构、变化及辨认，挑战侧重无提示的应用与综合目标。课程和练习可展示解析，挑战活动状态不能读取相关答案。三部分的原题来源必须独立；不同回放阶段、数字置换、旋转和镜像不能跨功能复用，题目来源与等价局面冲突由工具拒绝交付。基础正确性机制可以共享。

具体访问与帮助规则见 [讲解与练习设计](technique-learning-practice-design.md)，练习题不占挑战五个专项关的名额。免费题和扩展题随实际技巧发布，不要求在首批覆盖全部目录。

## 设计人员的工作边界

设计人员可以选择已支持技巧、结构模式、编辑难度、公开任务、综合目标、来源引用和排序。可以淘汰不清楚、重复或节奏不好的例子，也可以请求工具定向寻找素材。

设计人员不能手改题目、候选或答案，不能添加技巧检测器、自定义判题脚本或逐题特例，不能通过内容配置改变广告奖励、进阶条件或普通游戏评分。若现有约束找不到合适素材，报告内容缺口；由产品与机制评审决定如何调整。

## 设计输入

以下设计单是工作规格，未来由编译器定义正式机器输入格式。填写文字约束和来源引用即可，棋盘及证明由工具生成。

| 字段 | 专项关填写 | 综合关填写 |
| --- | --- | --- |
| 稳定内容身份 | 所属集、level_id 和顺序 | 所属集、综合 level_id |
| 学习目的 | 希望玩家观察到的关系 | 希望玩家连接起来的推理关系 |
| 技巧范围 | 一个目标技巧及允许证明 | 允许技巧、核心技巧集合与基础收尾 |
| 结构变化 | 区域、方向、模式及结果 | 核心结构、干扰与依赖形态 |
| 提交任务 | 单次填数或完整直接排除 | 同样的逐步原子提交及最终目标 |
| 难度 | 标准、变化或混合及原因 | 核心等级、步数、依赖和预计体验 |
| 来源 | 原题引用、可选回放定位 | 原题引用、可选起点定位 |
| 替代解法要求 | 哪些有效结构应被接受 | 成功目标集合及多路径要求 |
| 任务与解析 | 四语语义稿和证明引用 | 考核说明与一条或多条示范解析 |

对预计时长先记录假设，试玩后修改；不能为了维持时长手改候选或限制正确替代路径。任务不能泄露关键坐标；专项关可公开技巧名称，综合关不公开顺序。

## 选题过程

1. 确定学习目的和可执行约束，不先从漂亮图形倒推虚构题目。
2. 从现有题库按技巧检索候选，使用原生引擎重放并定位实际目标机会。
3. 缺少合格来源时，由生成器定向生成唯一解原题，再搜索合法起点。
4. 编译候选的证据、状态图、目标和解析资源。
5. 独立检查正确性、完整性、重复及核心技巧覆盖。
6. 人工观察结构是否可辨、干扰是否合理、反馈是否清楚，进行陌生盘面试玩。
7. 组合完整挑战集，检查节奏和综合关，生成正式资源。

检索报告中出现目标技巧不表示某个局面已经合格。内部 Hint Lab 的合格例题可作为候选来源，仍需通过挑战提交规则和状态图检查，不能直接改名发布。

## 专项关准入

起点必须真实可达，目标结构有实际作用，没有已定义的低级动作直接绕过目标。排除目标数量适合首期整组提交，依据选择在小屏上可操作。

优先让同一技巧的例子在方向、区域关系、必要观察和结论上有实际差异。布局更拥挤并不自动更有价值；候选密集但毫无新观察的例子可以淘汰。

专项任务要求某技巧时，应接受该技巧的其他有效机会；若存在特别容易造成误解的等价分类，选更清楚的素材或交给机制评审，不让玩家猜设计者命名。

## 综合关准入

综合关使用单个连续起点，所有核心技巧已在本集或以前内容出现。初期优先二至三个关键步骤，至少两个核心技巧结构，并有真实跨步骤依赖。

不能把五道互不相关的题放在一个页面上称作综合考核，也不能只增加图形密度。不同有效路径均需达标且不会进入考核死路，全部接受路径由编译器和检查器验证。

设计人员提供一条示范讲解路径，不指定唯一可玩路径。若其他有效路径更短，只要满足目标就接受；若更简单路径完全绕过核心目标，回到选题阶段处理。

## 组集和长期节奏

每集五个专项关的目标技巧不同，第六关进行综合考核。综合关应呼应本集重点，不要求机械使用全部五种技巧。

初期使用产品建议的六种技巧池。后续可安排一个新技巧、三个当前阶段技巧和一个旧技巧复习，并确保五种不同；新技巧只有完成证据适配和机制验收后才进入内容池。

每批扩展按整集发布。新内容需要解释带来的学习变化：新技巧、新结构模式、新依赖或混合判断。轮换数字和镜像只作为复习素材，不抵扣独立新内容配额。

30 集和长期 100～150 集只是规划容量，设计人员不承担凑满数字的要求。先制作少量完整集并观察继续率、任务理解和重复感，再决定补充量；内容更新继续随 App 发布。

## 交付内容

每次交付包含当前设计输入、必要原题及回放引用、生成后的完整集资源、四语任务解析和简洁验证报告。报告列出实际集数、专项及综合数量、技巧分布、结构差异、替代路径检查、唯一性与完整性结果，以及尚未完成的体验检查。

题面、候选、证据和状态图全部由工具导出。不要保存每轮实验数据库、原始生成日志、历史验证副本或人工编辑的已发布资源。

## 发布前核对

| 检查 | 通过条件 |
| --- | --- |
| 集结构 | 五个不同专项技巧加一个综合关，引用完整且无进阶环 |
| 正确性 | 原题唯一、合法回放、证据与效果可复验 |
| 判题公平 | 所有允许替代路径被接受，截断不被当作完成 |
| 综合目标 | 两类核心结构和必要依赖确实出现，无考核死路 |
| 任务一致 | 玩家看到的范围等于实际执行的提交与通关规则 |
| 内容差异 | 不能靠数字置换或几何变换冒充独立新例子 |
| 三池独立 | 讲解、练习、挑战不共享原题来源族、等价考题或其他回放阶段 |
| 用户体验 | 手机和平板竖屏、四语、大字体、读屏及候选选择可用 |
| 数据边界 | 不修改普通题库评分、奖励、成长统计或广告市场规则 |

工具失败返回机制开发；正确性合格但体验不好返回设计；广告、进阶或新技巧要求返回产品和技术评审。不能通过在某道题中埋入特殊规则解决这些问题。
