# 免费辅助钱包与 Premium 无限权益验收

更新日期：2026-09-28

状态：代码、持久化与四语运行时文案已实现；真机商业流程及 Beta 验收待完成。

## 1. 验收结论边界

当前构建只保留一套首发前开发基线：免费玩家使用可跨题保存的全局辅助钱包，
通过初始额度、首次完成和逐次主动激励广告获得额度；Lifetime Premium 无限辅助且不进入钱包经济。
自动化测试已覆盖本文的核心领域、SQLite、协调器、商业控制器和界面边界；本文仍保留真机和
Beta 门槛，未通过的发布配置或设备验收不能被自动化结果替代。

## 2. 目标规则

### 免费玩家

- 新用户初始获得快速候选 `3` 次、智能提示 `5` 次，仅发放一次。
- 两种资源分别持有，分别以 `99` 为上限，可以跨题保存并离线使用。
- 每次有效智能提示消耗 `1` 次。
- 快速候选第一次成功生成或明确确认的重新生成消耗 `1` 次；显示、隐藏和恢复已有快速候选免费。
- 每个有效激励广告事件只为所选资源增加 `1` 次，并写入可持久化的全局钱包。
- 每道新题第一次合法完成获得快速候选 `+1`，智能提示按 Level 1–5 获得 `+1/+1/+2/+2/+3`。
- 提示辅助完成与独立完成获得相同基础补给；完美和连续完成不叠加辅助额度。
- 同一道题重玩不重复发放完成奖励。

### Lifetime Premium

- 智能提示无限使用。
- 快速候选第一次生成和重新生成均无限使用。
- 不读取、显示或扣除免费钱包。
- 不请求或展示激励广告。
- 完成题目不发放辅助额度。
- 首次购买和恢复购买均不补满 `99`，也不创建额度奖励事件。
- 使用智能提示仍记录真实次数，并按提示辅助完成结算。

## 3. 初始钱包与上限验收

- 新建用户数据时恰好发放快速候选 `3`、智能提示 `5`。
- App 重启、开始新局、重新挑战、重置统计、恢复购买和升级均不能重复发放。
- 两种资源不能互相转换，任一资源变化不影响另一资源。
- 广告和完成奖励都按 `99` 上限裁剪，余额不得超过 `99` 或低于 `0`。
- 满仓时不得播放无法兑现的对应资源激励广告。
- 完成奖励在满仓时可以实际入账 `0`，但首次完成资格仍必须原子结算，不能以后补领。
- 钱包余额、累计获得、累计消费及每条流水在 SQLite 重开后保持一致。

## 4. 智能提示验收

- 免费玩家有余额时可以在无网络状态正常请求提示。
- 只有有效 `HintStep` 的第一阶段成功展示时才消费 `1` 次；后续推理页和应用不重复消费。
- 用户看过第一阶段后关闭，仍记录为已使用一次。
- 盘面冲突、标红错误、已完成盘面、引擎无结果、计算失败或请求取消均不消费。
- 余额为 `0` 时不能先展示提示再形成负数；应提供可拒绝的单次激励广告入口。
- 广告奖励到账后取消提示、盘面变化或计算失败时保留获得的额度；之后成功展示有效提示才消费。
- 同一提示请求、持久化重试和恢复流程均不能重复消费。
- Premium 连续请求有效提示不改变钱包余额，但每次仍增加真实提示使用计数。

## 5. 快速候选验收

- 免费玩家当前题第一次成功生成快速候选消费 `1` 次。
- 隐藏后重新显示、恢复同一指纹的候选和正常落数后的自动清理不消费。
- 手工修改后确认覆盖并重新生成再消费 `1` 次。
- 盘面非法、存在标红错误、生成失败或用户在确认前取消均不消费。
- 余额为 `0` 时可以通过一条有效激励广告获得 `+1`，随后成功生成再消费，正常结束余额为 `0`。
- 广告奖励到账后取消重新生成或生成失败时保留额度。
- Premium 第一次生成和任意合法重新生成均不消费钱包，但覆盖手工修改仍需保持现有明确确认。

## 6. 激励广告验收

- 只允许标准激励广告，不新增插屏、激励插屏、横幅、原生、开屏或自动广告。
- 每次播放前明确显示所选资源和固定奖励 `+1`，并由玩家主动选择。
- 免费玩家可以从奖励页主动储备，也可以从对应资源不足的游戏入口进入。
- 点击、加载、展示和关闭事件均不能代替有效奖励事件。
- 有效奖励事件成立后，即使随后关闭或短暂断网，也必须把 `+1` 保存到钱包。
- 加载失败、无填充、隐私状态不允许、地区不可用、提前关闭、跳过或拒绝均不入账，也不影响手动游戏。
- 同一广告事件的重复回调只能入账一次；奖励收据与钱包变化必须在同一事务保存。
- 不自动播放下一条广告，不提供批量观看、后台播放或每日广告任务。
- Premium、商店审核 Premium 和本地缓存的有效 Premium 均不能进入广告请求路径。

## 7. 免费完成奖励验收

目标补给表：

| 首次完成难度 | 快速候选 | 智能提示 |
| ------------ | -------: | -------: |
| Level 1      |     `+1` |     `+1` |
| Level 2      |     `+1` |     `+1` |
| Level 3      |     `+1` |     `+2` |
| Level 4      |     `+1` |     `+2` |
| Level 5      |     `+1` |     `+3` |

- 只有完成时为免费权益且该题尚未完成过才发放。
- 提示辅助完成、独立完成和完美完成使用同一张基础补给表。
- 零错误、无提示、连续完成和单局积分不能额外增加辅助额度。
- 失败、放弃、开局、暂停和恢复未完成游戏不发放。
- 同一道题重玩、完成事件重试、App 重启和重新打开完成页都不能重复发放。
- 免费阶段已经首次完成的题目，之后购买 Premium 不追补。
- Premium 期间首次完成的题目不发额度；以后退款或撤权也不补发免费奖励。
- 完成记录、首次完成标记、实际入账奖励、钱包和流水必须在同一事务提交或一起回滚。
- 达到上限时完成页只显示实际入账数；两种资源均实际入账 `0` 时显示已满说明，不制造待领奖池。

## 8. Premium 购买、恢复与撤权验收

- 首次成功购买后立即切换为无限智能提示和无限快速候选，不补充数值库存。
- 购买前的免费钱包余额原样保留但隐藏，Premium 使用期间不消费、不因完成或广告增加。
- 恢复购买与站外兑换识别得到相同无限权益，不重复生成奖励事件。
- 前台刷新、商店静默同步和购买成功提示继续按既有流程工作。
- 离线启动使用最后一次有效的本地 Premium 缓存；联网后由平台权威状态刷新。
- 商店明确退款或撤销后恢复购买前保留的免费钱包；不追扣历史使用，也不补发 Premium 期间的免费完成奖励。
- 商店不可用、查询失败或网络中断不能误撤销最后一次有效 Premium。
- iOS 与 Android 权益仍分别绑定各自商店账号，没有 App 账号时不承诺跨平台共享。

## 9. 完成页与统计验收

- 符合资格的免费首次完成显示本局两项实际入账奖励。
- 免费重玩、Premium 完成、失败和放弃均不显示辅助补给模块。
- 完成页可说明 `99` 上限造成的实际入账裁剪，但不能显示未到账的理论奖励为可领取。
- 免费与 Premium 使用同一成绩展示，不因权益身份改变题目基础分。
- 智能提示使用次数继续计入本局结果、统计和复盘。
- 快速候选使用次数继续按现有统计定义记录。
- 未使用智能提示的积分奖励保持不变；Premium 无限不自动获得“未使用提示”奖励。
- 合法完成事务重试必须保持幂等，不能因奖励资格变化破坏完成记录、积分或首次完成标记。
- 统计可以按来源汇总初始发放、广告奖励、免费完成奖励和实际消费；Premium 无限使用不伪装成钱包消费。

## 10. 难度与题库不变量

- 不改变五档技巧等级、HSP 评分算法、`difficulty_score` 或正式题库内容。
- 不提高同级最低分，不按广告消耗选择题目，也不把任何题定义为必须看广告。
- 题目分配继续面向真实难度与内容质量；余额与广告数据只用于校准奖励数值，不反向改写评级。
- 自动完成、手工候选、错误处理和提示原子步骤保持原有领域边界。
