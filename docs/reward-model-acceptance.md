# 奖励模型实现验收

日期：2026-09-10

## 验收结论

奖励领域逻辑与 SQLite 数据事务通过自动化验收。免费用户、Premium 用户、库存上限、广告奖励收据、购买启动补给和辅助消费均使用同一当前开发基线。

本报告不代表 AdMob、App Store 或 Google Play 的真实 SDK 流程已经接入；相应界面、商店回调和真机商业化验收仍属于阶段 7。

## 已实现规则

- 新用户初始获得快速铅笔 `3`、智能提示 `5`。
- 免费用户首次、完美或连续完成均不获得辅助额度。
- 免费用户每个有效激励广告事件只为所选资源增加 `1` 点。
- Premium 在结算时首次完成题目，Level 1–5 固定获得快速铅笔 `+1`、智能提示 `+1/+2/+3/+4/+5`。
- 提示辅助完成与独立完成获得相同的等级基础补给；完美和连续完成不叠加额度。
- 快速铅笔和智能提示对所有用户每次均消耗 `1` 点；Premium 不再绕过库存或获得无限辅助。
- 免费与 Premium 的两种资源上限均为 `99`；满仓结算只记录实际入账数量。
- 首次成功购买 Premium 时补足至快速铅笔 `3`、智能提示 `5`；恢复购买不重复发放。
- 免费阶段已经首次完成的题目不在购买后追补，重玩不再次发放。
- 游戏完成、首次完成标记、实际奖励、钱包和流水在一个事务中提交。
- 广告和购买启动补给使用独立收据；即使满仓实际入账为 `0`，重复回调也不能在以后补发。

## 自动化覆盖

定向奖励回归：

```text
Test Suites: 5 passed, 5 total
Tests:       65 passed, 65 total
```

覆盖内容包括五个难度补给表、免费完成零奖励、Premium 权益结算、99 点裁剪、广告单资源 `+1`、重复广告事件、满仓零入账收据、首次购买补足、恢复不补发、Premium 禁止广告兑换、额度消费及 SQLite 重开持久化。

静态检查：

```text
npx tsc --noEmit 通过
npm run lint 通过
```

完整 Jest 回归共 `3150` 项，其中 `3125` 通过、`17` 跳过、`8` 失败。失败集中在既有技巧成长/复盘展示和机会分组测试；这些文件不在本次改动范围，定向复跑仍以相同断言失败。奖励相关测试全部通过。

## 阶段 7 剩余验收

- 接入真实激励广告 SDK 后验证有效奖励事件、提前关闭、加载失败、断网和重复回调。
- 接入商店购买后验证首次购买、恢复购买、离线权益缓存及 iOS/Android 各自商店账号边界。
- 真机验证免费零库存入口、Premium 零库存说明、完成页实际入账和 `99` 点满仓文案。
- 试玩 Premium 零库存和题库首次完成耗尽后的长期体验；不得自行增加每日赠送、广告兜底或重玩奖励。
