## 1. 文档目的与边界

本文档保存可能用于未来产品决策、市场验证和新项目探索的构想，避免有价值的讨论随时间丢失。这里记录的是**机会、假设和备选实验**，不是已经确认的产品需求、技术承诺或开发排期。

本文件不得用于改变当前开发线路。发生冲突时，以下文件始终优先：

1. `docs/product-and-data-architecture.md`：产品与数据架构决定。
2. `docs/game-feature-plan.md`：首期游戏定义和功能边界。
3. `docs/development-roadmap.md`：阶段顺序、交付物和验收门槛。
4. `docs/cpp-hint-engine-development-plan.md`：提示引擎技术目标。
5. `docs/open-questions.md`：尚需明确批准的产品和技术决策。

未经产品负责人明确批准，不得因为本文档中的构想而新增 SDK、网络服务、埋点、账号、社交能力、玩法模式或修改当前数独规则。

## 2. 已有能力所带来的机会

当前项目采用 React Native 构建 iOS/Android 客户端，并以独立 C++20 核心提供 39 项 Level 1–5 数独技巧检测和结构化提示。这一架构可作为未来提示体验、玩家能力分析和衍生玩法实验的技术基础。

外部讨论使用了“20ms 极速解题引擎”和“高胜率技术壁垒”等表达。这些属于战略叙事或目标假设，不替代仓库中的性能验收数据，也不能作为对外宣传依据。任何性能表述必须以目标设备上的发布构建实测为准。

## 3. 候选产品方向

### 3.1 启发式提示与“战争迷雾”

在现有棋盘遮罩、局部高亮、候选标记、删除线和多步讲解之上，研究更克制的提示层级：

- 第一层只提示值得观察的局部区域或相关行、列、宫。
- 第二层提示可能使用的技巧或技巧难度，但不展示结果候选。
- 第三层逐步展示参与推理的格子和候选关系。
- 最后一层才展示可应用的落数或候选删除。

目标假设是减少直接剧透，保留玩家自己完成推理的顿悟感。是否优于当前标准动画提示，需要后续行为实验验证，不能仅凭主观偏好替换默认体验。

### 3.2 Brain Lab：技巧熟练度与错题追踪

候选能力包括：

- 记录不同技巧被玩家自主识别、错过或请求提示的次数。
- 记录面对特定盘面时的响应时间、撤销、擦除和试错趋势。
- 以趋势图或技能雷达图呈现技巧熟练度。
- 根据长期弱项推荐练习残局或技巧复习。

该方向可能形成可感知的“脑力资产”和长期成长反馈，但与首期“不包含课程、考试或学习进度”的边界冲突。因此它只能作为未来版本候选，必须先形成独立 PRD、数据口径和隐私评估，再决定是否进入路线图。

### 3.3 泛娱乐化衍生玩法

以下方向保留为未来测款或独立产品构想，不属于当前 Hard Sudoku Pro 的游戏定义：

- **卡牌肉鸽数独**：把数独技巧包装为可构筑能力，正确识别或触发技巧产生局内收益。
- **侦探/密室逃脱数独**：把盘面和推理包装为线索、机关或案件推进。
- **每日共同残局**：所有玩家面对同一高难残局，比较推理路径质量或分享结果。

这些玩法会显著改变内容系统、平衡、联网、社交和商业模型。如需尝试，应先作为隔离原型或独立项目验证，不能直接侵入当前离线单人数独代码路径。

### 3.4 核心引擎复用

未来可以评估把“高性能规则检测、结构化推理、确定性回放”能力抽象后复用于卡牌数独或其他规则型游戏。外部讨论提到“海外掼蛋”，目前仅作为架构研究线索；不同游戏的规则、信息模型和求解目标差异很大，不能假设现有数独求解器可以直接复用。

### 3.5 未来数独技巧目录扩展

当前 `hsp-1.2` 已冻结 39 项 Level 1–5 人类逻辑技巧，覆盖基础唯一候选、区块交互、显性/隐性数组、基础鱼、主流单数字图形、Wings、染色、唯一性、链和 Forcing。生产 10,000 题的评级报告包含 637,504 个逻辑步骤，全部可用当前体系完成；标准评级路径实际只使用其中 35 项。因此当前技巧集合不存在首发内容阻塞，本版本不得为了增加目录数量而继续扩展。

“技巧数量”不能直接代表逻辑覆盖能力。同一个推理可能被不同体系命名为 AIC、Nice Loop、X-Cycle 或某种特定 Wing；通用链检测器可能得到相同结论，但不会以具名技巧展示。未来评估时必须分别判断：

- 是否存在当前引擎无法推出的逻辑能力缺口。
- 是否只是已有 AIC、Grouped AIC、Coloring 或 Forcing 推理的另一种教学名称。
- 新名称是否真的能让玩家更容易理解，而不只是扩大宣传数字。

对照 HoDoKu 等主流专家体系后，未来候选按产品价值分为以下优先级：

1. **优先研究 ALS 家族**：ALS-XZ、ALS-XY-Wing、ALS Chain，以及与之关系密切的 WXYZ-Wing 和 Sue de Coq。这是当前 39 项中最明确的体系性空白；Death Blossom 可在基础 ALS 证明稳定后再评估。
2. **补充常见高级变体**：Finned/Sashimi Swordfish、Finned/Sashimi Jellyfish，以及 Unique Rectangle Type 2–6、Unique Loop 和更一般的 BUG 变体。
3. **只为专家内容评估**：Franken Fish、Mutant Fish、Siamese Fish、Kraken Fish、五阶以上基础鱼、Templates、3D Medusa 和其他具名链循环。部分技巧可能已被现有通用链逻辑覆盖，不应默认新增独立检测器。

未来扩展的触发条件至少满足一项：

- 新题库中出现无法由当前 39 项稳定解出、又希望保留的高质量题目。
- 数独学堂明确升级为专家课程，用户确实需要独立的 ALS 或高级鱼类教学。
- 真实使用数据表明足够多玩家完成 Level 5，并持续需要更高难度内容。
- 市场定位经过验证，需要以更完整的专家技巧体系形成可感知差异。

一旦批准扩展，必须作为独立版本工程处理：提升 `rating_version`，重新评级和回放全部题库；为每项技巧补充正例、反例、答案安全、确定性和性能测试；增加结构化证明、Hint Lab fixture、四语名称与教学正文，并重新校准 Level 5 边界。任何扩展仍不得引入猜测、试错或通用回溯提示。

## 4. 候选数据验证方案

### 4.1 轻量行为事件流

讨论提出的候选方案是：客户端先在内存或本地队列记录操作事件，在合适时机批量异步上传，由轻量 Serverless API 和数据库接收，再通过 Python 脚本进行离线分析。

可能关注的事件包括：

- 选格、填数、擦除、撤销和候选数操作。
- 请求提示、提示层级、查看步骤和应用提示。
- 技巧代码、盘面阶段、响应时长和退出位置。
- 单局开始、完成、失败、放弃和恢复。

该方案尚未获准实现。即使不使用第三方 SDK，自建采集仍属于产品分析和个人数据处理，必须遵守同意、最小化、保留期限、删除机制、传输安全、儿童与目标市场法规以及商店隐私披露。它受 `OQ-007` 约束，不能以“静默”或“盲发”为由跳过用户知情和合规评审。

### 4.2 A/B 测试假设

候选实验是比较标准动画提示与启发式“战争迷雾”提示，观察：

- 次日和七日留存。
- 平均单局时长及完成率。
- 高难关卡退出率。
- 提示使用率、逐层展开率及应用率。
- 提示后继续游戏与短期退出的比例。

实验必须先定义主要指标、护栏指标、样本分配、最短观察窗口和停止规则。未接入合规分析能力前，可先进行本地可用性测试或小规模、明确同意的封闭测试。

### 4.3 冷启动买量假设

外部讨论提出：首期使用约 `500–1,000 美元`，优先在部分 T2 市场投放 Android，在 `7–14 天`内争取约 `1,500+` 样本。这里的预算、CPI、地区和样本质量均是待验证假设，不是已批准的发行计划。

执行前至少需要重新核实：

- 目标国家的实时 CPI、设备结构、语言覆盖和付费能力。
- “安装”“有效玩家”和“可分析样本”的转换关系。
- 统计功效以及该样本量能检测出的最小效果。
- 广告平台归因、隐私同意和数据跨境要求。
- 只投 Android 对 iOS 产品决策的外推限制。

## 5. 从构想到正式需求的准入规则

任何构想进入正式线路图前，必须依次满足：

1. 明确要解决的用户问题，而不只是功能描述。
2. 提供与当前游戏定位一致的使用场景和成功指标。
3. 说明对离线能力、隐私、性能、包体和维护成本的影响。
4. 通过小型原型、用户测试或可信数据验证关键假设。
5. 形成独立产品决策，更新权威产品文档和待确认问题台账。
6. 获得产品负责人明确批准后，才可进入开发路线图和排期。

## 6. 建议的未来验证顺序

在不改变当前路线图的前提下，未来可以按风险从低到高评估：

1. 使用现有 Hint Lab 做启发式提示的离线交互原型，不接入生产游戏。
2. 通过人工可用性测试比较标准提示和分层提示是否更容易产生自主推理。
3. 研究只保存在本地的技巧熟练度模型，先验证指标是否可信。
4. 在阶段 7 正式决定分析与隐私策略后，再设计事件 Schema 和服务端方案。
5. 发行准备成熟后再评估 A/B 测试、目标市场和买量预算。
6. 卡牌、侦探、每日联网挑战或其他游戏复用应作为独立立项讨论。
7. 只有在新内容、专家教学或真实用户需求触发时，才按 3.5 的优先级评估扩充 39 项技巧目录。

## 7. 当前结论

这些构想已被完整保留，供未来产品决策参考。当前继续严格执行既有游戏定义和开发路线图；本文档本身不产生任何新增开发任务。
