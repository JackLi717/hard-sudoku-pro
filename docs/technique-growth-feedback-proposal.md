## 1. 已确认原则

> 即时反馈鼓励参与，长期统计描述趋势，掌握结论随证据逐步建立。

- 从第一局提供成长入口、接触记录与适度反馈，不要求先达到可靠掌握判断才能看见积累。
- “可以用某技巧解释”“观察到符合准入的应用”“长期表现稳定”是不同结论。
- 允许证据不完整，表达必须真实；样本增多不自动消除系统性误判。
- 提示和演练有学习价值，但不是独立使用证据；不以误填、没有匹配、未做草稿或操作慢否定能力。
- 独立掌握发布仍需既有可靠性门槛；本原则确认不等于评分和成长存储方案已批准。

## 2. 从第一次使用就能看到什么

第一版推荐四个入口，而非新建一套复杂教学系统：

1. 首页“我的技巧”：初次显示“从第一局开始，记录你的练习”，不显示0分或39项未掌握。
2. 游戏中可关闭的轻反馈：不遮挡棋盘、不阻塞输入，不要求玩家确认技巧。
3. 完成页“本局技巧足迹”：最多三条摘要，详细记录仍可展开全部查看。
4. 技巧详情：证据类别、涉及对局、近期变化，点击具体例子进入现有复盘。

首版总览优先显示最近接触和近期有记录的技巧；全部39项另在“全部技巧”中查看。没有记录写“尚无记录”，不写“不会”。

## 3. 即时反馈怎么鼓励

| 情境 | 建议文案 | 记录与限制 |
| --- | --- | --- |
| 第一次实际查看技巧提示 | “已记录一次隐性对子学习” | 记录已展示事实，不声称理解或学会 |
| 完成一段解释演练 | “完成一次宫内锁定演练” | 记录完成事实；重复回看不刷成长次数 |
| 符合归因准入的完整应用过程 | “本局新增一次技巧应用记录” | 单局总结注明系统默认解释及证据，不宣称读心 |
| 仅有复盘可验证路径 | “这一步有一种宫内锁定的可能解释” | 仅在复盘或局后展示，不进入独立应用计数 |
| 多次同类行为 | “又积累了一次相关练习” | 仅在来源和归因明确时使用；同机会先去重 |
| 没匹配或分析未完成 | 不弹负面反馈；详情写“分析待完成/证据不足” | 不计失败、不扣分、不伪造成功 |

建议默认使用“简洁”反馈；参考旧版调度设计，首版游戏内每局至多1条，优先重要的新接触，其余合并到局后，而不是本草案最初设想的3条。同一技巧同一机会只反馈一次，过期消息移到局后，不排队连续弹出。该频率仍待体验校准。减少动态效果时使用静态文字，无声音/震动默认奖励、无强制弹窗。

即时确认正确性本身可能成为辅助：游戏内默认不根据后台新推理宣布“删对了/填对了”，不披露未执行的删除和下一步答案。可即时反馈用户已知的提示查看/演练事实；自动应用标签默认进入不主动展开的记录区或局后总结。若未来在游戏中展示实质推理，须先按提示曝光处理，不能悄悄影响后续独立性。此限制不取消从第一局提供成长反馈。

奖励以“被看见的努力和具体过程”为主，不与提示货币、等级解锁或连续打卡惩罚挂钩。首版不制作掌握庆祝动画或积分排行榜。

## 4. 一局结束后如何总结

本局卡片分三栏，可为空：

- 学习接触：如“查看了隐性对子提示；完成了宫内锁定演练”。
- 应用记录：协议允许归因且通过完整过程校验的记录，使用默认解释，不称已掌握。
- 值得回看：仅有可能解释、多解释或未解释的操作，附明确状态。

例如：“本局接触2种技巧；新增3个可归因应用过程；另有1步值得回看。”这些数来自不同类别，不相加成“使用6种技巧”。分析尚在进行时允许先展示事实，后续补充并标明更新时间。

## 5. 长期统计如何实现

### 5.1 统计对象是机会过程，不是点击

保留原始事件、提示曝光与可验证证明引用，生成可重算投影，不改写事实。给完整机会过程稳定去重身份：同一局同一机会的连续删除及填数收尾只计一个独立应用过程；收尾可作为依赖步骤展示，不再计第二次独立发现。不同备选路径作为同一记录的解释，不为每个候选都加一次成功；按权威协议取默认解释，其他候选不丢失。

提示受助记录与独立准入记录分开；撤销撤回相关有效应用投影但不删除真实学习曝光。重新填回同一机会不刷次数。快速可重放操作不惩罚；断点、恢复、过期等严格遵守协议。仅省略路径推导、枚举不全或准入不明，归入“可能解释/待分析”，不能通过多次累加变成独立证据。

### 5.2 首版显示可解释的数量，不显示掌握百分比

每项技巧显示：首次已记录接触、最近活动、接触过的不同对局数、可归因应用过程数、涉及不同题目数、提示受助记录、可回看的例子。日期只能称“首次记录”，不能当作真实首次学会的日期。缺少旧数据时说明统计起点。

趋势默认对比“最近10局已完成对局”与“之前10局”（建议值待批准），同时显示有效证据涉及几局、几道不同题目。样本不足时只显示累计与“继续积累”，不强行画趋势。不同窗口的日期范围和难度构成同时可查，避免误把题变简单当成进步。

推荐先画两类离散记录：可归因应用、提示辅助学习。不同分析/证据状态另列，不用平滑曲线制造连续测量。统计为0并非能力为0；没有机会、没用该技巧或没匹配不能当失败。

首版不展示“独立完成率/正确率”：尚缺可靠的机会分母。可展示“可归因记录变多”，但不能直接翻译为“掌握率提高”。掌握评分、发现耗时和自动降级均暂缓。

### 5.3 状态和鼓励结论

| 状态 | 可据以表达的条件 | 不得暗示 |
| --- | --- | --- |
| 尚无记录 | 没有可展示事实 | 不会使用 |
| 开始接触 | 有提示曝光或演练事实 | 已理解 |
| 应用积累中 | 有通过协议准入的应用记录 | 已独立掌握 |
| 多局出现应用记录 | 暂建议至少3道不同题目中累计5个合格过程 | 已经达到科学测定的掌握门槛 |

上述3题/5过程仅是描述性里程碑草案，不是已批准的能力阈值。升级后可在局后说“你已在3道不同题目中留下这项技巧的应用记录”。“表现更稳定/已掌握”需另有可靠评价依据及产品批准，不能由该阈值自动推出。

“待巩固”首版作为可选关注项，允许玩家主动标记；提示变多、长期没玩都不自动贴负面标签。未来若有相当难度和可靠机会分母，再讨论系统建议。

## 6. 实现结构和性能约束

已接受事件 → 现有证据与机会过程分析 → 准入/去重投影 → 单局足迹 → 多局聚合 → 文案展示。

建议最小持久投影保存：会话/动作或事件引用、技巧与过程身份、记录类别、证据状态、来源/依赖、首次记录时间、分析配置指纹与更新时间。仅为设计概念，不在本文另创一套归因字段；具体字段在实现前与现有协议对齐。保存原始输入引用以便重新计算，更新算法时保留旧事实、明确统计重算，不把变化包装为玩家突然进步或退步。

成长不是复盘搜索结果数量的累计：用户选择初级/高级/专家不能直接改变成长权重或造成升档刷成长。独立成长统计采用统一、固定且可追溯的证据分析口径；复盘更高预算发现的路径只补充可回看内容，除非另经统一归因流程验证。

即时层读已有事实，不启动额外高成本搜索；机会分析复用现有流程，缺结果记待处理，先局后批处理，能在后台/退出时安全中断。游戏输入优先，所有数据本地保存，不上传。

成长开关控制展示，不默认删除数据；重置成长与删除原对局必须分开，需明确用户确认。不增加账号/同步。首版不要求玩家填写技巧名称。

## 7. 开发顺序与验收

方案批准后再实施：

1. 对齐证据分类、去重与数据投影；用既有iOS/Android历史回归，报告可用/受助/未知覆盖，不能仅报通过数量。
2. 第一版交付第一局即有的入口、接触记录、局后足迹和可点击复盘例子；明确无掌握评分。
3. 增加多局统计与里程碑；先验证不同难度、缺数据、重复题和撤销不会造成虚假进步，再开放趋势文案。
4. 最后与提示/复盘统一讲解和动画体验。已掌握分数、发现时间、曲线与个性练习另行签收。

验收反例：同一对子删6次不计6次；同一步3条解释不计3次；提示锁定带出的单数不算独立；纯心算不因草稿少扣分；未解释不扣分；重复演练不刷增长；撤销与重填不刷次数；重启不重复聚合；复盘预算升档不增加能力分；旧局重算有来源而不伪造新学习。

体验验收：第一局有内容且不出现0分羞辱；所有结论能点回依据；至少能一眼区分“学过/可能解释/可归因应用”；关闭反馈和减少动态效果有效；不遮挡输入、不提前泄露解题答案；大字号与读屏可用。

## 8. 本轮待用户确认

- 是否接受首版“接触＋应用积累＋事实趋势”，暂不显示掌握率？
- 是否接受游戏内轻反馈只讲已知学习事实，技巧应用的自动判断主要放在局后，避免成为额外提示？
- 是否接受先上局后足迹和技巧详情，再加入趋势，不先做成长动画？

统计窗口、反馈频率和里程碑数字是可调整建议，不需要用户现在逐项决定；批准总体方向后再以样本校准。

## 9. 对之前功能设计的取舍

参考[原开发计划](technique-growth-development-plan.md)的指标目录、M2存储、M4成长界面及M5互动反馈。下表是重新评估后的建议，不直接恢复原评分口径。

| 之前设计 | 本次取舍 | 产品理由 |
| --- | --- | --- |
| 首页成长摘要 | 保留，显示最近一条具体进展 | 首局就有入口，不拿“掌握0项”作开场 |
| 39项成长总览 | 保留全部目录，默认突出近期有记录项 | 完整而不让新手面对39个失败标记 |
| 技巧详情及原始样本 | 优先保留，并连接真实复盘 | 鼓励应有依据，用户可以检查系统的判断 |
| 完成页成长总结 | 恢复为首版核心入口 | 不打断思考，也能集中呈现有意义的反馈 |
| 成长曲线 | 先恢复事实活动轨迹，暂缓能力/速度曲线 | 能画出记录，并不意味着测出了能力 |
| 永久里程碑 | 保留可核实的学习经历，不永久固化推测性能力标签 | “第一次完成演练”是事实，“已掌握”可能需要重算 |
| 四种生命周期 | 改成接触、应用积累等证据状态；掌握仍后置 | 避免低证据时过度承诺，也不把没玩视为退步 |
| 初期/近期/最佳发现时间 | 不恢复为首版用户指标 | 操作间隔无法确定究竟在思考哪一个机会 |
| 独立率与提示依赖率 | 分别显示记录数量，比例暂缓 | 机会分母与不同难度混合会让百分比误导 |
| 反馈分级、合并、延后和回执 | 保留工程设计，简化可见层级 | 重启不重复庆祝，连续操作不连续弹消息 |
| 丰富/简洁/关闭 | 保留设置方向，默认简洁；丰富动画后置 | 用户可控，且不能与复盘计算三档混淆 |
| 可重算档案、统一ViewModel | 保留 | 所有入口同一统计口径，不各自计算成长 |

来源事实更正或旧记录被判无效时，相关派生里程碑允许更正并注明原因；不能为维持“永久”而保留错误统计。重算不生成“今天新学会”的庆祝。

## 10. 推荐的首版完整体验

### A. 首页：一张卡，不做评分仪表盘

初次使用：“我的技巧 · 从第一局开始记录。”有数据后：“最近接触：隐性对子”“最近3局新增2条应用记录”。点击进入总览。数字均须能追溯，不同类别不混算。

### B. 总览：最近积累优先，完整目录可查

顶部给出近期学习与应用两类事实；下面是“最近有记录”“我想巩固”，另可查看全部39项。技巧卡示例：“隐性对子 · 开始接触 / 涉及2局 / 最近一次来自提示”。状态旁标注来源，避免把提示学习误看成独立掌握。

### C. 技巧详情：让数字变成自己的经历

先用一句话描述“目前记录到什么”，再给接触、应用、涉及题目数量及最近样本。事实轨迹可按对局查看，点选进入对应步骤复盘。未解释、受助、缺失证据不必堆诊断术语，但有“为什么这样记录”入口。首版只复用已有技巧简介和演练，不在此重新设计整套教学。

### D. 完成页：告诉我本局有什么值得记住

默认静态卡，最多三条不同性质的事实摘要。例如：“第一次查看隐性对子提示”“宫内锁定出现新的应用记录”“有一步可以回看另一种解释”。允许直接下一局，不强制看完，不把基础技巧折叠规则偷带进复盘。计算晚到的结论在卡内补充，不中途弹回完成页。

### E. 里程碑：庆祝经历，不颁发能力证书

首版建议只保留三个类别：首次记录接触、首次完成对应演练、跨不同题目积累应用记录。前两者来自实际事件，第三者依赖统一准入和去重；具体计数阈值待批准。先做静态徽记与一句话反馈，动画等提示/复盘整体体验统一时再决定。

首版交付应让人感受到“我留下了哪些学习和应用记录”，而不是展示一页数据库计数。长期趋势在这些可核对的经历上逐步形成；未验证的能力分数不承担鼓励任务。
