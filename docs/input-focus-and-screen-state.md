# 数字优先焦点与页面状态恢复

发行范围说明（2026-09-10）：本文同时记录当前页面状态机制和已实现的实验页面。首发 Release 只开放游戏、单局复盘、统计、玩法说明及必要支撑页面；下文数独学院、我的技巧、单局成长足迹和 Hint Lab 的状态规则不表示存在首发入口。

## 1. 数字优先是否需要默认选中格

建议不人为选择左上角或第一个空格。数字优先时，玩家首先选择的是数字，尚未指定填入位置；默认选中某格会让这两层意图混淆。清爽的无格子焦点状态是合理起点。

应分别理解三个视觉状态：

- 数字键选中：接下来点格子时使用哪个数字。
- 单元格选中：玩家最后明确操作的位置，也可作为擦除等操作的目标。
- 行、列、宫高亮：相对某个选中格的辅助阅读信息，适合按偏好开关。

当前代码也分别处理这三者。初始 `selectedCell` 为空，选数字后只更新数字键；点过棋盘后才有格子及其行、列、宫高亮。因此前后视觉差异来自“是否点过格子”，不能据此认定游戏初始缺少必要焦点。

### 建议

1. 数字优先的新局不设置默认格子，也不自动替玩家选数字。
2. 保留当前选中数字的明显反馈；点过格子后保留轻量格子定位，保证擦除等操作目标明确。
3. 喜欢清爽棋盘时，关闭现有“高亮相关区域”，保留“高亮相同数字”。这会让前后视觉一致，不需要另造一种输入模式。
4. 格子优先维持点格子后显示相关区域的习惯；智能提示的证明高亮独立遵循共享棋盘语义。
5. 不建议仅因更换数字而删除业务层的 `selectedCell`，否则擦除目标及返回后的操作位置也会一起丢失。

本轮未强行更改用户的区域高亮设置或新增默认格子；此部分交付为设计建议。

## 2. 页面往返丢状态

直接原因是页面通过条件渲染切换，返回首页时 `GameScreen` 被卸载。数字键选择和候选聚焦原本只存在页面的 `useState` 中。设置本身及游戏盘面已有持久化，并不是所有状态都没有保存。

现在通过应用级 `ScreenStateProvider` 保留导航期间的轻量交互状态，页面卸载后仍可恢复，按局 ID、回放 ID、技巧 ID 或页面键隔离。没有把所有页面常驻隐藏，也没有让后台计时器继续运行。

| 页面 | 本轮保留的状态 | 重置边界 |
|---|---|---|
| 正在玩的游戏 | 选中数字、候选聚焦开关及数字、同一提示的讲解页、滚动位置 | 新局独立；切换为格子优先清除锁定数字；新提示重新开始；已填满数字退出候选聚焦 |
| 设置、首页、统计、帮助、结果 | 各自滚动位置 | 结果按局隔离；弹窗、确认操作不恢复 |
| 数独学院 | 技巧目录和每个详情的滚动位置 | 按技巧隔离 |
| 历史列表、单局回放 | 列表位置、每局回放帧、回放速度 | 回来保持暂停；显式从成长记录跳转时以记录定位为准；历史长度变化时夹到合法范围 |
| 我的技巧 | 所选技巧、标签、筛选、展开项、显示数量和各子页滚动位置 | 预览弹窗及异步操作不恢复 |
| 单局成长足迹 | 该局筛选、展开项、滚动位置 | 按局隔离；预览内容重新加载 |
| Hint Lab | 目录筛选、模块内当前页面、每项技巧最后选择的例题、目录位置 | 切换例子仍重置临时演示与已应用状态；验收记录仍由原数据库保存 |
| 单局调试复盘 | 选中条目、列表与详情滚动位置 | 数据重新加载，不保存原生分析任务 |

滚动位置只在进入页面时恢复，滚动事件更新记忆但不反向控制当前手势。异步历史列表在数据就绪时重新挂载滚动视图，避免空列表先把恢复位置限制为零。所有棋盘仍使用当前应用主题。

### 保留范围与后续建议

本轮修复覆盖同一次应用运行中的“游戏 → 首页 → 设置 → 首页 → 继续”、模块往返，以及进程仍存活的前后台切换。**不包含杀进程或冷启动后的临时界面状态恢复**。游戏盘面、进度和设置继续走已有持久化。

若进一步要求冷启动也恢复操作现场，建议只把“当前未完成局的选中数字、候选聚焦”等少量上下文存入用户存储，并按局校验；列表像素位置、播放状态、弹窗、进行中的请求不宜全量持久化。这和本轮导航恢复是不同的验收范围，不应混为“保存所有界面对象”。

验收包括实际应用级的设置往返、新局隔离、输入模式切换，回放重新进入后的位置和暂停状态，以及通用页面状态与滚动位置恢复检查。最终测试结果见本次交付说明。
