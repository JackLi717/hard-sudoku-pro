# 数字优先焦点与页面状态恢复

发行范围说明（2026-09-10）：本文同时记录当前页面状态机制和已实现的实验页面。首发 Release 只开放游戏、单局复盘、统计、玩法说明及必要支撑页面；下文数独学院、我的技巧、单局成长足迹和 Hint Lab 的状态规则不表示存在首发入口。

## 1. 数字优先是否需要默认选中格

建议不人为选择左上角或第一个空格。数字优先时，玩家首先选择的是数字，尚未指定填入位置；默认选中某格会让这两层意图混淆。清爽的无格子焦点状态是合理起点。

应分别理解三个视觉状态：

- 数字键选中：接下来点格子时使用哪个数字。
- 单元格选中：玩家最后明确操作的位置，也可作为擦除等操作的目标。
- 行、列、宫高亮：相对某个选中格的辅助阅读信息，适合按偏好开关。

当前代码也分别处理这三者。初始 `selectedCell` 为空，选数字后只更新数字键；点过棋盘后才有格子及其行、列、宫高亮。因此前后视觉差异来自“是否点过格子”，不能据此认定游戏初始缺少必要焦点。

### 官方资料比较（2026-09-08 查阅）

### 建议

1. 数字优先的新局不设置默认格子，也不自动替玩家选数字。
2. 保留当前选中数字的明显反馈；点过格子后保留轻量格子定位，保证擦除等操作目标明确。
3. 喜欢清爽棋盘时，关闭现有“高亮相关区域”，保留“高亮相同数字”。这会让前后视觉一致，不需要另造一种输入模式。
4. 格子优先维持点格子后显示相关区域的习惯；智能提示的证明高亮独立遵循共享棋盘语义。
5. 不建议仅因更换数字而删除业务层的 `selectedCell`，否则擦除目标及返回后的操作位置也会一起丢失。

本轮未强行更改用户的区域高亮设置或新增默认格子；此部分交付为设计建议。

## 2. 页面往返丢状态

直接原因是页面通过条件渲染切换，返回首页时 `GameScreen` 被卸载。数字键选择原本只存在页面的 `useState` 中。设置本身及游戏盘面已有持久化，并不是所有状态都没有保存。

现在通过应用级 `ScreenStateProvider` 保留导航期间的轻量交互状态，页面卸载后仍可恢复，按局 ID、回放 ID、技巧 ID 或页面键隔离。没有把所有页面常驻隐藏，也没有让后台计时器继续运行。

| 页面 | 本轮保留的状态 | 重置边界 |
|---|---|---|
| 正在玩的游戏 | 选中数字、同一提示的讲解页 | 新局独立；切换为格子优先清除锁定数字；新提示重新开始 |
| 设置、首页、统计、帮助、结果 | 各自滚动位置 | 结果按局隔离；弹窗、确认操作不恢复 |
| 数独学院 | 技巧目录和每个详情的滚动位置 | 按技巧隔离 |
| 历史列表、单局回放 | 列表位置、每局回放帧、回放速度 | 回来保持暂停；显式从成长记录跳转时以记录定位为准；历史长度变化时夹到合法范围 |
| 我的技巧 | 所选技巧、标签、筛选、展开项、显示数量和各子页滚动位置 | 预览弹窗及异步操作不恢复 |
| 单局成长足迹 | 该局筛选、展开项、滚动位置 | 按局隔离；预览内容重新加载 |
| Hint Lab | 目录筛选、模块内当前页面、每项技巧最后选择的例题、目录位置 | 切换例子仍重置临时演示与已应用状态；验收记录仍由原数据库保存 |
| 单局调试复盘 | 选中条目、列表与详情滚动位置 | 数据重新加载，不保存原生分析任务 |

滚动位置只在进入页面时恢复，滚动事件更新记忆但不反向控制当前手势。异步历史列表在数据就绪时重新挂载滚动视图，避免空列表先把恢复位置限制为零。所有棋盘仍使用当前应用主题。

游戏操作区规则（2026-09-30）：棋盘、数字键和工具栏必须完整显示在当前屏幕内，不支持页面滚动。竖屏按控制区的实际高度限制棋盘尺寸，较矮横屏按可用高度缩放控制面板；尺寸切换时容器允许收缩，避免沿用较高布局而溢出屏幕。提示讲解仅在正文区域内滚动，不移动棋盘或操作区。

棋盘尺寸规则（2026-10-01）：本次调整仅覆盖游戏页和正式单局复盘页，Hint Lab、玩法说明及其他棋盘保持原布局。两页棋盘使用安全区域内左右各 6 个逻辑像素的最小边距，取消游戏布局的 720 宽度限制和棋盘的 700 尺寸上限；棋盘按可用宽高尽量放大，受高度限制时允许增加左右留白。横屏下棋盘左侧、棋盘与操作区之间、操作区右侧均分剩余宽度，避免把空白全部堆在中间。游戏页缩减键盘、工具栏之间及底部的空白，保留控制区实际高度测量和固定布局。正式复盘按实际工作区和播放控制区高度计算棋盘，预留独立讲解区；讲解图例放在正文滚动区内，打开分析时不移动棋盘。仅这两页的大数字与候选数字随实际格子尺寸缩放，每格九候选的行高保持在候选槽位内。

本次验证：布局定向测试覆盖短手机、平板横竖屏、父容器测量、保存/暂停尺寸稳定及每格九候选显示。全量 Jest 运行通过 3854 项，发现两条旧布局断言；更新间距和图例位置断言后，该套件 4 项复测全部通过，合计 3856 项通过、17 项既有跳过。类型、lint 和修改文件格式检查通过（lint 保留 5 条既有警告）。iPad 开发版竖屏实测棋盘和候选数放大、操作区完整可见；当前 iOS 原生方向配置仅支持竖屏，本次未修改该配置。

首发方向规则（2026-10-01 更新）：手机和平板统一只支持竖屏；该原则已写入 AGENTS.md。Android 在 Activity 清单和启动配置中锁定竖屏，iOS 保持已有竖屏配置。保留现有横屏布局代码及测试，不开放方向切换入口；用户后续明确调整产品规则时可重新启用。

竖屏锁定验证：Android 调试构建、类型检查及 4 个相关 Jest 套件共 134 项通过。在上述两台 API 35 平板上通过 ADB 加速度传感器模拟物理旋转，游戏页和正式复盘页保持竖屏，棋盘及操作区完整可见；测试后恢复传感器及系统旋转设置。当前未连接手机 AVD，也未实测 Android 16；应用已有游戏类别声明，按 [Android 16 官方规则](https://developer.android.com/about/versions/16/behavior-changes-16#large-screens)属于大屏方向限制覆盖的例外。

此前双方向布局实测：通过 ADB 在 Medium_Tablet_API_35（800×1280 dp）和 HSP_7in_Tablet_API_35（600×960 dp）验收游戏页、正式复盘页及横竖屏切换，棋盘、候选数和操作区完整可见；横屏三处空白均分，滑动不移动棋盘或工具栏，复盘分析正文独立滚动。没有已连接的手机 AVD，使用临时显示覆盖验证 360×640 dp 手机游戏／复盘与旋转锁定，并补查约 411×914 dp 的正式复盘；结束后恢复显示尺寸、密度和系统旋转设置。大平板使用独立测试包保留原应用，7 英寸平板原进度保留。Android 调试构建通过；相关 4 个 Jest 套件共 138 项通过，类型与 lint 通过（5 条既有警告）。

进入游戏时先完成容器、标题栏和控制区的实际尺寸测量，再显示适配后的布局；测量期间不接受触摸或辅助功能焦点。横屏缩放容器保持挂载，避免测量后重新挂载控制区。保存、暂停或退出时，即使自动完成入口暂时隐藏，也保留它的布局空间，避免棋盘、键盘和工具栏在离开前突然变大。

### 保留范围与后续建议

本轮修复覆盖同一次应用运行中的“游戏 → 首页 → 设置 → 首页 → 继续”、模块往返，以及进程仍存活的前后台切换。**不包含杀进程或冷启动后的临时界面状态恢复**。游戏盘面、进度和设置继续走已有持久化。

若进一步要求冷启动也恢复操作现场，建议只把“当前未完成局的选中数字”等少量上下文存入用户存储，并按局校验；列表像素位置、播放状态、弹窗、进行中的请求不宜全量持久化。这和本轮导航恢复是不同的验收范围，不应混为“保存所有界面对象”。

验收包括实际应用级的设置往返、新局隔离、输入模式切换，回放重新进入后的位置和暂停状态，以及通用页面状态与滚动位置恢复检查。最终测试结果见本次交付说明。
