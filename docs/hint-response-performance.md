# 提示响应性能回归与修复

2026-09-03，首发前开发阶段。

## 原因与实测

提交 `18c78dd` 新增提示辅助信息回放。每个已接受命令的观察逻辑在界面更新前同步执行；准备和展示提示分别回放全部历史，每条历史提示又进行两次全盘 singles 扫描。

在运行中的 iPad mini（第六代）iOS 17.5 模拟器开发版本采集 Hermes CPU 轨迹，连续两次 `rebuildHintAssistance` 分别占用约 1.20、1.22 秒。最新提交 `8499053` 的快速候选合并不是主要热点。普通翻页的两次 React 渲染约 26、30 毫秒，原有动画时长为 360 毫秒。

修复后，在同一模拟器已加载的 Hermes 模块中，用原先保存的 20 次历史提示棋局副本测试，未写入存档或改变实际棋局：

| 操作 | 游戏领域计算 | 后台观察逻辑 |
| --- | ---: | ---: |
| 准备提示 | 5.96 ms | 0.71 ms |
| 展示提示 | 8.88 ms | 1.97 ms |
| 应用提示 | 6.96 ms | 1.73 ms |

五次独立反序列化后的首次辅助信息重建为 39–53 ms；二十次已缓存重建为 0.63–0.83 ms。此处是开发版本函数耗时，不包含 SQLite、原生求解、界面绘制和动画，不能作为真机 Release 端到端延迟承诺。

## 修复边界

- singles 使用行、列、宫的候选次数统计，保留原来的效果集合与顺序。
- 合法候选使用行、列、宫占用位图，保留原来对正确、冲突和无候选盘面的结果。
- 对不可变历史、操作和盘面使用弱引用缓存。历史追加或撤销时复用已有前缀；改变前缀上下文、重新反序列化时按实际输入计算。
- 同一提示的辅助效果缓存包含完整候选上下文，避免同盘面上不同历史排除互相污染。已看过的提示仍由当前观察状态维护，缓存不保存或恢复观察资格。
- 保留已提交的快速候选合法性校验与交集合并规则；撤回未提交的 `hintCandidates` 子集上界替代方案，保留并补充相关测试。
- 不改变技巧识别规则、观察时机、异步搜索与失效判定、存档格式，也不修改翻页交互和任何动画。

## 验证

`hint-assistance-performance.test.ts` 使用独立的逐格扫描、完整回放参考实现，覆盖全部 39 种技巧的展示、应用、撤销、反序列化恢复，以及长局观察请求、失效判定、候选上下文和历史前缀变化。性能回归检查通过真实行为观察器，断言连续 25 次提示后不再重算旧提示盘面，避免依赖不稳定的 CI 墙钟时间。

`solver-candidates.test.ts` 用独立逐格约束扫描比较合法候选输出，覆盖完成、空白以及 400 个有效/冲突盘面。
