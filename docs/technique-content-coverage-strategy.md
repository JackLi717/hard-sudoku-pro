# Hard Sudoku Pro：技巧覆盖、检索与定向补题策略

状态：已决策，先建立覆盖证据与检索能力，再按缺口定向补题

记录日期：2026-09-02

关联开发计划：`docs/technique-growth-development-plan.md`

## 1. 决策

技巧成长开发不以随机扩充 10,000 题为前置条件。当前题库足以开始协议、识别原型和算法评价；正式成长功能进入产品化前，必须先完成逐技巧覆盖审计，再对真实缺口定向补题。

固定实施顺序为：

```text
现有 10,000 题
  ↓
评级路径覆盖 + HSP 运行时路径覆盖
  ↓
按技巧组合检索与人工复核
  ↓
确认真实缺口
  ↓
定向生成候选题
  ↓
运行时复现、代表性试玩与去重
  ↓
合入首个公开内容基线
```

不得用随机扩容代替覆盖分析，也不得仅因某项技巧在 HoDoKu2 标准路径中稀少，就直接断定玩家无法遇到它。

## 2. 三类题目集合

### 2.1 首发游戏题库

面向正常随机游玩，优先保证整体难度分布、唯一性、逻辑可解性和体验质量。只有通过完整自动验收与人工抽检的补充题才能合入。

### 2.2 算法评价题集

面向技巧成长识别算法，包含每项技巧的正例、反例、动作序列、提示污染、撤销、歧义和快速连续操作。评价单位主要是“中间盘面 + 玩家动作”，不要求每个 fixture 都成为正式游戏题目。

### 2.3 技巧代表题集

面向未来的专项推荐或练习。题目不仅要包含某技巧，还应让该技巧在正常解题路径中可达、具有代表性，并尽量减少更简单替代路径造成的干扰。首轮技巧成长可以使用其覆盖证据，但不自动上线专项训练入口。

三个集合可以引用同一道题，但必须分别验收，不能用一个“包含技巧”标签代替各自质量标准。

## 3. 两种关联语义

### 3.1 评级路径关联

`puzzle_technique_usage` 保存 HoDoKu2 标准评级路径中的技巧和使用次数。它用于：

- 难度评级审计。
- 初步寻找包含任意或全部指定技巧的候选题。
- 统计标准路径的技巧覆盖缺口。

该表增加反向索引：

```sql
CREATE INDEX puzzle_technique_usage_lookup
  ON puzzle_technique_usage(technique_code, rating_version, puzzle_id);
```

索引已经进入当前首版 schema 源文件。已提交的 `content-v4` 继续作为不可变审计产物，不原地修改校验值；组合查询在该 10,000 题数据库上仍可工作，索引会随下一次获批的首发内容整合构建进入实际安装包，不为这一项结构优化单独制造 `content-v5`。

### 3.2 HSP 运行时标准路径关联

构建期使用实际 C++ `HintEngine.nextStep()` 从题面回放至完成，为每道题导出：

```text
puzzle_id, technique_code, use_count
```

这份数据更接近技巧成长算法实际看到的机会，用于决定补题优先级和选择算法测试样本。它仍然只是 HSP 引擎选择的标准路径，不保证真实玩家一定按相同顺序遇到技巧。

### 3.3 玩家可达与代表性

最终认定“适合某技巧”的题目，还需要中间盘面、候选状态、结果签名和人工试玩证据。后续可以在构建审计产物中增加逐次 occurrence；在正式需要从中间盘面开始专项练习前，不把完整轨迹装入 App。

## 4. 检索能力

运行时内容仓储提供 `findPuzzlesByRatingTechniques()`，支持：

- `match: 'all'`：同时包含全部指定技巧。
- `match: 'any'`：包含任意指定技巧。
- 难度过滤。
- 每项技巧的最少使用次数。
- 返回数量限制和稳定排序。

离线构建人员可以使用：

```bash
python3 tools/puzzle-generator/scripts/query_puzzles_by_technique.py \
  --all xWing,xyWing \
  --difficulty 4 \
  --limit 20
```

该查询当前基于评级路径语义。需要按运行时路径查询时，使用生成的运行时 CSV 或后续专用审计仓储，不混淆两类数据。

## 5. 覆盖报告

执行：

```bash
npm run content:coverage
```

命令会：

1. 编译当前 C++ 提示引擎。
2. 回放 10,000 道生产题目。
3. 导出逐题运行时技巧使用 CSV。
4. 合并 `content.sqlite` 的评级路径数据。
5. 生成 JSON 与 Markdown 覆盖报告。

报告位置：

- `tools/puzzle-generator/reports/content-v4-runtime-technique-usage.csv`
- `tools/puzzle-generator/reports/content-v4-technique-coverage.json`
- `tools/puzzle-generator/reports/content-v4-technique-coverage.md`

当前每项 50 道题是首发质量评估下限，不是算法可靠性的充分条件。算法仍按 `docs/technique-growth-development-plan.md` 的正反例、污染隔离和人工复核门槛验收。

### 5.1 当前 10,000 题结论

2026-09-02 全量报告得到：

- HoDoKu2 评级路径覆盖 35/39 项技巧，8 项低于每项 50 题的评估下限。
- HSP 标准 `nextStep()` 路径覆盖 31/39 项技巧，12 项低于下限。
- `forcingNet` 在评级路径中为 0，运行时路径却出现在 4,168 道题，说明两套路径不能互相替代。
- `xyChain` 有 2,927 道评级路径题、`aic` 有 1,961 道、`groupedAic` 有 122 道，但都没有成为运行时标准路径的选中步骤。
- `lockedPair`、`lockedTriple`、`nakedQuad`、`remotePair`、`sashimiXWing`、`xChain`、`xyChain`、`aic`、`groupedAic` 优先判定为机会选择算法复核对象，不进入补题队列。
- `jellyfish`、`complexColoring`、`forcingChain` 需要先进行多机会扫描和代表性复核，才能判断是否存在真实内容缺口。

因此当前执行结论是：**暂不生成补充题目**。下一步先在 TG-1/TG-2 评价多机会识别；只有报告证明现有题库中缺少足够可达、具有代表性的状态，才按第 6 节启动定向补题。这不是推迟既定策略，而是“先证据、后补题”在第一次全量数据上的实际决策。

2026-09-02 多机会算法基线进一步验证了该顺序：39项 Hint Lab 目标 identity 全部被 `allDirect` 召回，但16个去重夹具盘面中存在大量跨技巧共享原子 effect，且默认枚举边界会省略 `forcingNet` 与 `xyChain` 的12个 identity。当前证据首先指向归因歧义和枚举策略，而不是可以直接用随机补题解决的内容缺口。逐技巧结果见 `tools/puzzle-generator/reports/opportunity-evaluation.md`。

## 6. 定向补题规则

只有覆盖报告和人工复核确认缺口后，才启动补题：

1. 按缺口技巧提高对应 HoDoKu2 候选来源的过采样量，不改变 39 项技巧目录。
2. 使用统一评级器筛选包含目标技巧的候选，优先选择能够同时补足多个缺口的题目。
3. 与现有 10,000 题执行题面、校验值和等价变换去重。
4. 使用 HSP 引擎验证目标技巧在运行时状态中可复现。
5. 人工确认技巧不是只在牵强路径中偶然出现，且题目适合普通游玩或明确的代表题用途。
6. 重新计算整体等级分布、包体、查询性能和39项覆盖矩阵。

补题在可丢弃的 staging 数据集中迭代，不为每批候选增加产品内容版本。所有批准题目一次性合入首个公开内容基线；只有形成新的不可变发行内容时才建立新的兼容身份。

## 7. 与技巧成长阶段的关系

- TG-0：冻结两种覆盖语义、检索协议和算法真值规则。
- TG-1：从现有题库提取正例、反例和中间状态，不等待补题完成。
- TG-2：按39项技巧评价识别算法；覆盖不足和识别不可靠分别报告。
- TG-3/TG-4：影子运行验证真实玩家路径中的机会分布。
- TG-4 通过前：可以生成和评审补充候选，但不因内容投入倒逼算法上线。
- 首个发行候选：技巧覆盖、代表性、算法可靠性和整体题库质量同时签收。

核心原则是：题库补充解决“有没有足够机会”，识别算法解决“能不能正确理解玩家行为”。两者互相提供样本，但不能互相替代验收。
