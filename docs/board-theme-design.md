# 棋盘与讲解主题规范

## 设计目标

盘面讲解应像在同一张棋盘上逐步揭示答案。不同技巧共用稳定的颜色和标记含义，玩家无需在每次讲解时重新学习视觉规则。

当前选用「暖纸」主题：暖白底、蓝色关注、绿色确定、红色删除、灰色退后。复杂推理使用紫色假设；染色链在格内用圆方形状、在棋盘外用带字母的图例。大片区域保持低饱和度，醒目的颜色集中在真正需要关注的候选和结果上。

## 主题与明暗模式

主题是整套视觉语言。首个公开版本固定使用浅色外观；代码中保留的暗色配色与系统外观解析仅供后续开发，不进入首发界面。

结构为：应用主题 → 明暗外观 → 公共配色与棋盘主题 → 棋盘基础样式与讲解标记。讲解主题属于棋盘主题，不独立选择。切换主题时，公共界面、棋盘及讲解一起变化；切换明暗模式时，语义和形状保持一致。

目前只有「暖纸」一个主题，不增加主题商店或外观设置。未来新增暗色外观时，需完成棋盘、候选、讲解及复盘的整套视觉验收，再接入用户选择。

染色提示固定采用「四种组色 × 两种组内形状」。第 1–4 组按上述顺序取色；每组的 A 状态是内缩的圆形浅底，B 状态是同样大小的内缩方形浅底。两种底形位于数字和候选数下方，不在格内放 A/B 字母，也不遮挡原有数字。A/B 是同一链组的交替可能性，均不预先代表真或假。棋盘外图例写明组号与 A/B，且使用与棋盘相同的颜色和形状；无障碍标签读出所在组及状态。冲突、删除、假设和真实结果继续保留各自独立的标记，不改变链组颜色或 A/B 形状。

当前产品最多为前四个链组提供独立颜色；超过四组时沿用四组循环配色，不为此新增颜色。首发仅使用浅色外观；暗色数值保留相同的组别映射，待暗色外观开放前再做真机视觉验收。

普通笔记使用中性色；蓝色保留给当前关注候选。当前已填入的玩家数字延续主题绿色。普通棋盘的同行、同列、同宫及同数辅助高亮继承棋盘配色，不据此宣称推理成立。

备注模式中的「备注数字辅助」默认开启，可在棋盘高亮设置中独立关闭。它突出当前选中数字的备注，并为行、列或宫中仅出现一次的备注数字添加细描边；数字已填入的区域不提示唯一备注。描边使用关注徽标的对比色，不使用绿色、勾号或整格答案标记。统计仅依据当前显示的手动／快速备注，不调用解题器，唯一备注不代表确定答案；设置说明与无障碍标签保持这一含义。玩家仍按原有方式落子。非备注模式的普通同数高亮与提示讲解维持各自原有语义。

「轻点填入」位于输入方式下方，默认开启，可即时关闭；仅在专家（Level 4）和极限（Level 5）难度生效。Level 1–3 始终保留普通选格操作，不显示补全高亮。生效时，点击行、列或宫中的最后一个空格，或当前显示的手工／快速备注只剩一个合法候选数的格子，即填入对应数字；关闭后这些格子恢复普通选格操作，也不显示补全高亮。末格保留原有结果底色；单备注格只用浅蓝关注底色，不宣称备注一定正确。实际落子时按当前盘面和备注重新验证，保存为可撤销、可复盘的填数操作。这是即时生效的输入偏好，不是新游戏规则。

## 九宫交错底色

「九宫交错底色」默认关闭，用户可在棋盘高亮设置中开启并保存。按从左到右、从上到下编号，第 2、4、6、8 宫使用 `alternateBoxSurface`，第 1、3、5、7、9 宫使用原底色。仅使用两档颜色，横向和纵向相邻宫明暗交替，不按单行或单列分色。保留现有单元格线与宫界线。

两档底色只提供结构，优先级低于同行列宫、同数、错误、轻点填入和讲解区域。亮色使用略深的纸色，暗色使用略亮的中性色以维持数字可读性。应用根部将设置解析进当前 `boardTheme`；关闭时两档颜色相同。游戏、讲解、回放和缩略棋盘使用同一 `boardCellSurface` 规则，不记录历史外观。

## 鱼类结构与背景解析

统一主题意味着同一语义始终使用同一表达，不意味着所有结构使用同一种背景。具有基线／覆盖线结构的鱼（X-Wing、剑鱼、水母、鳍鱼及退化鳍鱼）使用明确的 `fishBase` / `fishCover` 区域角色；不根据技巧名称在棋盘组件内猜测配色。

| 鱼类角色 | 亮色：图例色 / 底色 | 暗色：图例色 / 底色 | 辅助识别 |
| --- | --- | --- | --- |
| 基线 | `#2563D6` / `#E7EEFC` | `#8CB4FF` / `#253B5C` | 蓝色图例列出基线行／列 |
| 覆盖线 | `#966313` / `#FAEDD6` | `#E2B66A` / `#433721` | 琥珀色图例列出覆盖线行／列 |

交叉格保留基线底色。基线、覆盖线均不绘制额外边框，使用区域底色及文字图例区分，保持盘面简洁。覆盖色不表示“已确定”、假设或删除；候选仍用蓝色，删除仍用红色。临时冲突优先显示错误底色，确定填入优先显示绿色。鱼的行／列朝向不会改变角色含义。

所有讲解共用 `src/ui/themes/hint-background.ts` 解析背景：冲突 → 明确结果／事实 → 鱼类结构 → 普通观察 → 棋盘底色。普通候选与单数字图解先合并区域语义，再进入同一个解析器；显式鱼类角色不会被一般的关注范围覆盖。

`focusCells` 和 `spotlightCells` 只表达注意范围；不能推导为 `established`。已识别的候选组合或链结构仍属观察证据，不等于格子已有确定填入值。缺省和空的 `cellMarks` 不改变基础语义；只有显式的事实标记或实际填入结果可以使用确定色。技巧不再通过传空标记绕开隐式背景回退。

## 标记规则

1. 区域底色提供范围，候选标记说明本步关注对象，删除线说明动作，选中内框位于单元格标记上方。网格保持结构稳定。
2. 普通候选视图和单数字图解使用同一套蓝色、红色及删除线，不因技巧切换为另一种颜色语言。
3. 斜纹表示该位置起初就没有目标候选；红色删除线表示推理排除了候选。早先步骤的删除降低强调程度。
4. 假设及其条件推导始终带 ? 和虚框；只有实际结论才使用确定状态。冲突使用错误样式。
5. 推理关系线共享关注色；强关系用实线，弱关系用虚线。活动程度可以改变强调程度，不能改变关系含义。
6. 颜色之外保留删除线、✓、?、格内 A/B 圆方形状、棋盘外图例字母及无障碍语义。主题不得修改技巧成立条件、候选快照和应用结果。

## 实现边界与修改入口

- `src/ui/themes/warm-paper.ts`：当前主题的身份、两种外观、公共配色、棋盘及讲解配色、标记参数。改颜色、删除线角度、圆角和强调程度从这里开始。
- `src/ui/themes/app-theme.ts`：应用主题契约；主题身份与两种外观分开定义。
- `src/ui/themes/board-theme.ts`：棋盘主题的类型契约，不含推理规则。
- `src/ui/themes/hint-background.ts`：唯一的讲解背景优先级解析器，普通盘面与图解共同使用。
- `src/ui/themes/sudoku-board-styles.ts`：主题标记到 React Native 样式的映射，以及棋盘字体和布局样式。更换颜色无需修改这里；增加一种全新的形状可能需要改这里。
- `src/ui/theme.tsx`：解析系统明暗偏好，向界面提供已选主题；不存放具体色值。`ThemeProvider` 的 `theme` 与 `preference` 是两个独立输入。
- `src/ui/components/SudokuBoard.tsx`：根据棋盘状态和语义标记决定显示对象，计算坐标并处理交互；只引用主题颜色或样式，不写具体色值。
- `src/domain/hints/`：决定观察范围、候选、假设和结论，不引用 UI 主题。

换主题不改解题程序；新增视觉形状可以改样式适配；新增推理含义才需要扩展语义契约。这个边界比单纯把所有颜色搬到一个文件更重要。

## 全部盘面统一主题（硬约束）

游戏、历史回放、实验提示、会话复盘及棋盘缩略图，一律读取应用根部提供的首发浅色主题。页面不得独立选择主题，或为某个历史记录恢复旧主题。历史数据只描述盘面与操作；外观在展示时从全局主题解析。

应用根部负责选择主题与明暗模式。各展示页面通过 `useAppTheme()` 继承；完整棋盘与缩略图均使用其中的 `boardTheme`。精简展示可以省略候选或交互，但不能自行换色。缩略图的焦点也使用选中内框，不将关注位置画成已确定结果。

实验提示的目录、讲解卡片和弹层同样跟随公共主题。恢复 `fd7136a` 教学表现时，保留其他现有页面对静态 `palette` 的导入兼容；实验和所有棋盘使用 `useAppTheme()`。新主题仍在应用根部统一接入。

## 验证

棋盘组件测试覆盖明暗外观、选中内框、候选标记、删除及图解状态。额外验证在同一盘面上替换主题后，外观更新而语义标记、交互和游戏状态保持不变。Hint Lab 测试继续验证技巧目录及提示行为。真机视觉验收需检查小屏候选可读性、明暗对比、遮罩和线条表现。

染色手工验收在 Hint Lab 中分别查看简单染色、多重染色、复杂染色和远程数对的观察、推理、冲突及结论页：同一组的 A/B 必须同色且分别为圆／方，最多四组依次使用蓝、琥珀、紫、青；图例与格内一致。候选数、删除线、假设标记和目标边框须保持可见，不能被形状遮挡或被组色误认为结果。前后翻页不能残留上一页的染色或冲突标记；讲解文案不能把 A/B 说成两种颜色。先在小屏模拟器检查，再由用户在实际设备上确认颜色辨识与阅读舒适度。暗色外观尚未开放，开放前另行验收。

## 对局与回放的选中标记

正常对局中，数字优先隐藏当前格的蓝色选中内框；选格优先保留蓝色内框，明确下一次数字输入的目标。两种模式在开启相关区域高亮时，当前格均与同行、列、宫使用相同浅底色，不留下原底色的空洞。保留输入目标、无障碍选中状态与回放焦点记录。提示讲解和回放继续显示选中内框，用于指示当前观察或操作位置。


## 唯一候选数的简洁讲解

实验室、游戏内提示和回放共用同一讲解。观察页同时浅亮目标格的行、列、宫，以同一主题色显示，不叠加深浅；目标格保留关注边框。每个被排除的数字强调一个真实已填位置，重复数字不重复计数。正文只说「同行、同列和同宫已出现其他数字，只剩一个候选数」，不罗列坐标和等式。下一页才展示填入结果。

讲解只保留简短正文与棋盘高亮，不显示「排除已有数字」标签或额外的数字卡片。不划掉棋盘已填数字，不补写或修改真实备注。无障碍说明另行读出排除和剩余数字。

如果同行、同列和同宫的已填数字不足以解释唯一性，观察页只说明排除已有数字，再用一页简短说明此前已验证的排除。不能把此前的逻辑排除伪造成已填数字冲突。讲解不改变求解结果、候选快照或用户进度。

满宫唯一数（含满行、满列）的观察与结论页保持整个区域清晰，遮罩只淡化区域外的格子。区域使用当前主题的观察底色，已填证据使用关注色；结论目标使用结果色，不能让遮罩覆盖区域证据而使主题色发灰。

唯一隐形数的所有分镜保持所检查的整行、列或宫清晰；阻挡分镜同时保留区域外的已填证据，不能只亮结论格而遮住阻挡来源。区域与证据继续使用共享主题的观察色。

## 锁定数对的三页讲解

lockedPair 单独校验两格均只有相同两个候选，且同时属于同一宫和同一行／列。第一页只突出两格，说明它们必然各占一个数字；第二页先浅亮行／列，再浅亮宫，交叉区域只显示一次观察色；第三页保留两个区域和数对证据，只在实际删除候选上标红并画删除线。正文不使用「候选并集」、逐格坐标说明或预设数字排列。

区域依次出现使用共享棋盘的 `regionRevealOrder` 和场景过渡，至少 900 毫秒；关闭提示动画或系统启用减少动态效果时直接显示完整区域，前后翻页会清理该过渡。所有颜色仍来自当前 `boardTheme`。

实验室锁定数对从真实回放筛选，要求同时有宫外同行／列、行／列外同宫的删除目标。通过 `npm run hint:lab:fixtures -- --technique lockedPair` 更新该技巧例题，保留其他技巧当前的例题和变体，不手工编辑生成数据。结论文案只列本步实际删除的数字。

锁定三数组与锁定数对共用三页分镜及区域过渡：先观察三个格，再说明同一行／列与同一宫的占位，最后标出实际删除候选。三格的完整候选合起来必须恰好是三个数字，每格允许有其中两个或三个候选，不要求候选完全相同，也不补画缺失候选。讲解层明确校验同宫且同行／列，防止把普通三数组误讲成锁定三数组。保留现有包含不等候选集合与双区域排除的实验室例题。

显性数对采用「观察数对 → 理解占位 → 展示排除」三页讲解。第一页面只强调两个格的真实候选；第二页显示同时包含两格及本步所有删除目标的共同区域，说明数字不能重复；最后一页才标出实际删除的候选。保留完整区域的可见范围，不扩展到两格各自的其他行、列、宫。两格必须恰好具有相同两个候选，不把「都包含这两个数字」误当作数对。沿用当前列内数对例题，真实候选及游戏操作不变。

隐性数对采用「观察位置 → 理解占位 → 展示排除」三页讲解。所有分镜保持证据所在的整行、列或宫清晰；第一页面在同一分镜内依次强调两个数字的全部出现位置，原有候选以中性色保留在强调层下。第二页说明两个数字各占一格，第三页只给数对格内的实际删除候选画删除线。不能预先隐藏格内额外候选，也不能删除区域中其他格的同数候选。校验必须覆盖两个数字在整个区域的全部位置。

候选强调顺序通过共享棋盘的 `candidateRevealOrder` 使用当前主题、动画设置和减少动态效果偏好。例题 R3C1、R3C9 中的8只在结论页标记删除，R3C8中的8始终保留；回退会清理删除标记，不修改真实候选或落子。

显性三数组使用三页讲解：先突出三格的完整真实候选，再显示支持本步排除的共同区域，最后删除区域内其他格的实际目标候选。每格可有其中两个或三个候选，不补齐缺失数字；只显示一个足以支持全部删除的区域，与锁定三数组的双区域解释区分。

隐性三数组使用三页讲解：完整区域内依次强调三个数字的实际出现位置，说明三格必须各容纳一个数字，最后只删除三格内其他候选。允许某格缺少组内某个数字，不补画候选；每个数字约 450 毫秒依次出现，关闭动画时直接显示全部强调。实验室优先选择不含隐性唯一数或更小隐性数组的真实回放例题，通过生成器更新，真实求解器仍保留合法的可简化子集。

显性四数组使用三页讲解：先整体观察四格合起来的四种候选，再用共同区域内数字不重复说明四格占位，最后标出区域其他格中的实际删除候选。允许各格只有其中两个或三个候选；不展示排列枚举，不补画缺失候选，结论文案仅列本步确实删除的数字。

隐性四数组采用三页讲解：整区域内依次强调四个数字的真实出现位置，说明四格被这四个数字占用，最后只删除四格内其他候选。观察动画按四个数字分配约 1800 毫秒，避免一次闪过；保持候选缺席和其他数字可见。生成器选择不含隐性唯一数、隐性数对或隐性三数组的例题，并仅更新该技巧的当前实验室例题。

## 剑鱼与带鳍鱼的讲解

剑鱼统一使用单数字图示，四页依次说明基础线各需一个数字、候选仅落在三条覆盖线、覆盖线各被占用、排除实际目标。不补齐缺失的交点候选。鳍 X-Wing 用「观察 → 逐个假设鳍成立 → 所有鳍不成立 → 结论」讲解：单鳍四页、双鳍五页。每个鳍各占一页，标题按鳍编号，棋盘只显示该鳍的紫色假设数字，不顺带删除其他鳍。约 550 毫秒后开始显示目标删除线，整个过渡至少 1000 毫秒；关闭动画或减少动态效果时直接显示完整分镜。切换分支清理上一个假设和删除标记。分支中的删除都是解释标记，结论才标记实际删除。

刺身 X-Wing 保留真实缺角，六页展示鱼鳍、主线的两个位置、直接排除分支、另一分支排除鱼身候选、至少一个鳍必须成立、共同结论。分支切换清理上一分支的假设和删除标记。三类技巧的各页均保留完整基础线、覆盖线，以及带鳍技巧的整个鳍宫，避免遮罩隐藏证据或翻页跳动。

鱼鳍使用 `boardTheme.colors.fishFin` / `fishFinSoft`（明暗主题分别配置的青色），仅绘制候选的描边、浅底和数字，并提供文字图例及无障碍标签；不增加整宫底色。假设仍使用紫色，删除仍使用红色加删除线。X-Wing、Jellyfish 与涡轮鱼的原有分镜不变。

保留现有剑鱼、鳍 X-Wing、刺身 X-Wing 主例及变体。回归检查独立枚举基础线的合法占位，验证每种占位都排除本步目标；同时覆盖单鳍、多鳍、行列方向、缺角和多个删除目标。无需重生成已合适的例题。
