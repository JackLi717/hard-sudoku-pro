# 自动化归因验收与持续体验分工

## 当前决定（2026-09-03）

产品负责人确认：程序承担可重复的正确性验收，用户负责持续的真实操作体验。不再要求用户学会复杂技巧、填写独立盲审工作表或反复完成高难度整局，作为工程推进的前置任务。

这项决定调整验收方式，不改变[唯一权威归因协议](player-technique-attribution-policy.md)，也不把自动化结果冒充真人技巧意图或人力成本真值。本文取代旧计划中“必须先由玩家完成独立盲审才能推进”的流程要求；涉及归因准入仍以权威协议为准。

## 一条命令

```sh
npm run behavior:acceptance
```

需要 Node 22.13+、项目依赖和 C++20 编译器。命令在新的临时目录生成 `acceptance.json`、`acceptance.md`、逐阶段日志、Jest 明细、技巧覆盖明细及对抗样本，不读取模拟器，不修改用户数据库，不覆盖仓库历史验收产物。可用 `-- --output-root <目录>` 指定产物父目录；每次仍创建独立子目录，失败时保留证据。

CI 在常规质量检查之后运行同一命令，无论成功失败都上传报告。

## 自动检查范围

1. 独立求解器自检：唯一解、冲突、多解、搜索预算耗尽；必须能拒绝故意注入的错误落数和删除答案。
2. 全部 Jest 游戏/行为回归与 TypeScript 检查：包括重复提示、候选恢复、撤销、过期返回、实际提示后落数和性能测试。
3. 从当前源码编译 C++ 回放器，避免使用旧二进制验收新代码。
4. 39 项技巧固定局面：独立搜索唯一解，不以保存的答案指导搜索，再核对候选保留答案及 placement/elimination 的结果正确性。完整、部分、逆序操作共 117 次 native 请求检查候选召回、机会枚举完整性及成本排序。
5. 6 个真实候选恢复/直接落数回归，以及双线风筝提示后落数和重新 attach 的 native 回归。
   另有真实 R1C6 删除 7、稍后 R1C1=9 的异步分段回归：用当前 native 解释器和可控时钟，覆盖 UI 切换、慢响应、截止结算、晚到回调及失败清理。
6. 20 个固定种子、每个 100 个策略步骤，经真实协调器及 SQLite 游戏持久化。跨种子轮转抽取至多 120 个最终诊断，再做 native 回放与污染准入审计，避免只审核第一个种子。
7. `opportunity-deduplication`：跨片段结果归并、同名不同机会、歧义不传递合并、重建观察器、提示/撤销失效、一步 placement 闭包和真实 C++ 数对分次删除。
8. `durable-hint-exposure`：关闭提示、应用后撤销、应用后重启的 SQLite 复开和独立进程读取；曝光不改变未应用提示的候选，保存失败与提示状态/扣费一起回滚，历史缺失不提升为独立归因。

没有结果、超时、独立求解不确定或阶段退出失败，都不能算通过。运行会返回非零状态并保留日志。

随机对抗中的 `no_match` 不自动算误识别：模拟器会制造无技巧解释或撤回的动作。只有带明确结果约束的固定正反例才能用来判定对应正确性，不能把随机样本的匹配比例当成准确率。

## 两种不同结论

- `engineeringPassed`：上述当前工程检查是否全部通过。它是有明确覆盖范围的自动化签收，不是“算法对所有行为百分之百正确”。
- `growthReleaseReady`：能否进入正式成长计分。当前保持 `false`。两个原延期能力现在由上述独立阶段验收，在 `completedCapabilities` 中按实际阶段状态报告，不能只改布尔值放行；成长评分规则及 `humanCost` 校准仍不由这些工程检查签收。

`--require-growth-ready` 用于下游正式成长准入；当前应返回非零，即使工程检查全绿。后续必须实现对应能力、加入能自动失败的验收，再逐项关闭门槛，不能仅修改布尔值放行。

## 证据边界与下一步

独立求解器证明的是数独结果成立，不证明玩家用了哪一种技巧。39 个种子来自既有引擎夹具，因此技巧名称召回属于回归证据，不是独立标签真值。复杂技巧的真人意图准确率、发现时间和 `humanCost` 校准不从这些测试推算；没有证据的指标保持未校准，而不是要求用户继续充当高阶玩家。

2026-09-03 后续决定：单局回顾原型可用后，恢复并实现两个延期能力，再继续测试算法与回顾。归并语义及曝光准入仅引用[权威协议](player-technique-attribution-policy.md)。回顾保留原始片段并显示共享机会编号，歧义和历史证据缺失保持可见。复杂技巧的独立推理标签证据与变换反例仍是后续评价方向。体验检查继续贯穿开发，用户发现的问题转为固定回归样本；不再以“再玩几整局”作为默认验收方案。正式成长页面、动画和用户档案本轮不开发。
