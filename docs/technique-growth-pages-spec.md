# 技巧成长首版：功能与页面详细设计

2026-09-04视觉改版补充：已按用户批准仅重做「我的技巧」与「技巧详情」，先供体验确认；当前页面顺序与验收见[收藏册改版记录](technique-growth-visual-refresh.md)。本局足迹、完成页及原统计口径保持本轮改版前行为。

状态：已于2026-09-04获用户批准并实施首版事实反馈。实现与设备验收结果见[首版验收记录](technique-growth-acceptance.md)。本批准不开放掌握评分。

## 1. 首版范围

新增3个独立页面：我的技巧、技巧详情、本局技巧足迹。扩展现有首页、完成页和设置页；增加1个非模态轻反馈组件。复用历史复盘及演练，不新增底部导航，不另建教学播放器。

包含学习接触、可归因应用、事实趋势、关注技巧、静态里程碑和记录深链。暂不包含掌握百分比、速度排名、发现时间曲线、自动降级、专门练习出题、技巧确认表单、成长动画和云同步。三档复盘预算不能改变成长统计权重。

## 2. 导航与返回

| 起点 | 操作 | 目标 |
| --- | --- | --- |
| 首页 | 点“我的技巧”卡 | 技巧总览 |
| 总览 | 点技巧行 | 技巧详情 |
| 完成页 | 点“查看技巧足迹” | 本局技巧足迹 |
| 历史对局 | 次级入口“技巧足迹” | 该局足迹，不改变现有复盘主入口 |
| 技巧详情/本局足迹 | 点“查看这一步/过程” | 原对局复盘的对应位置 |
| 技巧详情 | 点“关注” | 切换关注状态，留在原页 |

深链保存session及稳定move/event/process引用，不能只存可能变化的帧号。过程定位到起始动作并关联收尾。返回恢复来源页、筛选及滚动位置；无法定位时说明原因并允许打开该局，不默默跳到第0步。原复盘与演练的返回逻辑保留。

游戏进行中不新增能立即查看后台推理的成长面板，避免成为额外提示。页面浏览不改变游戏、计时、提示额度或原事件历史。

## 3. P0：首页成长卡

放在现有新游戏/继续游戏主操作之后，不把主操作挤出首屏。整卡点击进入总览，无多个细小按钮。

- 标题固定“我的技巧”。
- 首次使用：“从第一局开始，记录你的学习与应用”。不显示0分或掌握0/39。
- 有学习事实：“最近接触：隐性对子 · 来自提示”。
- 有合格应用：“最近一局新增2个应用过程”。
- 整理中：“学习记录已保存，应用记录待整理”。
- 读取失败：保留上次摘要及更新时间，卡内可重试；不阻止开始游戏。

新状态只提醒一次，旧内容不反复加“新”。

## 4. P1：我的技巧

从上到下布局：

1. 顶栏：返回、“我的技巧”、统计说明按钮。
2. 近期摘要：默认最近10局，分别显示“接触过的技巧X种”和“有应用记录的技巧Y种”；两者可以重叠，不能相加。
3. 分段选择：“最近记录 / 我关注的 / 全部技巧”。默认最近记录，不是能力分级。
4. 列表：技巧名、描述性状态、来源、记录数。整行进入详情。
5. 底部说明：“记录反映学习与可解释的应用，不等于掌握评定。”

示例行：“宫内锁定 · 应用积累中 / 3个过程·2道题 / 最近记录：今天”。仅有提示则显示“隐性对子 · 开始接触 / 提示学习·涉及2局”，不突出独立应用0次。

最近记录按真实活动时间倒序，同时间按现有技巧目录；全部39项沿用目录顺序，不增加排名。关注由玩家主动设置，不自动推断弱项。

初次空态：“你的技巧足迹会从第一局开始”，按钮“开始游戏”、次级“查看全部技巧”。全部技巧始终可进入详情，无记录写“尚无记录”，不写“不会”。关注空态提示去详情点关注。

首次加载占位，不为开页面重新跑全部对局。新统计完成后整体替换，避免每一行来回跳动。分析覆盖和日期范围可通过统计说明查看。

## 5. P2：技巧详情

### 页面结构

1. 顶栏：返回、技巧名、关注/已关注。
2. 一句话状态：“已在2道不同题目中记录到相关应用”；下方复用已有技巧简介，不重做教学内容。
3. 三张事实卡：“学习接触X局”“应用过程Y个”“应用涉及Z道题”，明确单位不同，不合成能力进度环。
4. 近期记录：按源对局列日期、难度和分类，首批最多5局，“查看更多”分页。
5. 近期变化：两个窗口的事实比较，样本不足不画空曲线。
6. 学习里程碑：静态时间线，各项可查看依据。
7. 相关记录筛选：“全部 / 学习 / 应用 / 可能解释”，每条可跳复盘。

记录示例：“9月4日 11:13 · Level 4 / 宫内锁定应用记录 / 连续排除后填数 · 查看过程”。来源分别写“当时查看提示”“提示辅助”“完成演练”“程序可能解释”，不靠颜色区分。

相关单数收尾可在单数详情出现，但标“相关收尾”，不再增加独立应用数。备选解释链接同一过程，不各加一次。

“为什么这样记录”弹层给出来源、是否受助、系统默认解释或仅可能解释、关联动作和证据状态，使用自然语言而不是原始诊断字段。

### 趋势与边界

- 仅有提示：显示学习经历，不展示独立应用趋势。
- 仅有可能解释：显示“有可回看的解释”，不自动升级为应用积累。
- 不足20局completed会话：显示实际记录列表，比较区提示“继续积累后显示前后记录对比”。
- 两个窗口均有10局但证据缺失：显示覆盖/待处理数量，不给增长箭头或进步结论。
- 完整窗口某技巧为0：“该窗口未记录到应用”，不说能力下降。
- 重算期间保留旧统计并标“正在更新”；重算不生成新学习庆祝。

首版使用按局列表和比较卡，不画平滑能力曲线。以后图表仍复用同一统计口径。不得把画出一条上升线当成证明进步。

## 6. P3：本局技巧足迹

顶栏返回与标题，下方日期、难度、完成/失败/结束状态。显示“事实已保存 / 分析待完成 / 整理完成（仍可能存在未知）”。

三个分区：

- 学习接触：真实提示展示、应用提示及演练完成，按技巧合并且标来源。
- 应用记录：仅经过现有准入及完整过程验证的去重过程，每过程一行；不能直接计入复盘深搜路径。
- 值得回看：可能解释、多解释、未解释及证据不足，清楚显示不同状态。

每行技巧名称可进技巧详情，“查看过程”为主要按钮，避免嵌套整行点击造成误触。异步补充时不抢滚动位置、不自动打开演练。

零记录：“本局暂未形成技巧记录，仍可查看完整复盘”。全程提示仍有学习接触，不说“本局没有成长”。失败/弃局保留真实记录，但不参加默认completed对局的比较窗口。

## 7. P4：完成页摘要

保留成绩和下一局/选择难度/复盘操作，增加“本局技巧足迹”卡，最多3条摘要，详情完整可见。优先首次学习里程碑，再是合格应用，再是值得回看；同一事实不占两条。

例：“第一次查看隐性对子提示”“宫内锁定：新增1个应用过程”“有1步可查看另一种解释”。不足三条就少显示，不造夸奖。主操作“查看技巧足迹”，允许直接下一局。

局内已反馈的里程碑仍可作为静态事实出现，但不重复庆祝；分析晚到只更新卡片，不让离开的玩家被弹回完成页。

## 8. P5：轻反馈及设置

轻反馈使用棋盘和键盘之外的既有区域；小屏或大字时放不下则延后局后，不压缩操作区。默认每局最多1条，约3秒，静态或轻淡出，无声音/震动/强制弹窗，不抢焦点。

只反馈玩家已知的学习事实，如“已记录一次隐性对子学习”；后台判断的正确填数/删除默认不即时庆祝，防止泄露正确性。连续输入、提示面板或其他弹窗打开时延后，没有安全时机就只局后展示。读屏礼貌播报一次，重复渲染不重复读。

演练完成可在演练内显示“本次演练已记录”，不等于理解。按源过程/技巧/事实类型保存稳定回执，重启、反复回看不刷庆祝。

现有设置增加“技巧成长”分组：

| 设置 | 默认 | 效果 |
| --- | --- | --- |
| 对局中轻反馈 | 开 | 关闭只停轻反馈，不删记录 |
| 局后技巧摘要 | 开 | 关闭只隐藏完成页卡，仍可主动查看 |
| 关于成长记录 | 说明入口 | 本地保存、来源类别、统计起点说明 |

不提供尚未实现的丰富动画档；不与复盘初级/高级/专家计算档混用。展示设置不冒充数据采集开关。沿用现有全局数据管理，暂不新增“重置成长”；独立重置需先另定旧局重算和删除范围。

## 9. 指标与数据要求

页面读取统一的可重算投影，不自行判定归因。示例计数严格区分以下口径：

| 指标 | 定义 |
| --- | --- |
| 学习接触局数 | 有真实提示曝光或完成演练记录的不同源对局数；反复查看同局只计1局 |
| 应用过程数 | 归因准入且完整过程验证通过的去重过程；不是点击数 |
| 应用题目数 | 应用过程涉及的不同题目身份；重复玩同题不增加多样性 |
| 最近10局 | 最近完成的10局completed会话，按完成时间，不足则显示实际N局 |
| 之前10局 | 紧邻上一窗口的10局completed会话；不足不做前后比较 |
| 学习活动日期 | 实际提示展示或演练完成的日期；后来复盘学习不倒填到对局当日 |
| 首次记录 | 现有可核实历史中最早事实，不声称真实首次学会 |

学习轨迹按实际活动时间，应用按来源对局聚合，不混成一条趋势。趋势文案：“最近10局记录到5个应用过程，之前10局为3个”，附难度构成和分析覆盖；不能说“能力提高67%”。缺失局不能偷偷剔除再凑满10个可用样本。

状态为尚无记录、开始接触、应用积累中、多局有应用记录；仅有可能解释另行表达。无需先看提示才能进入应用积累。跨题3题/5过程的里程碑仍是待批准假设，首版事实计数不依赖其批准。

实际演练完成需要最小持久学习事件：点击完成、关联源对局/解释/技巧、真实发生时间；打开或中途退出不算完成。直接翻页到结束仍只说明完成操作，不证明理解。若现有记录缺失，在实现阶段补充此学习事实，不能猜测历史完成。独立存于学习事实层，不把理论状态写入原始游戏操作史。

投影保留来源引用、去重身份、分类、证据状态和更新时间，具体合同实现时沿用权威协议。原始事实不改写，复盘升档不自动增加应用数，撤销撤回有效应用但不抹去曾查看提示的学习事实。存储、设置和重算均离线可用。

## 10. 手机、iPad Mini与异常状态

- 手机单列；正文建议16–18逻辑单位，允许换行，动态字体不缩小以塞满一行。
- iPad Mini主内容建议最大宽度720逻辑单位；宽屏详情可分摘要/记录两栏，大字回退单列。尺寸以设备实测校准。
- 所有点击区域至少44逻辑单位；来源使用文字和图标，不只靠颜色。
- 读屏按标题、摘要、记录、操作顺序，趋势有文字等价描述；加载不抢焦点。
- 加载失败可重试，有旧内容则保留并标更新时间；不阻止正常游戏。深链缺失说明原因，不默默跳错盘面。
- 首版禁止因为数据少、长期没玩或使用提示而给红色负面状态。

## 11. 交付顺序及验收

方案批准后分三个增量：

1. 证据投影、P0/P1/P2/P3/P4静态页面、稳定深链和空态；第一局就可用。
2. 最小学习完成事件、静态里程碑、按局轨迹与窗口比较；样本不足不做能力结论。
3. P5轻反馈与设置、反馈回执及Android/iPad Mini大字/读屏验收。

必测：同过程多次删除不重复；提示派生单数不独立归因；3种解释不算3次；同题不刷多样性；升复盘预算不刷成长；退出演练不记完成；旧局回看按真实日期记接触；重算不重庆祝；比较不隐藏缺数据；记录能定位原操作；关反馈不删事实；全程提示仍有真实学习反馈。

产品评审重点：是否接受3个独立页面和3处现有入口扩展；是否接受以记录积累而非分数为首版核心；是否接受局内最多一次、局后集中总结。上述尺寸、频率、窗口和里程碑数值均为设计起点，不是已验证最优参数。
