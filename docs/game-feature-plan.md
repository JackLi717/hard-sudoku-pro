# Hard Sudoku Pro：首期功能与商业化规划

## 1. 文档目的

本文档定义 Hard Sudoku Pro 首期的页面、核心玩法、本地统计、广告、购买和辅助功能边界。参考产品截图仅用于分析成熟的数独交互方式，不复制其图标、文案、布局、品牌或视觉资产。

2026-09-03 更新：本文件第 8 节记录当前奖励与商业化决策，替换此前的全体玩家完成奖励、广告多次额度和 Premium 无限辅助方案。Premium 补给数值的专项设计见[Premium 奖励设计](premium-reward-design.md)。本次为文档决策，现有运行时代码和历史验收记录不代表新规则已实现；实施与重新验收纳入阶段 7。

产品定位是：

> 面向中国大陆以外用户的单人、离线、技巧型数独游戏，打开即可游玩，不要求注册账号。

## 2. 产品原则

- 所有题目、进度、设置和统计均保存在本地。
- 无网络时仍可开始、继续和完成任何题目。
- 广告、购买、恢复购买和隐私同意可以需要网络。
- 基础玩法与辅助额度来源分开：新用户获得一次性试用额度；免费用户之后通过主动观看激励广告补充；Premium 通过有限的游戏完成奖励补充。
- 已获得的辅助额度可以离线使用；广告兑换不绑定任何一局的开始、完成或联网状态。手动铅笔始终免费。
- 游戏中不能自动插入广告，不能打断推理和输入。
- 技巧成长反馈必须分级、非阻塞且可降低或关闭，不能为了制造成就感反复打断推理。
- 题目使用 Level 1–5，并由所需技巧决定等级。
- 不建设账号、云同步、排行榜、对战、活动、社交、经验值或金币系统。
- 首期支持英语、日语、德语和简体中文，以英语作为源文案。

## 3. 页面结构

首期只包含以下页面：

| 页面 | 主要内容 |
| --- | --- |
| 首页 | 继续游戏、新游戏、Level 1–5、技巧成长摘要、统计、设置、Premium 入口 |
| 游戏页 | 棋盘、数字输入、撤销、擦除、快速铅笔、铅笔、智能提示、暂停 |
| 完成页 | 时间、错误、提示使用、奖励、个人纪录、下一题 |
| 统计页 | 全部统计及 Level 1–5 分组统计 |
| 技巧成长 | 39 项技巧的待探索、成长、掌握、巩固状态及个人成长曲线 |
| 设置页 | 游戏偏好、语言、主题、购买、恢复购买、隐私和重置统计 |
| 玩法帮助 | 数独规则、铅笔、快速铅笔、智能提示、难度和额度说明 |
| 数独技巧 | 首期支持技巧的静态说明，并与对应的个人技巧成长详情互相跳转 |

不采用“首页、对战、探索、个人”等综合游戏平台式导航。首页应直接突出“继续”和“新游戏”。

## 4. 首页和开始流程

### 4.1 首页内容

- 有未完成题目时，主按钮显示“继续 Level N”。
- 新游戏允许选择 Level 1–5。
- 显示各等级已完成数量，不强调题库总数或完成百分比。
- 显示紧凑的技巧成长摘要和独立入口；首页仍优先突出继续与新游戏。
- 提供统计、设置和 Premium 入口。
- 显示智能提示与快速铅笔库存；免费用户可主动进入“观看广告获得 1 次”补充入口，不要求先耗尽库存或开始一局。

首期全局只允许存在一局未完成游戏。返回首页只保存当前游戏，不算放弃。如果用户在已有未完成游戏时选择新游戏，必须显示“继续游戏 / 放弃并开始新游戏 / 取消”；只有明确确认“放弃并开始新游戏”才记录一次放弃并清除旧会话。

### 4.2 普通插屏机会（与奖励独立）

普通插屏承担基础广告收入，与第 8 节的激励广告兑换分开。“每局一次广告机会”是商业目标，不能作为每局必有广告展示或收入的保证。离线、无广告填充或隐私状态不允许请求广告时仍可正常游戏。

此前“点击开始/继续后、棋盘显示前自动弹出插屏”的位置尚未通过展示政策与交互评审，不作为可直接实施的发布方案。阶段 7 应评估完成后的自然停顿等位置，最终位置由 OQ-016 单独确认，不能为保证广告数量打断用户已开始的操作。参考 [Google Play 广告政策](https://support.google.com/googleplay/android-developer/answer/9857753)及 [AdMob 插屏展示建议](https://support.google.com/admob/answer/6201350)。

规则：

- 首次安装后的第一局不显示普通插屏；用户主动兑换辅助额度的激励广告不属于自动广告豁免范围。
- Premium 用户不显示广告。
- 广告未加载、无网络或隐私状态不允许请求广告时，立即继续用户的游戏流程，不等待补播。
- 同一设备最多每 10 分钟显示一次自动插屏，作为待试玩校准的频率上限，不要求每次开始或继续都显示。
- App 从后台返回当前棋盘、来电后恢复、锁屏后恢复或崩溃恢复时不显示广告。
- 棋盘显示后，游戏进行中不自动弹出插屏广告。
- 完成记录与符合条件的 Premium 奖励先正常结算，不等待广告；完成后的普通插屏位置待单独确认。

普通插屏是否显示或被关闭，不产生辅助额度，也不改变 Premium 完成奖励资格。需要兑换额度时，使用明确告知奖励、由用户主动选择的激励广告入口。

### 4.3 题目分配

- 玩家只选择 Level 1–5，不选择具体题号。
- 在该等级尚未首次完成的题目中随机分配，同级题目全部完成前不重复。
- 完成页“下一题”优先随机进入同等级尚未完成的题目。
- 一个等级全部完成后，允许选择其他等级或随机重玩；重玩不再发放首次完成奖励。
- 正式发行目标为总计 `10,000–30,000` 道通过验收的离线题目；如果安装包体积和内容质量允许，可以继续增加。
- 当前100道题只用于验证生成、评级、验收和数据库流程，不代表正式发行数量或等级分布。
- 正式题量和 Level 1–5 分布在上线前根据评级结果、内容质量和目标用户确定。

## 5. 游戏页

### 5.1 顶部信息

只显示：

```text
返回    Level 4       12:35    暂停
```

不显示分数、连击、脑力值、排名、收藏或游戏中分享。

### 5.2 棋盘和输入

首期支持：

- 9×9 标准数独。
- 原始数字、玩家数字和错误数字使用不同且可无障碍识别的样式。
- 当前格、同行、同列、同宫和相同数字高亮。
- 冲突提示。
- 数字键盘 `1–9` 和可选的剩余数量。
- 选格优先输入；数字优先模式作为设置项。
- 撤销和擦除。
- `铅笔`：手动添加或删除候选数，不消耗额度。
- `快速铅笔`：自动为当前盘面补全候选数，消耗额度。
- 填入确定数字后自动删除同行、同列和同宫的相关备注。
- 每次操作后保存，退出、杀进程或设备重启后可以恢复。
- 暂停时隐藏棋盘内容并停止有效游戏计时。

工具栏固定为：

```text
撤销    擦除    快速铅笔    铅笔    智能提示
```

`铅笔`是候选数编辑模式，开启状态必须清晰可见；点击数字时在当前格中添加或删除当前草稿的候选数。`快速铅笔`负责生成和切换系统提供的完整候选草稿。两个按钮可以同时显示 `ON`，但职责不同：快速铅笔决定当前草稿来源，铅笔决定数字键是在编辑草稿还是填写确定数字。

### 5.3 铅笔和数字输入

- 候选数固定显示在格子内对应的九宫位置，不能随候选数量重新排列。
- 铅笔开启时，点击 `1–9` 添加候选数，再次点击同一数字将其删除。
- 只能编辑空白格；题目数字和已经填写确定数字的格子不能添加候选数。
- 关闭铅笔只把数字键切换为确定数字输入，不隐藏当前显示的草稿。
- 手工候选数不与标准答案比较，候选数错误不标红、不计入错误统计。
- 切换手工草稿与快速草稿时保持当前铅笔状态；只有首次成功生成快速草稿时自动开启铅笔。
- 默认使用选格优先。玩家格已有确定数字时，输入新数字直接替换；替换及其候选数清理作为一次操作。
- 数字优先模式下，再次点击已选择数字退出该模式，不自动选择下一个数字或格子。
- 某个数字在当前盘面已经出现9次时，数字键显示为灰色但仍可点击，以免错误盘面无法修改。
- 题目给定数字不可修改。

### 5.4 擦除与撤销

- 当前格为玩家确定数字时，擦除该数字。
- 当前格只有候选数时，擦除当前草稿在该格中的全部候选数；删除单个候选数仍通过铅笔模式再次点击对应数字完成。
- 当前格为题目给定数字时，擦除无效。
- 当前题内保留完整撤销历史，并在保存、退出和继续游戏后恢复；首期不提供重做按钮。
- 填数、替换以及由“自动删除备注”引发的两份草稿变化必须作为一个操作撤销。
- 智能提示应用可以整体撤销，但已经消耗的提示额度不退还。
- 快速草稿生成、恢复和两个模式开关不进入棋盘撤销历史，撤销候选编辑也不退还快速铅笔额度。

### 5.5 计时、暂停和中断

- 棋盘首次显示时记录一次开始并启动计时，不要求之前展示过广告。
- 正常解题和智能提示讲解期间继续计时。
- 显式暂停、进入后台、锁屏、系统中断和播放广告期间停止计时。
- 从后台返回时显示隐藏棋盘的暂停遮罩，由用户主动点击继续；不播放开始/继续插屏广告。
- 暂停界面首期只提供“继续游戏”和“放弃本局”，不提供重开本题。

## 6. 快速铅笔

游戏为每道题独立保存两份可编辑草稿：

- **手工草稿**：初始为空，由玩家使用铅笔逐项录入。
- **快速草稿**：首次开启快速铅笔时，根据当时盘面生成完整合法候选数，再由玩家使用铅笔继续删除或补回候选数。

两份草稿唯一的本质区别是来源，生成后的编辑方式完全相同。快速草稿不是持续自动重算的只读结果；系统不能在盘面未要求重新生成时自动补回玩家已经排除的候选数。

按钮组合的行为如下：

| 快速铅笔 | 铅笔 | 显示与输入行为 |
| --- | --- | --- |
| OFF | OFF | 显示手工草稿；数字键填写确定数字 |
| OFF | ON | 显示并编辑手工草稿 |
| ON | OFF | 显示快速草稿；数字键填写确定数字 |
| ON | ON | 显示并编辑快速草稿 |

首次成功生成快速草稿后，快速铅笔和铅笔都自动切换为 `ON`。关闭快速铅笔只切回手工草稿，不删除快速草稿；关闭铅笔只改变数字键输入方式，不隐藏当前草稿。两份草稿不得相互覆盖、合并或清空。

自动检查开启时，填入正确的确定数字后，应按“自动删除备注”设置清理两份草稿中同行、同列和同宫的相同候选数；错误数字虽然保留并标红，但不能触发候选数清理。自动检查关闭时，所有尚未验证的确定数字都按当前盘面约束触发候选数清理，避免通过备注变化泄露答案是否正确。填数和由此产生的候选数清理作为一个操作写入撤销历史；撤销时同时恢复。智能提示应用的有效排除也应同步到两份草稿。

智能提示另行维护持久化的 `hintCandidates`。每次准备提示时，可合并由快速铅笔已完成的候选删除，但仅限仍是当前合法候选子集、非空且保留标准解的格子；该合并只会删除候选，绝不采纳新增候选。手工草稿以及不满足这些条件的快速草稿都不能成为提示推理依据。应用候选排除后更新该状态；填入确定数字后在其基础上清理同行、同列和同宫候选数；普通删除或替换确定数字时根据新盘面重新计算；撤销时恢复操作前快照。游戏退出和继续时必须保存、恢复该状态及其盘面指纹，盘面指纹不变时继续使用，避免重复提示同一候选排除。

### 6.1 恢复或重新生成

关闭快速铅笔时，保存快速草稿以及当时只包含确定数字的盘面指纹。再次开启时：

| 当前情况 | 处理 | 消耗额度 |
| --- | --- | ---: |
| 从未生成快速草稿 | 根据当前盘面生成完整快速草稿 | `1` |
| 当前盘面指纹与保存值相同 | 恢复玩家上次编辑后的快速草稿 | `0` |
| 当前盘面指纹与保存值不同 | 经用户确认后重新生成并替换旧快速草稿 | `1` |
| 盘面改变后又完整撤销至保存状态 | 恢复原快速草稿 | `0` |
| 盘面存在标红的错误数字 | 要求先修正错误，不生成草稿 | `0` |
| 盘面冲突、无解或无法计算 | 保留旧草稿并提示检查盘面 | `0` |

“盘面变化”只包括新增、删除或修改确定数字，不包括候选数编辑、选择格子、高亮、暂停或退出。实现时比较81格确定数字的内容指纹，而不是简单判断是否发生过操作。

盘面指纹不同时，显示确认框：

> 盘面已经改变，需要重新生成快速铅笔草稿。重新生成将替换之前的快速草稿，并消耗 1 个快速铅笔额度。

操作为“取消 / 重新生成”。免费用户额度为零时，将后者替换为“观看广告获得 1 次快速铅笔”；Premium 额度为零时显示库存与完成补给说明，不展示广告入口。只有新草稿成功生成并显示后才覆盖旧草稿和扣除额度；取消、广告失败或计算失败不得改变旧草稿。

额度规则：

- 每次成功创建或重新生成快速草稿消耗 `1` 点额度。
- 恢复与相同盘面指纹关联的快速草稿、编辑候选数或继续未完成游戏不收费。
- 盘面存在冲突或无法计算时不扣额度。
- 只有在新快速草稿成功生成并显示后才写入扣减记录。

“快速铅笔使用次数”按成功创建或重新生成草稿的次数统计；免费恢复旧草稿不增加使用次数。

## 7. 智能提示

智能提示采用三个语义阶段，但不固定为三个页面。C++ 返回可变长度的 `proofSteps`；简单技巧可以只有“观察、结论”两页，Hidden Single 按实际排除组展开，高级链按链接或分支展开。一次提示始终只解决一个原子推理步骤：

1. 高亮相关区域并说明应观察的技巧。
2. 显示可以排除的候选数或能够确定的结果。
3. 用户确认后应用排除或填入结果。

交互表现建议：

- 打开提示后棋盘保持可见，但进入只读状态；背景变暗，无关格子弱化。
- 用底色和边框标识推理起点，用整行、整列或整宫的轮廓标识作用范围。
- 待排除的候选数同时使用删除线、斜杠或删除标记，不能只依赖颜色。
- 底部抽屉显示本地化的技巧名称、分步说明和分页圆点；数字、格子和区域等语义对象使用一致的强调色。
- 第一页提供“关闭、下一个”，中间页提供“上一个、下一个”，最后一页提供“上一个、应用”；结论前另提供“直接看结果”，供不需要完整教学的玩家跳转。
- 观察页不得高亮最终填数或排除目标；每一页只展示该页证明所需的区域、候选数和已填数字证据，结论页才完整显示本次原子动作。
- 关闭只退出讲解，不修改盘面；“应用”将本步的全部排除或填数作为一个原子操作执行，并允许一次撤销。
- 讲解期间计时继续，因为提示属于解题过程；只有显式暂停或进入广告时停止计时。

额度规则：

- 一个完整的结构化 `HintStep` 消耗 `1` 点提示额度。
- 第一阶段成功展示有效提示时扣除；同一提示的第二、第三阶段不重复扣除。
- 用户看完第一阶段后关闭，额度仍视为已经使用。
- 当前盘面冲突、已经完成或提示引擎无法产生有效步骤时不扣额度。
- 盘面存在标红错误时，只提示“请先修正标红数字”，不进入技巧讲解，也不扣额度。
- 玩家修改盘面后旧提示失效；重新请求新提示需要新的额度。
- 使用过智能提示的题目计为“提示辅助完成”，不计为独立完成。

整个讲解绑定打开时的盘面版本。若盘面状态发生变化，提示必须关闭并重新计算。例如“锁定候选数（宫区块排除法）”可依次展示：候选数在宫内的受限格子、受影响的行或列、可排除的候选数，最后由用户点击“应用”。这些页面由结构化提示数据生成，不在客户端硬编码坐标或整段说明。

游戏中不会自动播放广告。免费用户额度为零时，对应消耗额度的辅助动作明确显示“观看广告获得 1 次智能提示”或“观看广告获得 1 次快速铅笔”，确认后游戏暂停并播放激励广告。有库存时直接按原规则使用；同盘面免费恢复快速草稿始终优先，不因余额为零而变成广告动作。Premium 额度为零时说明通过完成题目补充，具体补给与耗尽体验按专项设计验收。

## 8. 额度、广告与完成奖励

### 8.1 初始额度与上限

新安装用户获得一次性试用额度，用于理解两项辅助功能并培养使用习惯：

| 资源 | 初始额度 | 普通用户持有上限 |
| --- | ---: | ---: |
| 智能提示 | 5 | 20 |
| 快速铅笔 | 3 | 20 |

两项初始额度为已确认数值；不能因开始新局、重置统计或恢复购买而再次发放。普通用户 20 点持有上限沿用当前开发基线，最终上限待校准。Premium 同样保留有限库存，上限在专项设计中验证。

到达上限后停止该资源的广告兑换入口，不让用户看完广告后损失承诺奖励。Premium 完成奖励按剩余容量入账，完成页显示实际增加量及“已达上限”。

### 8.2 激励广告奖励

已确认：每成功完成一条激励广告，只获得所选资源的 `1` 点额度。一次兑换只能选择一项，不同时获得两种资源，也不因本局难度、成绩或 Premium 状态而增加广告兑换量。

| 激励广告选择 | 有效奖励事件后的入账 |
| --- | ---: |
| 获得智能提示 | `+1` |
| 获得快速铅笔 | `+1` |

规则：

- 免费用户可从首页库存、完成页或额度耗尽的辅助按钮主动进入兑换；不要求完成游戏，也不要求该局在线开始或看过普通插屏。
- 每次播放前明确显示所选资源、奖励数量和广告操作；必须在广告 SDK 返回有效奖励事件后发放。点击按钮、加载完成、普通展示事件和关闭事件不能代替奖励事件。
- 没有有效奖励事件的加载失败、提前关闭或播放失败不发放、不扣资源。奖励事件已经成立后再关闭或断网，不撤回已获得额度；不能仅依据当前联网状态否决有效奖励。
- 每次广告兑换使用独立事件标识；奖励与本地额度流水同事务提交，重复回调、连续点击或恢复流程不能重复发放。
- 广告播放期间暂停计时，返回游戏后恢复。
- 不自动连续播放多个广告；每次都必须由用户主动确认。
- 库存未满时允许提前储备，也允许到账后再次主动点击兑换；不提供自动循环、离线重复播放缓存广告或无人操作持续领奖功能，不设置每日看广告任务。
- 没有可用广告时明确说明暂时无法补充，允许返回游戏；不承诺一定能连续获得任意数量的广告。
- 从库存或完成页主动兑换时，`+1` 留在钱包中供以后使用。从零余额的辅助动作进入时，先入账 `+1`，有效提示成功展示或快速草稿成功生成后再扣 `1`，正常结束余额为 `0`。
- 广告奖励与辅助消费是两个独立事件。奖励到账后取消辅助、盘面失效或计算失败，保留获得的 `1` 点，不虚扣；辅助成功消费的重试也不得重复扣除。
- 已获得额度随本地进度保存，之后离线可用。首版本地存储不保证卸载清除数据后的额度恢复。

### 8.3 游戏完成与奖励资格

免费用户完成游戏获得成绩、纪录、完成状态和符合技巧归因规则的成长反馈，不自动获得辅助额度。首次完成、完美完成、连续完成均不能成为免费额度补充通道；联网完成或看过普通插屏也不改变这条规则。

Premium 用户在有效权益下首次完成题目，获得有限的快速铅笔与智能提示补给；离线完成同样有效。奖励按正常每局的辅助消耗设计，目标是够用并保留独立推理的挑战。详细候选表、耗尽处理和校准方法以[Premium 奖励设计](premium-reward-design.md)为准，当前不把候选数值当作已冻结权益。

结算边界：

- 只有到达合法完成状态并写入完成记录后，才结算符合条件的 Premium 奖励。失败、放弃、开局或暂停不发放完成奖励。
- 奖励资格按首次完成结算时的有效 Premium 权益判断，不按开局网络状态或广告历史判断。
- 所有用户都保留题目首次完成标记；同一道题重玩不再发放完成奖励，不能通过重置统计或恢复购买重领。免费阶段已经首次完成的题目，购买 Premium 后不追补或通过重玩补领。
- 完美完成和连续完成仍作为成绩与进度记录；候选补给方案先不叠加额外额度。如未来设计额外奖励，必须计入同一局的总补给上限，不能另起通道突破预算。
- 连续首次完成可以跨等级、跨日期；智能提示辅助完成仍可推进连续完成。重玩既不推进也不中断，暂停、退出或离线不影响连续进度；失败和明确放弃中断当前连续记录。
- 快速铅笔不影响“完美完成”；使用智能提示的完成仍是有效完成，但不计为独立或完美完成。
- 成绩、首次完成标记、奖励结果及额度流水在同一事务结算；免费用户零额度奖励也必须正常保存完成结果。

完成页的“观看广告获得 1 次”是免费用户可选的独立兑换入口，不是扣住待领取的游戏完成奖励；成功兑换后与库存入口遵循同一规则。

### 8.4 Premium

首期只提供一次性非消耗型 Premium 购买，不提供订阅：

- 不请求或展示普通插屏、激励广告；额度耗尽也不能要求付费用户观看广告。
- 智能提示和快速铅笔保留库存、持有上限及每次 `1` 点消费；通过有限的游戏完成补给支持正常玩法，不提供无限辅助。
- 每局补给以快速铅笔 `1` 次、智能提示最多 `5` 次为设计起点；快速铅笔最多 `2` 次作为待验证备选，不默认每局都给满。最终按难度、真实消耗和提示依赖体验校准。
- 购买时启动补给、持有上限和库存耗尽体验需要专项设计并通过试玩；不得对外承诺尚未冻结的奖励数值。
- 可以附带额外主题，但不能锁定正常题目和统计功能。
- 购买页只显示实际价格和固定权益，不使用倒计时、虚假折扣或强制购买弹窗。
- 设置页必须提供“恢复购买”。
- iOS 和 Android 权益分别绑定对应商店账号；没有项目账号或服务端时不能跨平台共享。

未来可以另行研究订阅补给或无限辅助权益，但当前不实现订阅，也不为此增加独立钱包或版本字段。订阅必须重新评估对学习与游戏挑战的影响，并保留一次性 Premium 已经对外承诺的权益。

## 9. 错误与完成规则

默认设置：

```text
自动检查错误：开启
错误限制：关闭
```

### 9.1 错误处理

- 自动检查开启时，错误确定数字仍写入格子并标红，每次错误输入增加一次错误计数；擦除或改正后红色消失，但累计错误数不减少。
- 同一错误数字被反复输入时，每次尝试都计错。候选数不与答案比较，也不计错。
- 标红错误不参与两份草稿的自动候选数清理，也不允许快速铅笔生成或智能提示分析。
- 自动检查关闭时，不立即与标准答案比较，只显示行、列或宫内的直接重复冲突。盘面填满但答案不正确时，标出所有错误玩家数字，并按不同错误格计入错误数，继续游戏而不进入完成页。
- 开启“三次错误结束本局”时强制同时开启自动检查。第三次错误保留并标红，然后结束本次尝试、停止计时，不在游戏中提供广告继续。
- 失败页提供“重新挑战本题”和“开始新局”。重新挑战恢复初始题面，清空玩家数字、两份草稿、错误、时间和操作历史，作为新的尝试；已消耗的辅助额度不退还，之后首次完成且具有有效 Premium 权益时仍可获得该题的完成补给。“开始新局”返回难度选择。

### 9.2 完成处理

- 最后一格正确填入后自动完成，无需再次确认；计时立即停止，播放可跳过的短动画后进入完成页。
- 所有合法完成都可以刷新该等级最佳时间，不区分是否使用智能提示或快速铅笔。
- “独立完成”表示未使用智能提示；“提示辅助完成”表示至少使用一次智能提示；“完美完成”表示零错误且未使用智能提示。快速铅笔不影响这三种完成判断。
- 完成页“下一题”进入同等级随机未完成题目；该等级已经全部完成时，提供选择其他等级或随机重玩。

完成页显示：

- Level。
- 完成时间。
- 错误次数。
- 智能提示使用次数。
- 快速铅笔使用次数。
- 独立完成、提示辅助完成或完美完成状态。
- Premium 本次实际额度奖励、奖励前后余额及上限说明；免费用户不显示待领取的完成额度奖励，可提供独立的广告兑换入口。
- 是否刷新该等级最佳时间。
- 本局最有意义的一项技巧成长，以及可跳过的曲线或里程碑反馈。
- 返回首页和开始下一题。

## 10. 本地统计

统计口径固定为：

- “开始”在棋盘首次显示时记录，不依赖广告是否展示；重新挑战同一道题也算一次新的开始。
- “放弃”只由玩家明确确认产生；返回首页、暂停、退出 App 和仍在进行的游戏不算放弃。
- “失败”指启用错误限制后达到三次错误的尝试。
- 完成率为 `完成数 ÷（完成数 + 放弃数 + 失败数）`，当前未完成游戏不进入分母。
- 最佳时间和平均时间包含所有合法完成，不区分智能提示或快速铅笔使用情况；暂停、后台和广告时间不计入有效游戏时间。
- 最近完成记录保留50条。

统计页支持“全部”和 Level 1–5 筛选，显示：

- 开始、完成、放弃和失败题数。
- 完成率。
- 独立完成数。
- 完美完成数。
- 最佳时间和平均时间。
- 总游戏时间。
- 当前和最佳连续首次完成数。
- 错误总数。
- 智能提示、快速铅笔使用次数。
- 通过完成、广告分别获得的额度。
- 最近完成记录。

不显示全球 Top 百分比、排行榜或其他需要服务器数据的指标。

“重置统计”只清除用户可见的汇总和最近记录，不能清除题目首次完成标记、奖励发放标记、当前额度或 Premium 权益，避免通过重置反复领取奖励。“清除当前游戏”是独立操作。技巧成长档案的重置边界在 `docs/technique-growth-product-plan.md` 中继续细化，正式实现前必须提供不会误触的独立说明。

### 10.1 技巧成长系统

当前版本将技巧成长系统作为普通统计之外的独立产品能力进行尝试开发。系统在正常游戏中使用现有 39 项技巧引擎推定有效技巧机会、独立发现、提示依赖和有效发现时间，并在本地形成个人成长档案。

用户可见的主形态包括：首页成长摘要、技巧成长总览、技巧详情曲线和完成页成长反馈。39 项技巧采用“待探索、正在成长、已掌握、待巩固”四种生命周期；已掌握的基础技巧退出重点展示但继续保留历史和低频观察。详细产品边界、测量原则和待决定问题以 `docs/technique-growth-product-plan.md` 为准。

成长反馈采用静默记录、轻量反馈、重要反馈和里程碑四级。首轮以每局最多一次非阻塞游戏内反馈为试玩起点，其余变化合并到完成页；完整庆祝只在完成页等自然停顿出现，并且可以立即跳过。自动检查关闭时默认延后技巧确认，避免通过动画验证玩家刚才的填数或候选排除。

## 11. 设置

### 11.1 首期设置

- 语言：系统、英语、日语、德语、简体中文。
- 外观：系统、浅色、深色，默认跟随系统。
- 音效和震动分别设置，默认关闭。
- 保持屏幕常亮。
- 显示计时器。
- 自动检查错误和错误限制。
- 选格优先/数字优先输入。
- 高亮当前区域和相同数字。
- 自动删除备注，默认开启。
- 显示剩余数字。
- 技巧成长反馈强度：丰富、简洁、关闭；最终名称和默认值在 Beta 试玩后冻结。
- 购买 Premium 和恢复购买。
- 玩法帮助、数独技巧、隐私选择、隐私政策、关于和第三方许可证。
- 重置统计与清除当前游戏。

### 11.2 首次使用与帮助

- 不制作强制教程题。首次进入游戏时使用可跳过的轻量浮层介绍铅笔、快速铅笔和智能提示。
- 第一次使用快速铅笔前说明额度消耗、两份草稿和重新生成规则；第一次使用智能提示前说明扣费时机和分步讲解。两项说明都提供“不再显示”。
- 玩法帮助包含数独基础规则、铅笔与快速铅笔、智能提示、Level 1–5、广告额度和 Premium。
- 数独技巧页面提供首期支持技巧的静态说明及多语言术语，并与个人成长详情互相跳转。首轮技巧成长功能不建设课程、测验、证书或全球比较。
- 首次启动默认采用系统语言，只在适用地区展示必要的隐私和广告同意流程，不要求注册。

### 11.3 视觉与无障碍约束

- 首期面向手机并只支持竖屏。
- 棋盘状态的视觉优先级为：`错误或提示结果 > 当前格 > 相同数字 > 同行、同列和同宫`。
- 原始数字、玩家数字、错误数字和候选数必须有颜色以外的区分；候选排除和提示也应使用边框、斜杠、删除线或图标。
- 屏幕阅读器应能读出格子的行、列、确定数字、候选数、选择状态和错误状态。
- 交互区域符合平台无障碍触控尺寸。系统开启“减少动态效果”时关闭非必要动画。
- 成长动画不得遮挡棋盘、阻塞输入或抢占屏幕阅读器焦点；减少动态效果开启时使用等价的静态文字、淡入或状态变化。
- 动态字体不能破坏棋盘、数字键盘和主要操作；必要时对棋盘数字使用适配后的最大字号。

### 11.4 后续功能

- 完成动画设置。
- 分享本地成绩卡。
- 每日挑战。
- 提醒通知。
- 更多主题和高对比度配色。

## 12. 本地数据建议

`user.sqlite` 至少需要以下领域数据：

- `game_sessions`：题目、状态、开始时间、有效耗时、错误、提示、两份候选草稿、当前草稿来源、铅笔模式、快速草稿盘面指纹、`hintCandidates`、提示盘面指纹和完成结果。
- `game_moves`：确定数字、两份草稿的候选数变化、`hintCandidates` 快照，以及撤销和恢复棋盘所需的操作记录。
- `settings`：游戏、显示、声音、语言和隐私偏好。
- `credit_wallet`：两种当前额度和累计获得/消耗数量。
- `credit_ledger`：每次获得和消耗的资源、原因、题目、广告事件和时间。
- `puzzle_completion_rewards`：结合所有用户的首次完成标记，保存结算时的奖励资格和实际发放结果，保证每道题最多结算一次完成补给，免费完成也不能在购买后重领。
- `purchase_entitlements`：本地缓存的 Premium 权益和最近一次商店验证状态。
- 技巧成长数据：有效机会、推定独立发现、提示影响、有效发现时间、生命周期状态和可重算的汇总；具体 schema 在数据契约细化后冻结。

完成奖励结算、完成记录和相应额度流水必须放在同一个 SQLite 事务中，避免 App 在完成页崩溃后重复领取或丢失奖励。广告兑换独立于游戏会话，以唯一兑换事件写入钱包和流水；同一资源不因广告或 Premium 来源拆分成不同钱包。阶段 7 更新当前开发 schema 与测试，不为已被替换的首发前内部奖励规则增加兼容版本。

## 13. 离线、广告与隐私边界

- 无网络时正常游戏、保存、统计和消费已有额度。
- 免费用户无网络且额度为零时，无法通过广告补充辅助额度，普通游戏和手动铅笔不受影响。已有有效 Premium 权益的用户可以离线完成题目并获得符合条件的补给。
- 广告 SDK 不得在用户完成隐私选择前请求广告。
- 设置页在适用地区提供可重新打开的隐私选项。
- iOS 只有在进行跨 App 或网站追踪时才请求 App Tracking Transparency 授权。
- 即使未来启用匿名产品分析，也不得上传棋盘、答案、逐步操作历史或用户输入内容。
- 自动插屏必须清晰标识、可关闭，并遵守广告网络和商店的频率及展示政策。

### 13.1 匿名产品分析（已决策，暂缓实现）

- 产品未来使用 Google Analytics for Firebase 观察 D1、D7、D30 留存和少量关键功能事件；当前版本不接入 SDK，也不开始上传数据。
- 初始只采用 Spark 免费方案和 Analytics，不绑定账单账户，不启用 BigQuery 或其他收费云服务。
- 核心玩法仍是离线游戏；无网络、上传失败、服务不可用或用户关闭分析时，不得影响启动、游戏、提示、保存和恢复。
- 没有账号时，“用户”按随机安装实例统计，不能将其解释为唯一自然人。
- 初始事件范围限制为首次启动、会话、开始/完成/放弃游戏、选择难度、使用智能提示和快速铅笔；扩展事件需要单独审核。
- 设置页未来提供“匿名使用数据”开关，并根据发行地区完成必要的告知、同意、商店数据声明和隐私政策更新。
- 具体实现必须通过独立 `AnalyticsService` 适配层完成，并作为后续独立任务再次批准。

### 13.2 最小静态官网

- 发行前使用自有域名和 Cloudflare 静态托管服务发布一个最小官方网站。
- 首期只提供游戏首页、隐私政策、技术支持和必要的使用条款，不提供登录、用户数据、在线题库或管理后台。
- 网站默认不放置 Cookie、第三方追踪和分析脚本；如未来增加，必须单独完成产品与隐私评审。
- 付费安装广告初期直接进入 App Store 或 Google Play 页面，网站不作为 A/B 测试或广告投放的必要前置条件。
- 广告素材、商店素材和 App 内体验分别在对应广告平台、商店控制台和未来批准的产品分析体系中测试。

## 14. 首期明确不做

- 账号、登录和云同步。
- 在线排行榜、全球百分位和玩家比较。
- 对战、赛事、活动和好友系统。
- Facebook 或其他社交群组入口。
- 经验值、脑力值、金币和复杂成就体系。
- 在线题库更新。
- 订阅和跨平台购买同步。
- 游戏进行中的自动插屏、Banner 或其他强制广告。

## 15. 上线前需要校准

已确认的初始额度（快速铅笔 `3`、智能提示 `5`）和每条激励广告单资源 `+1` 是当前产品规则，不能作为普通数值调优自行改回旧方案。以下事项通过小规模测试评估，结果与后续产品决策一并记录：

- 普通插屏的自然停顿位置、10 分钟冷却和首次安装第一局豁免的完整交互；不能把每局广告机会当作保证展示。
- 新手是否理解两项功能及额度消耗，明确区分手动铅笔与快速铅笔。
- 单条广告兑换一次的完成率、等待感受、到账后消费与离线储备体验。
- Premium 候选难度补给表、每局快速铅笔 `1` 或最多 `2` 次、提示最多 `5` 次能否覆盖正常消耗；按[专项设计](premium-reward-design.md)验证净消耗、提示依赖和库存耗尽路径。
- 普通用户 20 点上限与 Premium 库存上限是否兼顾储备和挑战；购买时启动补给是否必要及其数值。
- 完美与连续完成先保留成绩反馈，若后续增加额度奖励，验证其是否挤占正常补给或突破每局预算。
- 正式题库是否将 39 项技巧各至少 50 道可复现、可玩题目设为发布硬门槛；若不设为硬门槛，也应生成覆盖矩阵并优先补齐稀有技巧。
