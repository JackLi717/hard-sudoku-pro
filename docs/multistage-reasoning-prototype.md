# 多阶段可能解释：离线原型

产品目标见[复盘与成长定义](technique-growth-product-plan.md)，所有路径语义、预算和归因边界只引用[唯一协议](player-technique-attribution-policy.md)。当前不改生产识别结果、游戏历史、成长档案或界面。

## 实现

- `src/application/technique-recognition/reasoning-paths.ts`：泛化的有界搜索、状态合并、累计成本、路径去重和逐步复验；不包含按案例坐标或技巧名称特殊分支。
- `tools/behavior-evaluation/native_replay.cpp --opportunities`：离线枚举接口，复用原生现有全部 39 技巧和证明序列化；不修改技巧检测器或移动端 bridge。
- 历史回归的可选 `--reasoning-paths`：只对最终未被撤回、未被替代、现有准入允许但仍未匹配的投影请求进行补充分析；不把提示/撤销污染事件送入独立归因。其他动作仍走既有全库回归。
- 对每条输出路径，原生逐步复验之外，再用独立求解器得到的唯一解检查各阶段效果。答案只用于审核，不传入搜索。

## 重现

```sh
npm run behavior:regression -- --corpus <played-games.json.gz> --baseline <previous-report.json> --out <output-directory> --reasoning-paths
```

可以增加 `--path-depth 1` 或 `--path-expanded 64` 对比预算。报告每个目标的路径、总成本、完整快照、提示状态、实际/省略步骤、搜索预算、展开数、耗时和限制；原来的未匹配与默认技巧字段保持原样。

单元测试覆盖全部 39 技巧的直接路径和安全边界。设置 `BEHAVIOR_NATIVE_REPLAY` 为新构建的离线程序时，执行真实原生证明复验；工程验收已强制接入。真实多阶段测试包含连续删除 9、前置排除后隐性对子删除 4/8，以及错误删除的反例，比较单阶段与多阶段预算。普通无 native 的 Jest 运行跳过两项集成测试，不将跳过视为通过。

## 已知限制

这是离线、预算受限的解释原型。状态合并会放弃部分替代证明，当前不承诺全局最优、枚举所有路径、精确还原人类意图或精确分配假想路径的提示贡献。高成本短路径需要保留探索预算，不能完全被廉价单数排列挤占；这也是短路径探索阶段的原因。

后续是否接入回顾页面，需要结合解释质量、阅读形式和设备性能再决定。未找到解释不等于错误或猜测，也不通过扩大搜索到完整解题来强行消灭未知。

## 本轮验证结果（2026-09-04）

最终报告：`/private/tmp/hsp-path-regression/run-LHTcON/report.json`。25 局（iOS 9、Android 16）、1,848 条历史操作、1,106 个投影请求；明确失败 0，基线候选/默认解释变化 0，新路径基线防退化失败 0。源码指纹为 `1570627c429f348f769e6751832c2e73d73dc1714669ec6a01cad4aa0b2e3ba0`。

- R6C2−9、R7C2−9 各保留 3 条代表性路径，最小已发现成本均为 670；包括四个单数依次推导的解释。保守保留可能提示依赖，不增加独立技巧次数。
- R5C9−4 保留 3 条路径；单独的真实样本集成测试还验证了“前置排除 → 隐性对子 → 删除 4、8”的两阶段路径，深度 1 无匹配、深度 2 可以解释。全库单动作目标下也可能选到成本更低的其他路径，不能以此证明玩家实际采用哪一条。
- R1C4=6 在当前预算内仍无路径；记录深度、容量和展开限制，不判断为猜测。
- 四个目标分别展开 256、44、61、256 个状态，本机耗时约 5.9、0.8、1.2、3.3 秒。不是移动设备或实时性能承诺。

全量 Jest 832 项通过，11 项跳过（其中新增 2 项 native 集成测试已在专项启用）；原生联动专项 97 项通过，独立审核与基线故障注入 10 项通过。类型检查、全仓 lint、改动代码格式及差异检查通过。离线枚举程序由回归机使用 C++20 严格警告参数重新编译。

整体状态仍为 `checks_passed_with_incomplete_evidence`，历史证据缺口不因补出路径而消失。当前改善的是复盘解释覆盖，不是证明高级技巧掌握增长，也不是把原有 4 个未匹配默认归因强行改成成功。
