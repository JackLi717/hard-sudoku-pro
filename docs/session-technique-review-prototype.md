# 单局技巧回顾：开发模式内部原型

本轮按产品负责人决定推进内部解释界面。归因规则仅引用[玩家技巧归因协议](player-technique-attribution-policy.md)；工程验收遵循[自动化验收分工](automated-behavior-acceptance.md)。后续实现已接入共享归因层的机会关联及提示曝光持久化，具体边界只引用权威协议；以下初轮验证数字保留为历史记录。

## 使用入口

在 `__DEV__` 开发构建完成一局后，完成页显示“单局技巧回顾 · 开发模式”。Release 构建不显示入口，也不向界面暴露诊断读取接口。失败页不提供该完成回顾入口。当前只查看刚完成的会话，不提供历史对局浏览器。

列表显示本局可用的系统默认解释、逐条落数／明确候选删除，以及提示辅助、归因失效或证据不足状态。记录数量是动作片段数量；同一数对的多次删除可能分属多个片段，不能理解为独立发现次数。

点击记录后，可以切换保存的起始盘面与动作标记，查看候选解释、受助动作和已保存的提示来源。棋盘来自诊断请求中的起始指纹、`growthCandidates` 和 given cells；不是最终答案反推，也不是玩家当时的草稿。动作标记只标出请求的 `observedEffects`，不把落数自动清理候选冒充玩家的删除操作，不添加技巧证明动画。

原型支持简体中文和英文解释文案；其他界面语言暂用英文解释，技巧名称继续复用已有本地化。正文 17 pt、标题 20–26 pt、主要点击区域至少 48 pt。复用现有响应式棋盘，单列滚动布局适配手机与 iPad mini。

## 数据与状态

### 前置技巧与完整过程

提示沿实际动作传播的收尾，详情单独显示“提示后的依赖性收尾”，列出提示技巧、实际前置动作和本步效果。此类记录仍禁止默认归因和完整过程复验；来源关系遵循唯一权威协议，不由页面推理。新实现只影响新记录，原日志不静默重写；旧局重放结论应以单独离线报告呈现。

列表与详情将原结果明确标为“逐步解释／本步解释”，避免把局部单数当成整段推理。进入某条详情后点击“复验完整过程”，调用应用层 `verifyReviewProcesses()`，只复验涉及该记录的全部候选过程，同时保留整个机会图的完整性门槛。具体依赖归因、成本及歧义语义仅引用权威协议。

详情展示依赖性收尾、心算备选、起点已有单数及未确认状态；每条过程分别显示起始 revision、默认解释、候选技巧、实际效果及未明确执行的效果提示。“查看过程起始盘面”切换到原锚点的独立候选快照，仍是只读棋盘，可返回本步盘面。多个起点或多个完整机会不由页面强行选取赢家，原动作列表和机会编号不改写。

复验按需运行，不在打开列表时批量重算整局。总超时 30 秒，调用现有 native 分析器并传递取消信号；不同运行的请求 ID 隔离。刷新、新诊断、切换记录、返回或卸载立即撤销旧运行，迟到成功不会恢复旧标签。超时、失败、截断、无过程证据及 native 不可用均有独立说明，允许重试但不能把缺失证据当成独立发现。

原 `buildSessionReview()` 仍只投影历史记录；新过程结果只留在当前详情组件内存中，不更新 SQLite、评分或用户档案。开发运行时注入 native 分析器，Release 不提供回顾接口。

实测另修复热更新生命周期：新生产运行时等待 Nitro 数据库排队关闭完成再重开；重建期间不继续渲染已关闭的旧运行时，避免出现“database is closing／already open”。此修复不改变数据库 schema 或对局内容。

- `BehaviorShadowStore.readSession()` 按 session ID 参数化读取原有 `behavior-shadow.sqlite`，不在界面直接执行 SQL。
- `buildSessionReview()` 复用现有导出器的最终片段与失效优先规则；不会重新运行 native、修改历史诊断或改变权威归因字段。
- 仅有请求或暂定结果的片段显示“尚无最终分析记录”。完成页早于最后分析落库时，通过同一仓储的保存通知自动刷新，也可手动刷新；旧读取结果不能覆盖较新的读取。
- 缺少请求或无法读取的盘面不作推测还原。没有匹配、读取失败、空库分别说明，不等同于“玩家没用技巧”。
- 缺少 `hintAssistance` 的历史记录即使保存了默认技巧，也只显示证据不足；候选标签仅在详情中保留供检查。已知受助效果与旧 eligible 结果矛盾时，界面也不把旧标签提升为无辅助归因。
- 撤销、恢复、过期、枚举不完整等原始禁止原因保持可见。后到的成功结果不得覆盖失效诊断。

本轮不修改 SQLite schema、内容产物、C++ 技巧、递归规则、人力成本或版本号，不生成成长分数、掌握度、独立使用次数、发现时间曲线、成长事件或画像写入。`growthReleaseReady` 保持 `false`。

## 剩余边界

这些记录是系统对可观察动作的合理解释，不证明玩家脑中采用了哪种技巧。新记录的提示曝光跨重启保留，但不能补回旧记录中已丢失的证据。列表保留原始动作，并按共享归因层输出显示机会编号、歧义或缺失证据，不在界面中自行去重。尚未完成的片段在诊断写入失败或进程退出后可能一直缺少最终结果；刷新不会修复或重新归因旧数据。

用户原有 iPad mini 模拟器检查时有 1 局进行中、6 局已完成、913 条影子记录，两个库 `quick_check=ok`。本轮不覆盖安装该设备，不结束其对局或清空数据。排版预览使用独立临时模拟器和内存夹具，不是新的真人整局验收。
