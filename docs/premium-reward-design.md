# Platon Sudoku：宽松免费体验与 Lifetime Premium 商业方案

更新日期：2026-10-03

状态：本轮只统一商业、产品、运营和验收文档；新策略尚未实现，也未验证或发布。当前源码和已上传测试包不能据本文推定为新规则。

## 1. 权威边界与长期目标

本文是奖励和商业策略的唯一产品依据；游戏功能计划、SDK 边界、运营材料和验收清单引用本文，不另设奖励表。

- 长期扩大真实使用用户群，优先保证基础游戏好玩、免费且少打扰；教学、逻辑提示和复盘是附加价值，不要求大众玩家先理解高级功能。
- 大多数玩家可以长期免费使用；少量自愿购买者和自愿广告收入支撑低成本维护。小比例购买即可维持产品是待实际收入与支出验证的商业假设。
- 用户增加不构成减少福利的理由，不预设达到规模后提高广告频率或收紧免费体验。
- 优先商店搜索与发现、真实体验带来的推荐；无需持续经营多个内容平台或依赖博主合作。自然增长和半年至一年百万用户均不是已验证预测。
- 核心游戏、提示计算、奖励与进度本地处理。当前不建设账号、推荐归因、云钱包或自建后台，不因这轮策略接入分析 SDK、远程配置或额外云服务。
- 本轮不改题库、难度、提示算法、成绩、复盘或其他页面设计；代码、四语资源、schema、商店和广告配置留待下一轮明确实现范围。

## 2. 已确认的目标规则

| 项目 | 免费玩家 | Lifetime Premium |
| --- | --- | --- |
| 基础游戏与手动笔记 | 长期免费，不被自动广告打断 | 同样可用 |
| 快速候选（讨论中的自动笔记） | 首次生成、确认重新生成均无限免费；显示、隐藏、恢复和人工编辑免费 | 同样无限免费，不作为独占权益 |
| 智能提示 | 使用可储存的提示次数；每条有效提示消耗 1 次 | 永久无限，不扣免费钱包 |
| 每日补给 | 每个自然日首次打开 App 自动增加 5 次提示，当天只领一次；无需账号、联网或进入签到页面 | 不需要次数补给 |
| 连续使用奖励 | 采用温和的连续奖励方向，具体周期和数量待确认 | 不需要次数补给 |
| 自愿广告 | 每个有效标准激励奖励事件增加 5 次提示，可储存并离线使用 | 不请求或展示广告 |
| 自动／强制广告 | 无；开局、继续、游戏中、完成后均不自动插入 | 无 |
| 分享奖励 | 暂缓；不实现分享送 7 天、邀请奖励、归因或防刷后台 | 无额外分享权益 |
| 购买 | 可自愿一次性购买永久无限提示及无广告体验 | 永久权益，不提供订阅 |

“每天首次打开”表示按日增加 5 次，不是每次启动发放，也不是把余额补到 5 次。余额保存，不以当天用完为条件。

快速候选继续保持两份草稿、人工编辑、覆盖确认和恢复边界；免费不等于自动覆盖玩家笔记。快速候选无钱包、耗尽、广告补充或使用次数上限；使用量仍可作为真实操作统计，不改成绩规则。

## 3. 待确认参数与保留边界

以下事项须在实现前向产品负责人确认，不把讨论中的例子写成已冻结决定：

- 首次赠送提示的数量。旧运行时为 5 次；讨论中的充足初始赠送尚未定数。首次赠送与首次打开的每日 5 次是否同日叠加也待确认。
- 连续奖励候选：第 1、2、4、5、6 天各 5 次，第 3 天 8 次、第 7 天 10 次；8／10 为当天总数，候选七天合计 43 次。七天循环、中断后的计数方式尚未冻结；已领取余额不因中断而扣除。
- 本地自然日的时区、跨午夜、跨时区和修改系统时间处理。原则为每日幂等、离线可领，不要求服务端验真，不承诺防破解。
- 提示持有上限。当前运行时为 99；新补给节奏下是否保留以及每日奖励满仓处理待确认。任何上限不得导致用户看完广告却拿不到播放前承诺的 5 次；无法完整发放时不提供该广告。
- 既有“每道新题首次完成推进一格，满三格提示 +1”的完成奖励，是否与日补给并存待确认。本轮没有批准取消，不据新方案擅自删除；成绩、连胜与首次完成事实保持现有规则。
- 完成页已有自愿广告入口是否保留待实现范围确认；如保留，奖励统一为提示 +5，不再发快速候选次数，不增加广告入口或自动播放。
- 不承诺“每天最多一条”或“看完广告 24 小时无限”；本轮采用次数奖励。广告日上限尚未决定，每次展示必须主动选择。
- 首发奖励活动是否采用固定期限，以及起止日期尚未确认。“一年”是讨论候选，不是已发布承诺；不在源码或商店配置到期降额。

## 4. 提示、广告与本地发奖

- 一条有效结构化提示第一次成功展示观察阶段时消费 1 次；同一提示的推理页、应用和重复读取不再次收费。修改棋盘后请求新的有效提示仍消费一次。
- 冲突、标红错误、已完成棋局、计算失败或没有有效逻辑步骤不消费。看过第一阶段后关闭仍算使用；应用后撤销不退额度。提示不自动连续解题。
- 日补给领取记录、连续使用状态、实际发放和提示钱包在一个本地事务中保存；重启、重复前台恢复、重复回调或重试不重复发奖。
- 每次广告前明确写“观看广告，获得 5 次智能提示”。只凭 SDK 有效奖励事件入账，展示、关闭、点击广告素材、安装广告主产品不能代替奖励条件。
- 广告事件与入账流水同事务、幂等保存；奖励与后续提示消费是两个独立事务。奖励后取消提示或计算失败不撤回所得。
- 加载失败、无填充、提前关闭、拒绝同意或离线不入账，允许继续基础游戏和免费快速候选。已有有效奖励事件不能因随后断网被否决。
- 保存的提示可离线使用；日补给本地领取。广告、购买、恢复和必要隐私处理仍可能联网，不宣传“完全离线且无广告”。本地余额不保证卸载清除数据后恢复，不因此新增云服务。
- 延续标准激励广告、UMP、地区限制、平台验证与 SDK 隔离，技术边界见[商业 SDK 设计](commercial-sdk-boundary.md)。

## 5. Premium 与长期信任

- 一次性非消耗型 Lifetime Premium：永久无限智能提示、不请求广告，无需每日领取或补充。
- 快速候选对所有人免费，购买页不把它包装为付费专属权益。主题等其他权益不在本轮新增。
- 购买、恢复和权威交易刷新只更新权益，不补钱包。购买前提示余额保留并隐藏；有效 Premium 不扣钱包、不领取次数奖励，也不伪造使用流水。
- 成功权威刷新确认退款／撤销后恢复免费规则及保存的提示余额；不追扣历史使用、不追补 Premium 期间奖励。连续日数在权益切换时如何衔接待实现前确认。
- 已购买的永久权益按购买时承诺保留；已领取的提示不因以后奖励调整被扣减或突然过期。
- 正常游戏和免费快速候选保持稳定。未来赠送数量可基于实际负担和体验复评；不因用户数增加默认降低。
- 若公开固定期限活动，使用正式上线时确定的统一截止日期，承诺期内兑现；到期可直接续期。未公布替代安排时沿用规则，不自动关闭福利。
- 若调整未来奖励，建议提前约 30 天简明通知新旧数量与生效日；这是体验建议，不是引用的法定期限。“保留调整权”不能代替兑现承诺。

## 6. 测试者策略

测试者运行策略待产品负责人确认。推荐方案为普通测试者使用正式目标的宽松免费规则，少量许可测试账号单独验证 Premium 购买、恢复、离线缓存、退款／撤销，避免全部无限提示掩盖免费体验。

- 不要求普通测试者为了参与而购买或看广告；无广告可用时仍能测试基础游戏、日补给和快速候选。
- 当前没有批准新分析采集。使用 Play Console 原生可用数据及自愿问卷；少量测试者的主观活跃观察不能直接推算大众留存。
- 任何已经对外承诺的创始测试者 Premium 回报继续兑现。是否对新批次承诺永久码须另行决定，不把推荐策略理解成撤回旧承诺。
- 测试回报与评分、评论、推荐和正面反馈分离；负面反馈同样有价值。
- 不向全体测试者自动伪造 Premium。商店审核访问和许可测试权益是特定测试用途，不能当成普通玩家权益。

## 7. 当前实现与后续验收

截至本轮文档核对，源码仍为提示初始 5 次、快速候选初始 3 次、两项上限 99、普通广告所选资源 +1、完成页广告两项各 +1、首次完成三格兑换提示 +1；Premium 两项辅助无限。当前 `npm run android:bundle:closed-beta` 使用一次性提示最低余额 20，普通 Release 默认不启用该补贴。

历史 Play 上传记录曾使用闭测无限提示；这是已上传构建的记录，不能据它宣称当前源码仍无限，也不能把未来免费策略写成测试者已收到。实际构建与配置见[上架清单](operations/google-play-launch-checklist.md)。

本轮不改运行时、构建脚本、SDK、四语资源、数据库、广告后台、商品或已发布材料。新方案实现前先确认第 3、6 节，再确定具体实现页面与领域边界；所有新验收均待执行，旧测试通过不能证明新规则已通过。[专项验收](reward-model-acceptance.md)记录目标检查。
