# Hard Sudoku Pro：Premium 辅助额度与完成补给设计

更新日期：2026-09-03

状态：产品方向已确认，补给数值为待试玩验证的候选方案，尚未实现。

## 1. 目标与权威边界

本文件专门设计一次性 Premium 的有限辅助补给。通用规则以[游戏功能计划第 8 节](game-feature-plan.md#8-额度广告与完成奖励)为准：新用户获得快速铅笔 `3` 次、智能提示 `5` 次；免费用户此后每完成一条激励广告，只增加所选资源 `1` 次；Premium 不展示广告，通过游戏完成获得有限补给。

设计目标是让正常游玩的付费玩家有够用的辅助，同时保留自己观察、推理和掌握技巧的空间。补给太少会让学习频繁中断；补给太多、每局全额报销或无限使用，则可能让玩家一直跟随提示完成，削弱信心、挑战感和继续探索的兴趣。以上是需要试玩验证的体验假设，不能把减少提示使用量本身当作成功。

本次只更新产品文档。旧版全体玩家完成奖励、完美与连续奖励叠加、Premium 无限辅助的代码与历史验收结果，需在阶段 7 按新规则替换和重新验收。当前未公开发行，保持一个开发基线，不增加奖励策略版本、并行旧规则或额外币种。

## 2. 已确认原则与待验证数值

| 项目 | 约束或候选方向 | 状态 |
| --- | --- | --- |
| 辅助消费 | 智能提示和快速铅笔仍各消耗 `1` 点，手动铅笔免费 | 已确认 |
| Premium 权益方向 | 无广告、有限库存、按完成游戏补充，不提供无限辅助 | 已确认 |
| 广告兑换 | 免费用户一条广告只得所选资源 `1` 次，与游戏会话脱钩 | 已确认 |
| 新手体验 | 快速铅笔 `3`、智能提示 `5`，一次性发放 | 已确认 |
| 每局快速铅笔补给 | 以 `1` 次为起点，最多 `2` 次作为备选 | 待验证 |
| 每局智能提示补给 | 随难度和正常消耗校准，候选总量不超过 `5` 次 | 待验证 |
| 购买启动补给 | 避免零库存购买后仍无法体验辅助，候选为一次性补足至新手库存 | 待验证 |
| 库存上限 | 两种资源各 `20` 点作为首轮试玩起点，是否需要不同上限另行评估 | 待验证 |
| 完美、连续完成附加额度 | 首轮不叠加，之后如引入须纳入每局总补给上限 | 待验证 |

“每局最多补给 5 次提示”限制的是该局结算时新发放的数量，不是每局最多使用 5 次；玩家可以消耗此前攒下的库存。快速铅笔的 `1–2` 次同理。库存不按局清零，也不因离线过期。

## 3. 首轮候选补给表

按 Level 1–5 给固定完成补给，以真实试玩中的每局消耗校准等级表，不按这一局实际使用了多少逐项返还。

| 首次完成难度 | 快速铅笔 | 智能提示 | 校准意图 |
| --- | ---: | ---: | --- |
| Level 1 | +1 | +1 | 为基本候选录入和少量学习提供补给 |
| Level 2 | +1 | +2 | 覆盖入门技巧学习中的少量卡点 |
| Level 3 | +1 | +3 | 为多步骤推理保留有限帮助 |
| Level 4 | +1 | +4 | 覆盖高级技巧中的关键卡点 |
| Level 5 | +1 | +5 | 提供候选范围内最高补给，仍保留独立解题需求 |

这张表是设计候选，不是已经证明够用的发行配置。不能把 Level 5 的 `+5` 解释为用户每局应当用满 5 次提示，也不能因目标补给不足而改变题目难度或提示引擎的原子步骤。

快速铅笔先测试所有等级 `+1`。若正常玩法经常需要第二次有效重新生成，再比较高难等级或全等级 `+2` 的备选。任何备选均以每局快速铅笔总补给最多 `2`、智能提示总补给最多 `5` 为本轮评估边界；更高数值需要新的产品决定。

首轮不叠加完美完成、连续完成的额外额度，保留其成绩、连续记录和成长反馈。后续若需要这类奖励，应在每局预算内重新分配，例如给某等级预留一个额外额度，而不能在已经发满 `5` 次提示后再叠加另一套奖励。

不采用“本局用了几次就补几次”：这会使多用提示成为获得更多补给的条件。固定补给允许独立完成者把省下的额度留给以后更难的题，同时不取消提示辅助完成者的正常补给。

## 4. 结算与权益边界

- 仅合法首次完成、结算时有有效 Premium 权益的题目获得完成补给；与开局网络状态、开局广告及结束时广告供应无关。
- 免费阶段已首次完成的题目不在购买后追补，也不能通过重玩补领；重玩仍可更新正常成绩。
- 未首次完成的题目失败后重试，之后首次成功完成时可以按当时权益正常结算；失败和放弃本身不发放补给，已消费额度不退。
- 提示辅助完成可获得与同等级独立完成相同的基础补给；两种完成状态及成长归因仍按各自规则记录。
- 本局奖励只结算一次；成绩、首次完成标记、奖励结果、钱包及流水原子保存。杀进程、重开完成页、恢复购买、重置统计不能重复发放。
- 满库存时按剩余容量入账，显示实际获得量和上限说明；未入账部分不形成可在以后反复领取的待领奖池。
- 在线与离线使用相同本地钱包和结算规则，不把 Premium 玩家重新导向广告补充。

## 5. 购买启动库存与额度耗尽

购买时的候选方案是：首次成功购买 Premium 后，快速铅笔补足至 `3`、智能提示补足至 `5`；已有余额更高时保留原值。该方案是一次性体验衔接，不是每次打开应用、恢复购买或每局开始都补足。

候选计算方式为 `增加量 = max(0, 目标库存 - 当前库存)`，与首次购买补给标记同事务保存。免费阶段通过广告获得的剩余额度继续保留。购买补给的数值、恢复边界及其一次性标记在 OQ-015 冻结前仍需验证。

Premium 库存耗尽后，基础游戏、手动铅笔、撤销、保存和继续全部可用；相同盘面快速草稿的免费恢复也不受零余额限制。辅助按钮显示库存不足与完成补给来源，不播放广告，不偷偷转成无限使用，也不通过反复开局赠送额度。

必须专门试玩以下风险：玩家卡在高难题、库存为零，因缺少提示无法完成，也无法获得下一次补给。不能只用“可以换一道简单题”判定问题已解决，更不能让付费体验依赖反复刷低难题。若这种情况频繁出现，先调整初始库存、等级补给或储备上限；若仍不够，需单独设计有限的应急补给，并评估是否会形成免费循环。应急方案尚未确定，不能自行增加每日赠送、时钟刷新或看广告兜底。

同级乃至全部题库首次完成后的重玩补给，也应列入长期体验评估；当前重玩不发奖。若长期游玩因此失去合理补给来源，必须在发布权益前单独决定处理方式，不能默认为无限重玩领取。

## 6. 保留挑战与学习体验

- 提示仍然是可解释的一个原子逻辑步骤，先观察、再推理、最后应用；不自动串联下一次提示或连续执行整题解答。
- 候选排除也算一次完整提示，不能将“5 次提示”当成“必定填 5 个数字”。完整解题路径的步数不能直接用来估计正常玩家需要的提示数。
- 不因为高余额或余额将满而提示用户“尽快用掉”，不设置消耗辅助额度的任务或奖励。
- 关闭提示后允许用户自行继续，不把使用提示描述为失败；不为了压低消耗而隐藏解释、提高提示价格或改变引擎选择。
- 成长反馈继续区分独立发现与提示辅助，不因 Premium 身份或奖励数量改变技巧归因。不得借本次奖励设计修改技巧识别协议。
- 体验目标同时包括：正常辅助够用、关键卡点能学会、后续能独立推进，以及仍愿意挑战下一题。

## 7. 校准方法与验收

先进行本地内部试玩和经同意的封闭测试，不因本设计新增在线埋点、广告 SDK 或服务端。未来产品分析仍服从既有单独批准流程。

按难度、新手/熟练玩家和试玩阶段分组，记录合法展示的提示次数、成功创建/重新生成快速草稿次数、完成/失败/放弃、奖励前后库存及零余额遭遇。只展示提示后关闭也已经消费，免费恢复快速草稿不算消费。失败与放弃的消耗必须计入整段游玩序列，不能只看成功完成的局。

每种资源分别核对：

```text
期末库存 = 期初库存 + 实际入账补给 - 实际消费
```

比较每局消耗的中位数和较高分位数、连续多局净增减、库存耗尽率、满仓率、频繁补草稿的原因，以及需要靠低难题积攒额度的情况。避免只用平均值掩盖学习高级技巧者的短期需求。

同时观察提示后是否能自行推进、是否理解推理、下一道相似题的独立尝试，以及反复请求提示后的信心和继续游玩意愿。不能把提示后自主操作直接等同于已掌握技巧，也不能用广告展示量或提示使用量单独判断奖励设计成功。

| 观察到的问题 | 优先调整方向 |
| --- | --- |
| 正常使用快速铅笔者持续净亏，合理第二次生成频繁受阻 | 比较每局 `+1` 与最多 `+2` 的方案 |
| 高难学习者频繁零库存或因额度放弃 | 检查启动储备、难度补给和耗尽处理，不只要求玩家少用 |
| 多数玩家长期满仓且反复靠提示推进 | 检查补给是否过量及提示交互，不靠增加无关奖励消耗库存 |
| 玩家为补给刻意刷简单题 | 检查难度奖励比例与高难正常消耗是否失衡 |
| 提示使用下降但理解、完成意愿和信心也下降 | 不能视为改善，检查是否因稀缺而被迫放弃学习 |

发布前必须覆盖：新手库存衔接、零库存购买、离线长时间游玩、从低难到高难、连续失败/放弃、提示辅助完成、满库存结算、免费完成后购买、重玩及题库耗尽。测试样本量、分组与可接受阈值应在试玩前记录，不能用事后挑选的均值声称验证成功。

通过试玩后，由产品负责人冻结 OQ-015：等级补给表、快速铅笔 `1` 或 `2` 的选择、库存上限、购买启动库存、附加奖励和耗尽处理。冻结后再更新正式权益文案和阶段 7 验收用例；本文件中的候选表不得直接作为商店购买承诺。

## 8. 后续订阅机会

订阅仅作为未来构想保留：可以研究周期性有限补给、更高储备上限，或单独评估无限辅助是否适合某类用户。无限辅助可能削弱当前希望保留的挑战，不能因为改成订阅就跳过学习与兴趣验证。

当前首期保持一次性 Premium，不实施订阅、定时发奖或订阅专属数据结构。未来立项时需要明确与一次性 Premium 的差异，并保留已经购买者的既有承诺；当前不能在购买页宣传尚未批准的订阅权益。
