# 完成页庆祝体验改进：产品规格与开发计划

日期：2026-09-11

状态：实施中；任务 1 已完成，任务 2–9 待实施

## 1. 背景

当前完成页能够展示难度、用时、错误、智能提示和部分 Premium 首次完成奖励，也能继续同难度题目、
进入复盘或离开结果页。但页面主要承担结算和导航功能，完成反馈只有绿色勾号与固定标题，普通完成时
还使用“进度和奖励已安全保存”作为副标题，缺少获胜、被肯定和继续挑战的动力。

“选择其他难度”当前会先离开完成页并返回首页，再由玩家打开首页难度选择框。该路径增加一次无意义的
页面跳转，也让按钮文字与实际行为不一致。

本次改进把完成页从“结算页”调整为“胜利与下一步页面”：先明确庆祝玩家真实完成的成绩，再展示本局
数据和符合条件的实际道具补给，最后让玩家直接继续同难度、切换难度、复盘或返回首页。

## 2. 目标

- 每一次合法完成都有清晰、克制且有变化的庆祝反馈。
- 所有玩家都能得到视觉荣誉和与本局事实相符的表扬，不把免费用户或重玩玩家呈现为“没有奖励”。
- 继续保持 Premium 首次完成补给、库存上限和重玩不发补给等现有经济规则。
- 点击“换个难度”后直接在完成页弹出选择框；取消后仍保留当前完成页。
- 删除“进度和奖励已安全保存”及同类保存声明。
- 补齐完成类型、快速铅笔使用次数、新最佳成绩和实际补给状态等已经规划但尚未完整呈现的信息。
- 四种语言、深浅主题、动态字体、屏幕阅读器和减少动态效果保持一致体验。

## 3. 非目标与范围边界

本轮不做：

- 不新增积分、金币、经验值、每日奖励、连续签到或新的可消耗资源。
- 不改变免费、Premium、首次完成、重玩、库存上限或按难度补给的现有规则。
- 不建立可收藏奖杯、成就图鉴或新的持久化成就系统。
- 不恢复首发范围之外的“我的技巧”、本局技巧足迹或成长曲线入口。
- 不改变题目分配、难度评级、提示引擎、完成判定和失败页的产品结构。
- 不从完成页新增广告入口；广告补给继续遵守已经确定的商业化入口约束。
- 不新增第三方动画、图标或音频依赖。

若后续希望奖杯可以收藏、升级或用于解锁内容，应单独设计成就系统，不在本次视觉庆祝中暗示已经获得
持久化资产。

## 4. 产品原则

### 4.1 荣誉反馈与道具补给分层

“奖励”分为两个含义，界面必须清晰区分：

1. **荣誉反馈**：奖杯图形、庆祝动效、鼓励语和事实标签。每次完成都有，不产生库存或经济价值。
2. **实际补给**：快速铅笔和智能提示的实际入账数量。只在现有领域规则判定符合资格时展示。

免费用户和重复完成不会显示“+0”或“本局没有奖励”。Premium 首次完成即使因库存上限实际入账为
零，也应显示准确的满仓说明，不能承诺未到账的补给。

### 4.2 只表扬能够证明的事实

文案只使用完成状态和结算事务能够确定的事实：完美完成、独立完成、提示辅助完成、首次完成、新最佳
时间、难度和本局统计。不根据用时推断玩家“很聪明”，不根据少量数据声称能力提高，也不因使用提示或
出现失误贬低玩家。

### 4.3 庆祝不阻塞下一步

庆祝动画不延迟按钮出现，不要求点击领取，不阻止系统返回或屏幕阅读器操作。玩家可以立即开始下一题、
换难度、复盘或返回首页。

## 5. 页面信息结构

完成页从上到下排列：

1. 奖杯或胜利勋章图形，以及短时、可降级的庆祝动效。
2. 当前难度、情境化标题和一条鼓励语。
3. 最多三个真实荣誉标签，例如“首次通关”“完美解答”“刷新纪录”。
4. 本局数据：用时、失误、智能提示、快速铅笔。
5. 条件性的 Premium 实际补给卡。
6. 主按钮“继续挑战难度 {{level}}”。
7. 次按钮“换个难度”，直接打开难度选择框。
8. “查看本局复盘”和较弱的“返回首页”入口。

窄屏或大字体下，本局数据使用两列布局，不强制把四项数据挤在同一行。真实补给卡与荣誉标签在视觉和
无障碍文本中都不能混为一组。

## 6. 完成状态与文案策略

### 6.1 主标题优先级

同一局可能同时满足多个事实。主标题按以下优先级选择，其余事实作为荣誉标签展示：

1. 新最佳时间。
2. 完美完成。
3. 首次完成该题。
4. 独立完成。
5. 提示辅助完成。

首批中文建议：

| 事实 | 主标题示例 | 鼓励语示例 |
| --- | --- | --- |
| 新最佳时间 | 新纪录！ | 比此前最快成绩又前进了一步。 |
| 完美完成 | 太漂亮了！ | 零失误、未用提示，这一局解得很干净。 |
| 首次完成 | 首次攻克！ | 你已经拿下难度 {{level}} 的一道新题。 |
| 独立完成 | 靠自己解开了！ | 有过绕路也没关系，每一步都是你推出来的。 |
| 提示辅助完成 | 稳稳拿下！ | 提示只是路标，完成整盘的是你。 |
| 通用回退 | 又解开一局！ | 复杂的盘面，被你一步步理顺了。 |

### 6.2 文案轮换

- 每种完成类型首批准备 8–12 条鼓励语，标题保持少量、稳定，变化主要放在副标题。
- 使用 `sessionId + 文案分组` 的稳定哈希选择文案；组件重渲染、旋转屏幕或从复盘返回时不能换句子。
- 文案选择函数保持纯函数，并为所有状态优先级和稳定性编写单元测试。
- 所有文案进入类型安全的本地化资源，不能在组件中硬编码中文。
- 英语、日语、德语和简体中文资源必须同时补齐；各语言可以自然改写，不要求逐字翻译中文恭维语。

### 6.3 解题箴言

首版不用名人姓名或未经核实的名言。采用原创、无归属的短句，避免出处、翻译、版权和文化语气问题。
箴言作为低频点缀，每四次完成最多出现一次，不替代每局必有的鼓励语。

中文候选：

- 最后一格只是答案，走到这里的过程才是实力。
- 慢一点没关系，清晰的判断比速度更重要。
- 每一次排除，都让答案更接近你。
- 复杂的盘面，也会在耐心里逐渐清楚。
- 好的推理不是猜得快，而是每一步都站得住。
- 暂时看不见答案时，先找一个确定的下一步。
- 一格一格推进，也是一种漂亮的胜利。
- 解开数独，也是在把混乱重新排成秩序。

是否展示箴言由结算后的累计完成数决定，规则应稳定、可测试。若版面拥挤或动态字体超过布局阈值，可
优先隐藏箴言，不能隐藏主鼓励语、本局数据或操作按钮。

### 6.4 删除的文案

- 删除 `result.saved` 对应的“进度和奖励已安全保存。”及其他语言版本。
- 普通完成副标题改为情境化鼓励语，不再用保存状态占位。
- 不增加“奖励已自动领取”“数据已安全保存”等内部实现说明。

## 7. 荣誉标签规则

荣誉标签只呈现本局成立的事实，建议最多显示三项：

| 标签 | 条件 |
| --- | --- |
| 刷新纪录 | 本局用时严格小于该难度或该题既有最佳时间，具体口径必须与统计页统一 |
| 首次通关 | 该题此前从未合法完成 |
| 完美解答 | `completionKind === 'perfect'` |
| 独立完成 | `completionKind === 'independent'` |
| 提示辅助 | `completionKind === 'hint_assisted'` |

“完美解答”已经隐含未使用智能提示且零失误，不再同时显示“独立完成”，避免标签重复。若“刷新纪录”的
产品口径最终选择该等级最佳而不是该题最佳，结算数据、统计页和无障碍标签必须统一采用同一口径。

本计划推荐使用**该等级最佳时间**，更容易被玩家理解，也与“继续挑战同难度”形成连贯目标。实施前先
确认现有统计数据是否已经可靠提供该口径；若没有，不应临时改成无法说明的近似判断。

## 8. 实际补给展示

继续沿用当前规则：只有结算时具有有效 Premium 权益且首次完成该题，才获得按难度固定的快速铅笔与
智能提示补给；实际入账受 `99` 点库存上限裁剪。

补给卡状态：

| 状态 | 展示 |
| --- | --- |
| 两种资源都有入账 | “本局补给”，分别显示图标、实际 `+N` 和结算后余额 |
| 某项被部分裁剪 | 显示实际 `+N`、结算后余额和“已达到库存上限”的短说明 |
| 两项都因满仓入账为零 | 显示“库存已满，本局补给未增加”，不显示 `+0` 冒充奖励 |
| 免费用户首次完成 | 不显示补给卡，不显示待领取补给 |
| 重复完成 | 不显示补给卡 |

补给卡不是领取按钮，进入完成页前奖励已经与完成记录在同一事务中结算。杀进程、重新进入或返回完成页
不能再次发放。

## 9. 难度选择交互

### 9.1 完成页路径

点击“换个难度”后：

1. 完成页保持挂载，并在其上打开底部难度选择框。
2. 选择框复用首页的五级难度、说明和各等级完成数。
3. 点击背景、关闭按钮或系统返回时关闭选择框，仍停留在原完成页，所有文字和滚动位置保持不变。
4. 选择一个难度后关闭选择框并直接开始该难度的新题，不经过首页。
5. 题库分配、未完成题优先和全等级完成后的随机重玩继续使用现有协调器规则。
6. 启动失败时保持可恢复的结果状态并展示现有错误消息，不能留下空白页面。

本轮只改变合法完成页上的“换个难度”。失败页行为保持现状，避免把完成页批准范围扩展到失败流程。

### 9.2 组件边界

将首页内嵌的难度选择 `Modal` 提取为可复用的 `LevelPickerModal`。它只负责呈现和选择，不直接依赖
SQLite、协调器或页面路由。

建议属性：

```ts
type LevelPickerModalProps = {
  visible: boolean;
  busy: boolean;
  completedByLevel: Readonly<Record<DifficultyLevel, number>>;
  onClose(): void;
  onSelect(level: DifficultyLevel): void;
};
```

首页和完成页共同使用该组件，避免复制五级难度说明、无障碍标签和响应式样式。完成页选择难度后可调用
现有 `requestNewGame(level)`；终局会话不应触发“放弃进行中对局”的确认流程。

## 10. 结算与展示数据

当前 `GameState` 已有完成类型、用时、错误、智能提示次数和快速铅笔次数；当前完成奖励包含首次完成、
Premium 资格和实际入账数量。完成页还需要可靠的新最佳判断、奖励前后余额或等价的结算快照。

建议由完成事务返回只读的结果结算 DTO，再由 `OfflineGameSnapshot` 提供给完成页：

```ts
type CompletionResultSummary = {
  isFirstCompletion: boolean;
  isNewLevelBest: boolean;
  previousLevelBestTimeMs: number | null;
  reward: CompletionReward;
  walletBefore: Readonly<Record<CreditResource, WalletBalance>>;
  walletAfter: Readonly<Record<CreditResource, WalletBalance>>;
};
```

要求：

- 新最佳必须在更新最佳时间之前读取旧值，并在同一结算事务中产生结果，不能由 UI 事后猜测。
- 实际补给沿用库存裁剪后的数量；UI 不根据难度表重新计算应发数量。
- 余额前后值来自同一结算结果，不能从多个异步读取拼接。
- 不把鼓励语 key、动画状态或页面布局写入数据库。
- 若现有表已经能支持等级最佳查询，本轮不新增 schema；若不能，应先明确统计口径再评审数据变更。

## 11. 视觉与动效

- 将单独的绿色勾升级为奖杯或胜利勋章图形，保留数独产品的克制风格，不采用赌场式金币雨。
- 默认动效控制在约 `800–1200 ms`：奖杯轻微上移/缩放，少量星点淡入淡出。
- 页面和所有按钮立即可操作，动画不循环、不遮挡、不捕获触摸。
- 系统开启“减少动态效果”时直接显示静态终态，不仅缩短动画。
- 图形是装饰元素，不进入屏幕阅读器焦点；标题负责朗读完成结果。
- 首轮不新增声音。现有震动偏好可以在后续设备体验确认后复用，但不得绕过用户设置。
- 深色模式、四语长文案、窄屏和最大动态字体下均不得截断关键数据或操作。

## 12. 无障碍要求

- 进入完成页时，屏幕阅读器首先获得“难度 + 完成标题 + 主鼓励语”的组合信息。
- 荣誉标签逐项提供可理解的文本，不只靠颜色、星形或奖杯表达。
- 四项本局数据的朗读顺序与视觉顺序一致。
- 补给卡朗读资源名称、实际增加量和结算后可用次数；满仓时朗读明确原因。
- 难度选择框使用模态语义，打开后焦点不落到后面的完成页；关闭后焦点返回“换个难度”。
- 点击区域至少满足项目既有尺寸要求，动态字体下按钮文字允许换行。

## 13. 开发任务与执行顺序

本项目由一名开发者使用 AI Agent 完成。以下任务严格按顺序执行；每一步完成代码、定向测试和检查后，
再进入下一步。无需拆分角色、创建任务交接流程、功能分支或额外工作树。

预计主要影响：

- `src/ui/screens/ResultScreen.tsx`：完成页结构、状态呈现和操作入口。
- `src/ui/screens/HomeScreen.tsx`：移除内嵌难度弹窗，改用共用组件。
- `src/ui/components/LevelPickerModal.tsx`：新增无业务状态的共用难度选择框。
- `src/debug/CompletionResultPreview.tsx`：新增仅开发模式可见的完成页场景预览。
- `src/ui/HardSudokuApp.tsx`：完成页的开始其他难度与返回首页回调。
- `src/localization/resources.ts`：四语标题、鼓励语、标签、箴言和补给文案。
- `src/data/user/user-repository.ts` 与应用协调器：结算结果、新最佳和余额快照。
- `__tests__/`：展示模型、结果页、难度选择、协调器、仓储、本地化和无障碍覆盖。

## 14. 关键测试矩阵

| 场景 | 预期 |
| --- | --- |
| 零失误且未用提示 | 完美标题或更高优先级标题；显示“完美解答”；不重复“独立完成” |
| 有失误但未用提示 | 独立完成反馈；语气不责备 |
| 使用智能提示 | 提示辅助反馈；不使用“独立”“完全靠自己”等错误表扬 |
| 首次完成且刷新纪录 | 新纪录为主标题；首次通关作为标签 |
| 免费用户首次完成 | 有奖杯和荣誉；没有虚假的道具补给卡 |
| Premium 首次完成 | 显示事务实际入账数量与结算后余额 |
| Premium 满仓 | 明确库存已满；不显示 `+0` 奖励 |
| 重复完成 | 可显示新纪录与完成荣誉；不再次显示首次补给 |
| 打开后取消难度框 | 保持完成页内容、滚动位置和复盘入口 |
| 选择其他难度 | 直接进入所选难度新题，不经过首页 |
| 从复盘返回 | 回到同一完成页；文案不变；完整庆祝不重复播放 |
| 减少动态效果 | 静态奖杯立即显示；操作能力完全保留 |
| 最大动态字体 | 关键文案、四项统计和按钮无截断，可滚动 |
| 屏幕阅读器 | 标题、荣誉、数据、补给和选择框按语义顺序可操作 |
