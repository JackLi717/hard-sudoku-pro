# Hard Sudoku Pro：首期开发路线图

## 1. 文档目的

本文档把已经确认的产品和技术决策转化为首期开发顺序、阶段交付物与验收门槛。具体规则分别以 `docs/product-and-data-architecture.md` 和 `docs/game-feature-plan.md` 为准；路线图不重复定义产品规则，也不以赶工为理由改变规则。

首期采用“先验证高风险能力，再完成离线游戏闭环，最后接入商业化和准备发行”的顺序。当前100道题只用于贯通和验证流程，正式题库在提示引擎、评级规则和数据库格式稳定后生成。

## 2. 开发原则

- 棋盘页面只负责展示和输入，不能直接读写 SQLite、答案或提示求解器。
- 游戏规则集中在与 React Native UI 无关的领域层，并通过命令和状态转换驱动。
- 先建立可测试的数据契约，再实现页面、动画和商业化。
- iOS、Android 从首个可玩版本开始同时验证，不能在项目末期才移植另一平台。
- 所有正常游戏能力必须离线可用；广告、购买和隐私同意通过独立适配层接入。
- 每个阶段必须通过对应验收门槛，未通过时优先解决当前风险，不继续扩大功能范围。

## 3. 阶段路线图

### 阶段0：契约与工程基线

目标是冻结跨模块共享的第一版契约，避免页面、数据库和原生提示引擎分别定义同一概念。

交付内容：

- `GameState`、`GameMove`、`HintStep v1`、候选数集合和盘面指纹定义。
- Level 1–5 技巧代码、等级、检测顺序和多语言键清单。
- `content.sqlite`、`user.sqlite` 第一版 schema 与 migration 规则。
- 领域层、数据层、功能页面、原生桥接、广告购买和本地化的目录边界。
- ESLint、Prettier、Jest、原生构建和持续集成的基础检查。
- 第三方依赖、许可证和版本固定清单。

完成门槛：核心契约有示例和自动校验；业务文案不能散落为组件中的硬编码字符串。

### 阶段1：智能提示技术验证

这是首期最高风险阶段，应先于大规模页面开发完成。

交付内容：

- 审计并固定最终提示引擎，明确支持技巧和不支持技巧；候选审计结论见 `docs/phase-1-hint-engine-evaluation.md`。
- 强制关闭 Guess、Backtracking、Trial and Error 及等价回退。
- 根据最终实现选择原生库或纯 TypeScript Worker，通过最薄的 React Native 适配层返回 `HintStep v1`；不得预先绑定已被审计否决的候选。
- 使用当前100题、HoDoKu2 标准轨迹以及抽样中间盘面进行交叉验证。
- 验证后台线程执行、确定性结果、错误状态和无可用技巧状态。

完成门槛：两个平台均能从当前盘面返回正确、结构化、可解释的最简单步骤；不产生猜测提示；最低目标设备上不阻塞 UI。建议把普通提示的 P95 响应目标设为 `100 ms` 以内，高级技巧设为 `300 ms` 以内。若技巧覆盖不足，应在此阶段决定补充固定 fork，或评估 C++ 备选方案。

当前状态（2026-09-01）：原创 C++20 核心已实现全部 Level 1–5 共 39 项技巧；100 题、1,000 个固定随机合法状态和生产 10,000 题全轨迹回放均通过。RN 0.87 Codegen TurboModule 已接入 iOS/Android，在平台专用后台执行器运行，共用 C++ 序列化、取消和错误边界；Android 四种 ABI Debug 包与 iOS arm64/x86_64 Simulator Debug 包编译通过。自动化和工程集成门槛已完成，最低目标 iOS/Android 真机的 UI 无阻塞、取消、内存和耗时仍须在连接测试设备后完成发布前签收，详见 `docs/phase-1-native-integration-acceptance.md`。

### 阶段2：游戏领域核心

目标是先获得完全可测试的游戏状态机，不依赖正式 UI。

交付内容：

- 选格、填数、替换、擦除、错误、冲突、暂停、计时、完成、失败和重新挑战。
- `manualCandidates`、`quickCandidates`、`solverCandidates`、`hintCandidates` 的隔离与同步规则。
- 快速草稿盘面指纹、重新生成确认和原子扣费。
- 命令式操作历史，支持确定数字、两份草稿、提示候选状态和统计影响的整体撤销。
- 单局限制、放弃、题目分配、首次完成和连续完成规则。

完成门槛：主要规则均有单元测试；相同操作序列始终得到相同状态；撤销可完整恢复操作前快照。

当前状态（2026-09-01）：纯 TypeScript 游戏聚合和确定性命令入口已完成，覆盖选格、
填数/替换/擦除、两份玩家草稿、瞬时求解候选、持久化提示候选、快速草稿原子流程、
提示展示与应用、错误/冲突、暂停计时、完成/失败/放弃/重试及整体撤销。未完成题优先
分配、首次完成和连续完成奖励规则也已落地并通过领域测试。SQLite 事务与恢复属于
阶段 3，正式棋盘和提示界面属于阶段 4–5；验收明细见
`docs/phase-2-game-domain-acceptance.md`。

### 阶段3：SQLite 与恢复能力

交付内容：

- 只读 `content.sqlite` 的安装、版本识别和查询层。
- `user.sqlite` migration、会话、操作历史、设置、统计、额度流水和购买权益缓存。
- 每次有效操作后的增量保存，以及退出、杀进程、设备重启后的恢复。
- 完成记录、首次完成奖励和额度流水的同事务结算。
- 数据损坏、题库版本变化和 migration 失败的安全处理。

完成门槛：在填数、提示应用、奖励结算等关键时刻强制终止 App，重启后不能丢失、重复或产生互相矛盾的数据。

当前状态（2026-09-01）：阶段 3 数据层、持久化应用服务和双平台资源安装已完成。
生产 10,000 题数据库以 SHA-256 校验后原子安装并只读查询；`user.sqlite` v1→v2
migration、逐动作保存、完整 move 恢复、设置/统计/钱包/流水/权益缓存、内容版本隔离和
保留原库的故障路径已经落地。填数、提示应用和完成奖励的 SQLite 故障注入及幂等重试
均通过，Android 四 ABI Debug 与 iOS arm64/x86_64 Simulator Debug 构建通过；详见
`docs/phase-3-sqlite-recovery-acceptance.md`。

### 阶段4：离线可玩纵向切片

交付内容：

- 首页、Level 1–5 选题、继续游戏和单局替换确认。
- 受控棋盘组件、数字键盘以及固定工具栏：撤销、擦除、快速铅笔、铅笔、智能提示。
- 两份草稿、快速铅笔生成与恢复、错误标红、暂停和自动保存。
- 完成、失败、重新挑战、新局和下一题流程。
- 临时完成页和最小统计记录；广告、购买使用可替换的测试适配器。

完成门槛：在 iOS、Android 真机上断网后，可以从选题开始完整游玩、退出恢复并完成结算。这一版本作为首个内部试玩版本。

当前状态（2026-09-01）：阶段 4 代码、自动化和模拟器验收已完成。首页、Level 1–5、
继续/替换确认、受控棋盘、数字键盘、固定工具栏、两份草稿、暂停/后台自动保存、智能提示、
完成/失败/重试/下一题、临时统计和可替换测试适配器均已接通。53 个 Jest 测试、Android
四 ABI、iOS 双 Simulator 架构和两端 production bundle 通过；iOS 26.5 模拟器已用生产
10,000 题库真实启动。当前无连接真机，双真机断网完整游玩仍待补测，详见
`docs/phase-4-offline-slice-acceptance.md`。

### 阶段5：完整智能提示体验

交付内容：

- 提示前冲突、错误、无解和盘面指纹检查。
- `hintCandidates` 初始化、持久化、增量更新、重建及撤销快照。
- 三阶段或多页讲解：观察方向、推理结果、确认应用。
- 区域、格子、前提候选数、待排除候选数和填数结果的无障碍高亮。
- 技巧名称、说明参数、本地化模板和提示应用动画。
- 候选数排除或填数作为一个最简单原子步骤，整体应用和整体撤销。

完成门槛：正式支持集合中的每种技巧都有正例、反例和结果测试；全部候选发行题及抽样中间盘面可持续获得合法提示；相同状态稳定返回同一步；提示不能排除正确答案。

### 阶段6：产品完整化

交付内容：

- 完成页、统计页、设置页、玩法帮助和数独技巧页。
- 英语、日语、德语和简体中文完整翻译与术语审核。
- 浅色、深色和跟随系统主题。
- 音效、震动、常亮、输入模式、高亮、自动检查等已定义设置。
- VoiceOver、TalkBack、动态字体、减少动态效果和非颜色状态表达。

完成门槛：四种语言无缺失键或截断；屏幕阅读器能够完成开始、填数、提示、暂停和完成等主要流程。

### 阶段7：广告、额度与 Premium

交付内容：

- 首页开始/继续广告机会、10分钟冷却和首次安装第一局豁免。
- 智能提示、快速铅笔激励广告与幂等奖励事件。
- 初始额度、完成奖励、连续首次完成奖励、上限和本地流水。
- iOS/Android 一次性 Premium、恢复购买和本地权益缓存。
- 隐私同意、ATT 条件判断，以及广告或商店不可用时的降级行为。

完成门槛：棋盘显示后不出现自动广告；广告失败不阻塞游戏；重复回调不重复发奖；Premium 用户不请求游戏广告；购买恢复通过商店测试环境验证。

### 阶段8：正式题库与发行准备

交付内容：

- 在评级和提示技巧集合冻结后生成、验收并人工抽检正式题库。
- 验证 `10,000–30,000` 道题对安装包体积、数据库查询和首次启动的影响。
- 低端 Android、不同尺寸 iPhone、系统升级和数据库升级回归。
- 崩溃、性能、内存、冷启动、电量和长时间游戏测试。
- TestFlight、Google Play 内部测试、隐私材料、第三方许可证和商店资源。
- 根据 Beta 数据校准广告冷却、初始额度、完成奖励和激励广告奖励。

完成门槛：全部题库自动验收通过；两个商店的发布候选包完成回归；没有阻断游戏、数据恢复、购买或隐私合规的已知问题。

## 4. 测试策略

测试按以下层次建设：

1. 领域单元测试：游戏规则、候选数、撤销、计时、奖励和统计口径。
2. 提示引擎测试：每种技巧的正例、反例、依据、结果和确定性。
3. 数据集回放：全部题目、随机合法中间盘面及 HoDoKu2 对照验证。
4. 数据集成测试：SQLite migration、事务、崩溃恢复和题库升级。
5. 组件测试：棋盘状态、工具栏、提示抽屉、本地化和无障碍属性。
6. 真机端到端测试：开始、继续、放弃、失败、完成、广告、购买和离线恢复。

缺陷优先级固定为：错误答案或错误提示、进度或购买数据丢失、无法继续游戏、无障碍阻断、普通界面问题。

## 5. 里程碑和发布门槛

- **技术可行性门槛**：阶段1完成，证明运行时提示方案可用。
- **离线 Alpha**：阶段4完成，核心游戏闭环可长期试玩。
- **功能 Alpha**：阶段5完成，智能提示与全部游戏状态贯通。
- **产品 Beta**：阶段7完成，四语言、统计、设置和商业化完整。
- **Release Candidate**：阶段8完成，正式题库和双平台发行检查通过。

不得为了进入下一个里程碑而临时允许猜测提示、取消崩溃恢复、把广告插入游戏中间，或绕过额度和购买事务。

## 6. 工期建议

工期取决于运行时提示引擎需要补充的技巧数量。以一名全职开发者计算，首期建议预留约 `18–24` 周；如果需要自行补充较多 Level 4–5 技巧，再增加约 `4–8` 周。两名开发者分别负责“React Native 产品层”和“提示引擎及数据层”，在依赖清晰的情况下可按约 `12–16` 周规划。

以上估算不包含应用商店审核等待时间。进度跟踪应以阶段验收结果为主，而不是只使用页面数量或代码完成比例。

## 7. 当前暂缓事项

以下内容不进入首期关键路径：账号、云同步、排行榜、对战、活动、每日挑战、通知、订阅、在线题库更新和复杂成就。正式题量与 Level 1–5 分布、广告和额度的最终数值在 Beta 与上线前校准，不影响核心架构开发。
