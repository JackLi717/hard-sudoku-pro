# Platon Sudoku ASO 长期策略

更新日期：2026-10-13

Platon Sudoku 依靠 Google Play 自然发现与真实推荐积累长期玩家。商店首先传达舒服的经典数独体验，再展示提示、候选工具和复盘。ASO 的成效同时看发现、安装转化与持续游玩，不以关键词排名或下载量单独判断成功。

当前阶段为首次公开发行前。先完成本文的首发准备；公开后的前两周和后续实验只列执行规则，实际执行日期以公开可下载且首发商店资料生效之日为起点。当前执行状态、下次动作和效果记录统一维护在 [ASO 执行与效果追踪](aso-tracker.md)。

## 产品定位与承诺

大众定位：可以长期免费、舒服地玩的经典数独，没有强制广告打断。核心游戏离线、无需账号，五档难度覆盖 Easy 到 Extreme。进阶价值是讲清理由的提示、可编辑自动候选和真实操作复盘；玩家不必理解高级技巧才能选择产品。

表达顺序固定为：经典数独与舒服体验 → 离线和无强制打断 → 候选与提示 → 复盘。保留 Platon 品牌，不因一次实验随意换品牌。首发保持现有图标，图标变体留待公开后有适当样本时单独验证。

| 可以表达                                                      | 限定条件                                                                     |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 10,000+ offline classic Sudoku puzzles                        | 以当前发行题库为依据，不写无限题库或手工精选                                 |
| No forced ads when starting, playing or finishing a puzzle    | 免费版仍有玩家主动选择的激励广告；不能写 No ads 或 Ad-free                   |
| Core play, hints and replay work offline; no account required | 广告、购买、恢复和部分隐私流程可能联网；不能写完全不联网、无追踪或不收集数据 |
| Free, unlimited auto notes                                    | 对应当前免费快速候选，保留可编辑和重新生成确认边界                           |
| Step-by-step hints explain the logic                          | 免费提示有额度；不写所有人无限提示或自动连续解题                             |
| Replay recorded moves and explore possible explanations       | 不声称识别玩家真实思路，不保证解释每一步                                     |
| Optional one-time Lifetime Premium                            | 无订阅，永久无限提示与无广告；不写所有内容永久免费                           |

奖励与购买唯一依据为 [商业方案](../premium-reward-design.md)，功能证据见 [宣传事实台账](claims-register.md)。闭测的 999 次提示额度不写进面向公众的常规商店承诺。ASO 不改变产品权益、奖励、题库、应用界面或发行范围。

## 分类与标签

保留 Game → Puzzle。首发设置 Logic puzzle、Puzzle、Brain teaser、Casual 四个标签。最多五个不代表必须选五个；Brain training 暂不添加，不额外承诺提升智力或认知健康效果。Education、Mathematics、Strategy 与主玩法的关联不足，不用于扩展流量。

2026-10-13 实际后台的手动名单中没有 Sudoku、Offline、Single player。这些可能出现在公开商店的展示属性中，不能据此当作可手工设置项。操作路径为 Grow users → Store presence → Store settings → App category → Manage tags。

标签用于准确描述内容，不纳入每周轮换实验。主要功能改变时再评估相关性。[Google 分类与标签说明](https://support.google.com/googleplay/android-developer/answer/9859673?hl=en)

原有平板、TV、PC 和桌面素材与设备政策保留。新增语言的前三张手机图使用对应语言；未本地化的其他设备图按实际回退行为记录，不宣称全设备四语素材完成。只宣传已经验收的设备能力，模拟器截图不等于 Windows、Chromebook 或 TV 的商店设备验收。[设备扩展计划](../device-expansion-plan.md)

## 指标与统计边界

使用现有 Play Console、Firebase Analytics 和 Crashlytics，不新增后台、收费 ASO 服务、用户级归因或数据仓库。指标统一遵循 [分析标准](../product-analytics-launch-standard.md) 与 [分析操作文档](product-analytics-runbook.md)。

| 层次       | 每周记录                                                  | 判断用途             |
| ---------- | --------------------------------------------------------- | -------------------- |
| 发现       | 可用曝光、详情访问、Search、Explore、外部来源、可见搜索词 | 是否获得相关访问     |
| 转化       | 同一报表口径的转化分子、分母和比率                        | 页面能否说服安装     |
| 激活       | 正常可观测新用户、首日开局、首日有效游玩、首七日完成      | 页面承诺能否接住     |
| 留存       | 成熟用户组 D7、D30 打开与游戏留存，每周有效游玩人数       | 是否有持续使用价值   |
| 信任与质量 | 评分、评价量与问题主题、卸载趋势、崩溃、ANR               | 影响认可与推荐的问题 |

有效游玩沿用现有定义：同一天同一局前台未暂停游玩累计至少 60 秒，且有玩家填写或笔记操作。每周有效游玩按安装实例去重，不将事件数当用户数。

Play 与 GA4 的日期、用户单位和归因不同：Play 保留报表原始时间口径，GA4 为 UTC，运营记录日期用 Melbourne。不跨平台直接相除推算精确流失；不把安装当 first_open，不把 Play D28 当 GA4 D30。严格 D7/D30 必须使用同一成熟新增用户组及明确分子、分母，未成熟显示待成熟，零分母或不可见显示不适用。

当前 Play 来源定义中，部分品类搜索与自动补全归入 Explore，Search 更偏向品牌及紧密关联搜索；不能把 Search 当全部关键词流量。外部推荐单列，不能把所有非付费安装都称为商店自然发现。小流量搜索词可能进入 Other。采用报表实际列名；若界面显示 install clicks 或 click-through rate，不擅自改名为已完成安装。[Google 获客报表](https://support.google.com/googleplay/android-developer/answer/9859173?hl=en)

目前不能可靠把某个商店素材或关键词对应到 Firebase 用户的严格留存。商店实验结果和同期整体／国家／语言的激活留存分别报告，后者作为质量观察，不能声称某一素材造成留存变化。闭测、开发调试、测试激励、许可购买和异常观测起点排除或单列。

## 公开后执行节奏

公开可下载与基线商店资料均生效后，记录实际起点与各语言生效时间。现有 Closed testing — Alpha 继续运行，不暂停、不替换，不更换包名、签名、名单或加入链接。

| 阶段           | 工作                                                       | 完成条件                                 |
| -------------- | ---------------------------------------------------------- | ---------------------------------------- |
| 公开前         | 四语文案、四标签、前三张游戏截图、事实与字符检查、后台核对 | 本地素材与后台状态明确，审核等待单列     |
| 首个完整 14 日 | 记录公开来源基线，检查首局和评价，修复事实错误与阻断问题   | 两个完整周的同口径观察，未成熟留存不补造 |
| 随后           | 根据主要瓶颈选择一项实验或观察性调整                       | 有假设、主指标、保护指标和足够样本说明   |
| 每月           | 复评国家、语言、评价主题和质量，决定下一项投入             | 给出保留、调整、继续观察或停止的决定     |

首两周默认不频繁改名称、关键词和素材，必要纠错仍应及时做并注明时间。公开前闭测数据可用于语言和理解测试，不能充当公开 ASO 基线。公开后具体工作在届时复核后执行，本轮不预先启动 A/B、自定义页面或自动监控。

## 实验与调整规则

先诊断瓶颈：访问少而转化尚可，研究发现与本地化；访问多而转化低，研究标题、图标和首图；安装增加但有效游玩下降，检查受众和首局；留存下降，结合真实体验与评价处理产品原因。

每次只检验一个主要假设。流量足够时优先用 Play Console 商店实验比较一个主要变量，例如首图的安静体验表达与逻辑提示表达。实验至少覆盖完整一周，但一周不等于样本足够；采用 Console 对预计样本、置信区间和 More data needed 的实际判断。样本不足 100 的细分沿用分析标准，只做描述，不自动触发百分比波动预警；100 也不是显著性门槛。[Google 实验建议](https://play.google.com/intl/eng_ALL/console/about/store-listing-experiments/)

标题、关键词和不能随机分配的调整记为前后观察，同时记录国家、来源、版本与节日变化，不声称因果。低流量先做目标玩家的短时理解测试，验证是否看懂玩法、广告和免费边界；理解测试不证明安装提升。

有足够访问后再考虑按离线／安静和学习／提示两个意图建立自定义页面。关键词定向是相关页面展示工具，不保证排名或新增流量；自定义页面需单独维护翻译。[Google 自定义页面](https://support.google.com/googleplay/android-developer/answer/9867158?hl=en)

每轮结论必须为采用、保留当前、继续观察、结果不确定或停止之一。不能只因某天数字上升就宣布胜出；转化改善也需查看同期游玩质量是否恶化。清晰的虚假承诺、存档、购买履约和严重故障优先纠正，不等实验结束。

## 评价与自然推荐

评价围绕广告预期、输入、难度、提示可理解性和存档可靠性归纳。用户获得充分体验后才考虑低频原生评价请求，不在首次启动索评，不先筛选满意用户，不用提示、Premium 或其他奖励交换评价。回复解决具体问题，不索取更高星级。本轮只记录长期规则，不新增应用内索评功能。[原生评价指南](https://developer.android.com/guide/playcore/in-app-review)、[评价政策](https://support.google.com/googleplay/android-developer/answer/9898684?hl=en)

自然推荐使用普通下载链接与一致承诺，不建设邀请奖励或归因后台，不把高频社交运营作为增长前提。Google 将应用与宣传素材质量纳入发现和推荐考虑，技术质量与体验问题应与 ASO 一起观察，但不保证推荐位或增长幅度。[Google 推荐说明](https://play.google.com/intl/en-GB/console/about/guides/featuring/)

## 维护方式

每周一次更新追踪文档，按相同时间窗记录数据与分母，选择至多一个下一步；每月一次复评定位与语言投入。只有策略或产品边界变化才修改本文。文案和素材更新当前基线，长期只保留简洁的决定记录与必要报表引用，不建立每次实验的历史素材档案。

本策略不会自动执行定时任务。用户以后明确要求持续监控时，再设置合适的自动化；在此之前通过追踪文档手动执行。
